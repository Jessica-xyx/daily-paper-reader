## 摘要
LLM 智能体越来越多地通过持久性共享记忆进行协调：一个智能体的写入成为另一个智能体的前提，并最终转化为具有真实副作用的工具调用。当前的智能体记忆系统将每个被接受的写入视为立即可操作的真相，因此一个受污染的工具结果、过时的更新或队友未完成的笔记都可能悄然引发不可逆的操作。我们认为记忆写入并非信念提交。我们提出 MemTX，一种事务性信念提交协议。每条记录都带有证据、权限、来源和有效性。写入被暂存在快照隔离的事务中，并通过验证并提交管线接纳，不可逆的工具调用受制于进行中的信念状态，而撤回一个信念会触发对其衍生记录和工具副作用的类型化级联修复。两个不变量——动作安全门控和级联修复完整性——通过基于属性的测试和 550 万个协议状态的有界穷举枚举进行了机器验证，零违规。在来自三个模型族的五个骨干网络上，MemTX 在所有八个基线中领先，其中四个骨干网络具有成对 McNemar 显著性，在第五个最强骨干网络上与最佳基线统计上持平，同时是唯一在所有骨干网络上实现零下游危害的方法。骨干网络能力并不能替代提交纪律。

## Abstract
LLM agents increasingly coordinate through persistent shared memory: one agent's write becomes another agent's premise, and eventually a tool call with real side effects. Current agent memory systems treat every accepted write as immediately actionable truth, so a polluted tool result, a stale update, or a teammate's half-finished note can silently drive an irreversible action. We argue that a memory write is not a belief commit. We present MemTX, a transactional belief-commit protocol. Each record carries evidence, permissions, provenance, and validity. Writes are staged inside snapshot-isolated transactions and admitted by a validate-and-commit pipeline, irreversible tool calls are gated on in-flight belief state, and retracting a belief triggers typed cascading repair of its derived records and tool side effects. Two invariants, action-safety gating and cascade-repair completeness, are machine-checked by property-based testing and bounded exhaustive enumeration of 5.5 million protocol states, with zero violations. Across five backbones from three model families, MemTX leads all eight baselines with paired-McNemar significance on four backbones and statistically ties the best baseline on the fifth and strongest, while remaining the only method with zero downstream harm on every backbone. Backbone capability does not substitute for commit discipline.

# MemTX: 事务性信念提交协议——论文详细总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体通过持久化共享记忆协调行动，一个智能体的写入会被其他智能体读取并用于执行具有真实副作用的工具调用（如退款、发送邮件等）。现有记忆系统（如 MemGPT、Generative Agents）将每次接受的写入当作立即可信的“真理”写入记忆存储，忽略了写入与“信念提交”之间的区别。
- **核心问题**：这种“写入即真相”的设计导致一系列状态损坏故障：
  - 受污染的工具结果被总结为 profile，即便来源已修正，仍被用于错误退款；
  - 过时写入覆盖纠正结果；
  - 私密记录被转述到共享范围越权；
  - 未经验证的临时数据被用于不可逆行动。
- **根本缺陷**：现有系统只关注写入时的正确性，不跟踪信念是否成熟到可被行动，也不修复撤回的信念所污染的数据。数据库领域几十年前就已建立“写入不等于提交”的原则，而智能体记忆系统尚未采纳。

## 2. 方法论：MemTX 协议

### 2.1 核心思想

- 将记忆记录视为**受管制的对象**，带有：
  - **证据**：来源（authority weight）、写入者置信度；
  - **权限**：所有者、读写角色、共享范围（private/shared/public）；
  - **来源**：派生图中的边（derived-from edges）；
  - **有效性**：时间区间（validity interval）与逻辑时钟；
  - **类型**：区分 belief、summary、profile、index entry、shared copy、tool action。
- 引入**信念生命周期**：从 raw → tentative → validated → committed → action-safe，以及分支状态 quarantined、superseded、revoked。
- 事务性写入：写入被暂存在**快照隔离**的事务中，通过验证-提交管线进行四步检查后升级状态。
- **行动门控**：不可逆工具调用只能在对信念状态进行门控后执行：当前不能有未提交的 tentative 记录，且对于外部行动事务，快照中必须至少有一条 action-safe 记录。
- **类型化级联修复**：撤回信念时，沿派生 DAG 递归处理后代记录：
  - belief → revoked；
  - derived view → quarantined（待重建）；
  - tool action → 可逆则补偿，否则记为泄露。

### 2.2 关键技术细节

- **隔离级别**：五级（raw-read → action-safe-read），事务风险等级（low/medium/high/external-action）决定隔离级别。
- **验证管线**（四步）：(1) 证据检查（置信度≥0.6 或来源权威≥0.9）；(2) 有效性检查（时间区间含当前逻辑时间）；(3) 语义冲突检查（时间戳优先于权威，权威相同时不同来源暂留待人工）；(4) 依赖稳定性检查（祖先无待决撤销）。失败则 quarantined。
- **行动门控**：不可逆工具调用前检查 (1) 事务外无 tentative 记录在途；(2) external-action 事务快照中至少一条 action-safe 记录。
- **级联修复**：从撤回点出发，遍历所有后代，按类型执行对应修复动作，并记录审计日志。
- **形式化验证**：两个不变性 I1（行动安全门控）和 I2（级联修复完整性）通过基于属性的随机测试（10000 条随机轨迹）和 550 万规范协议状态的有限穷举枚举（4 记录、3 并发事务、深度 10）验证，零违反。第三个推论 G3（不存在 committed/action-safe 记录其祖先被 revoked）也在验证中暴露过一次缺陷并修复。

### 2.3 智能体集成

- 暴露为五个内存工具：读（快照下检索）、暂存、提交、中止、撤回。
- 域工具路由经行动门控，可逆/不可逆由静态配置决定。

## 8. 不足与局限

1. **套件覆盖有限**：自建案例虽有广泛领域，但数量偏少（主套件 90，强化 56），未来需要更大规模、更复杂的真实世界场景。
2. **转录与重试盲点**：强化套件揭示两个协议外失败模式：智能体转录私有内容时不声明父子关系，导致权限检查失效；事务重试时过时写入因时间窗口变化而通过仲裁。这些问题暴露了协议保护范围仅限单一提交/事务，无法处理跨事务的常规行为。
3. **级联修复范围受限**：仅覆盖记录在 DAG 中的衍生关系；未记录的派生不会被修理；补偿是记录级别的义务而非环境级别的回滚；工具可逆性是静态的（如已结算的退款无法补偿）。
4. **强门控需存储预热**：外部行动事务要求快照中有至少一条 action-safe 记录，冷存储初始阶段将导致额外阻塞（成本由可用性体现）。实际部署需成熟存储。
5. **骨干依赖性**：弱骨干（Qwen2.5-14B）在强化套件上表现差（0.518），大部分失败来自召回协议，表明协议依赖智能体正确使用工具。
6. **低层协议不可见**：风险等级声明被视为可信配置而非由智能体生成，避免降级攻击，但若 runner 级配置被篡改可能被绕过。
7. **未探索扩展性**：论文没有测试更多智能体并行或超长链时效性，性能可能退化。
8. **无用户实验**：没有真实人类用户交互评估，仅模拟回合制。
