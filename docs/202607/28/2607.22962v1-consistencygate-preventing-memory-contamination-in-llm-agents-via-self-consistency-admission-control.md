## 摘要
在多轮交互中运行的LLM智能体将事实累积存储在外部记忆库中，并将它们作为下游推理的前提。因此，在某个步骤中产生的幻觉事实会作为错误前提持续影响后续每一步骤，这种故障模式我们称之为记忆污染。现有的记忆管理方法关注检索和容量，但未处理写入时的正确性；这个准入问题无法通过基于效用或新颖性的标准解决，且不受控制的污染会在长轨迹中累积加剧。我们提出ConsistencyGate，一种写入时的准入控制器，在将从上下文c中提取的候选事实m提交之前，查询LLM K次以获得软支持分数，并且仅当平均分超过阈值时才接纳m。该机制与模型无关，无需微调，并且在针对延迟敏感部署的对数概率变体中简化为单次前向传播。为了衡量对自然数据的影响，我们通过在LoCoMo和MSC的长对话中植入受控的单一细节篡改，构建了两个真实对话基准（LoCoMo-Contam和MSC-Contam），并辅以一个结构化合成语料库（MemContam），该语料库隔离了近乎完美的上界。在四个LLM骨干网络上，相对于“写入所有”基线，ConsistencyGate在每个基准上都减少了污染，代价集中在源上下文中仅隐含陈述的事实上。我们发布了所有三个基准以及该准入控制器的实现。

## Abstract
LLM agents that operate over many turns accumulate facts in an external memory store and reuse them as premises for downstream reasoning. A hallucinated fact written at one step therefore persists as a false premise for every subsequent step, a failure mode we call memory contamination. Existing memory management addresses retrieval and capacity but not write-time correctness; this admission problem cannot be solved by utility- or recency-based criteria, and uncontrolled contamination compounds across long trajectories. We propose ConsistencyGate, a write-time admission gate that, before committing a candidate fact m extracted from context c, queries the LLM K times for a soft support score and admits m only when the average exceeds a threshold. The mechanism is model-agnostic, requires no fine-tuning, and reduces to a single forward pass in a log-probability variant for latency-sensitive deployments. To measure the effect on natural data, we construct two real-conversation benchmarks (LoCoMo-Contam and MSC-Contam) by planting controlled single-detail corruptions in long-term conversations from LoCoMo and MSC, and complement them with a structured synthetic corpus (MemContam) that isolates a near-oracle upper bound. Across four LLM backbones, ConsistencyGate reduces contamination on every benchmark relative to a write-everything baseline, with the cost concentrated on facts that are stated only implicitly in the source context. We release all three benchmarks together with the gate implementation.

# 论文中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：LLM 智能体在长时交互中依赖外部记忆存储事实，并作为后续推理的前提。然而，LLM 即使在给定上下文中也可能产生幻觉（hallucination），导致写入记忆的事实是错误的。这种错误一旦写入，会在后续所有检索中被当作正确前提使用，形成“记忆污染”（memory contamination）。
- **问题重要性**：现有记忆管理仅关注检索（如何找到正确记忆）和容量（在满时如何淘汰），但忽视了写入时的正确性。基于效用、新颖性或时效性的准入标准无法区分正确事实和其幻觉变体，因为两者具有几乎相同的效用分数。
- **整体含义**：记忆污染在长轨迹中会复合放大，导致下游任务性能显著下降。因此，需要一种针对事实正确性的写入门控机制，作为现有记忆管理体系不可或缺的补充。

## 2. 方法论

### 核心思想
- **ConsistencyGate**：对于从上下文 c 中提取的候选事实 m，在写入长期记忆前，利用 LLM 进行**自一致性验证**。具体地，多次（K 次）查询 LLM，让其对 m 在 c 中的支持程度给出 0–1 的软评分，计算平均分 p̂，仅当 p̂ 超过阈值 τ 时才将 m 写入记忆。

### 关键技术细节
- **软评分验证**：每次查询时，给定 prompt 要求模型输出 0.0（完全不被支持或矛盾）、0.5（部分支持/模糊）、1.0（完全直接支持）。
- **准入决策**：决策函数为 \( g(m,c) = \mathbf{1}[\hat{p}(m|c) \ge \tau] \)。默认推荐参数：τ = 0.7, K = 5。
- **高效单次变体（LogProb）**：将验证 prompt 改为二分类（yes/no），从一次前向传播中读取“yes”和“no”的 logit，计算 softmax 后取“yes”概率作为支持分数。适用于结构化、明确上下文，速度比 K=5 软评分快 12–14 倍（约 23–28 ms vs. 264–363 ms）。
- **自适应阈值**：当无法针对部署调参时，提供阈值随记忆占用率线性缩放：\[ \tau^* = \tau_{\min} + (\tau_{\max} - \tau_{\min}) \cdot \frac{|M|}{C} \]，记忆空时更宽松，满时更严格。默认 τ_min=0.4, τ_max=0.8。

## 3. 实验设计

### 数据集 / 场景
- **MemContam**（合成）: 5 个固定源上下文（个人传记、图书馆记录等），每个生成 40 个样本，共 200 个样本，每个样本包含 5 个正确事实和 5 个用四种策略（数值扰动、否定、专名替换、矛盾子句）生成的错误事实。总计 1000 正确 + 1000 错误事实，污染率固定 50%。
- **LoCoMo-Contam**（真实长对话）: 基于 LoCoMo-10 的 10 个长对话（400–700 轮），每个对话选最多 5 个可验证事实，生成正确/错误变体并转为自然对话语句。总计 50 个探针对，污染率 50%。
- **MSC-Contam**（人物对话）: 基于 Multi-Session Chat 的 20 个对话，每个人物有 concrete 人物属性句。筛选后得到 41 个探针对，污染率 50%。

### 基准（Baseline）
- **WriteAll**：写入所有提取的事实。
- **Random**：随机以概率 p=0.6 写入，匹配 ConsistencyGate 的实际准入率，以隔离过滤带来的影响（排除记忆大小减少的混淆）。
- **ConsistencyGate**：默认 K=5, τ=0.7。

### 评估指标
- 污染率 ρ（越低越好）、准入精度（1-ρ）、召回（正确事实被接受的比例）、下游 QA F1。

## 6. 主要结论与发现

- **污染显著降低**：在 MemContam 上，ConsistencyGate 将污染率从 50% 降至 1.2%（相对减少 97.6%），召回 100%；在 LoCoMo-Contam 上污染从 50% 降至 34.1%（精度 0.500→0.659）；在 MSC-Contam 上降至 36.7%（精度 0.500→0.633）。
- **推荐配置**：固定 τ=0.7, K=5 在所有模型上表现稳定；调高 τ 至 0.7 能大幅提升精度，继续提高至 0.9 无收益。
- **LogProb 变体局限**：仅在结构化的合成数据上表现优越；在真实对话（LoCoMo-Contam）上不如 K=5 软评分，因为对话上下文评分分布更连续、非二值。
- **污染级联效应**：写入错误随轮次累积，ConsistencyGate 在长轨迹中优势不断扩大（图2）。
- **召回代价**：隐含事实（LoCoMo-Contam）召回仅 0.58，即 42% 的正确事实被误拒；而显式事实（MSC-Contam）召回 0.93，说明门控对明确的、自包含的事实友好。
- **干净对话影响小**：在干净 LoCoMo 上 QA F1 仅下降 1.5%（0.271→0.267），对比 Random 下降 16.2%，说明过滤有针对性。

## 7. 优点

- **方法创新**：首次将写入门控定位为独立于检索和容量的新问题，并提出基于自一致性的解决方案，与现有效用型准入互补。
- **模型无关与无需微调**：直接应用于任何 LLM，无需额外训练，部署成本低。
- **效率变体**：提供 LogProb 单次变体，适合延迟敏感场景。
- **基准构造**：创建了首个带有可控污染的真实对话基准（LoCoMo-Contam 和 MSC-Contam），并公开所有基准和实现，便于社区研究和比较。
- **实验严谨**：使用 Random 基线控制记忆大小影响；在干净数据集上验证；跨多个骨干测试泛化。
- **深层分析**：详细讨论了故障模式（隐含事实、世界知识依赖）和适用场景（结构化上下文、长轨迹优先），给出实用指导。

## 8. 不足与局限

- **增加延迟和成本**：每次写入需 K 次 LLM 调用（默认 K=5 约 340 ms/fact），LogProb 变体虽快但仅适用于结构化数据。
- **召回低**：在隐含事实或分布推理场景中，42% 的正确事实被拒绝（LoCoMo-Contam 召回 0.58），可能导致遗漏重要信息。
- **正确性代理**：一致性检测不等于事实正确性检查，无法防止由于源上下文本身错误或需要外部知识验证的幻觉；可能产生虚假安全感。
- **世界知识依赖**：当候选事实需要超出源上下文的背景知识时，LLM 可能总是“yes”，导致误接受。
- **仅评估单轮写入**：未测试多步推理或记忆整合后的验证效果（如多跳验证）。
- **基准限制**：真实对话基准中 QA F1 因预种子正确事实而不敏感，主要衡量指标仅为污染率/精度，缺少对下游任务整体影响的全景评估。
- **未涉及训练**：方法虽无需微调，但可能通过针对性训练进一步提高召回/精度平衡。
