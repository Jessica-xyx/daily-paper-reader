## 摘要
针对LLM智能体记忆的基准测试通常首先生成对话，然后提取答案键——存在记录在案的标签错误和污染问题——并且它们绝大多数测量的是短交互历史。我们反转了管道：一个种子化的生活脚本采样器在文本存在之前就生成带有有效期、波动类别和源通道的事实；一个LLM渲染器根据每个事件的真实清单编写聊天和电子邮件；一个保真度验证器确认每个植入的事实；问题从脚本中机械地实例化，因此黄金答案通过构造对脚本有效，并单独验证可回答性。合成的虚构语料库（约380个问题，15种类型）嵌入了我们调查的基准测试中缺失的特征：每个事实的有效期、发送/接收信任区分、良性框架中的注入探测以及截至日期的问题集。我们对五种记忆架构与无记忆对照（固定回答者、带版本的LLM评判员、三个重复、两个时间范围）进行基准测试，发现后端排名随历史长度反转：在短期领先的预算型策划记忆地图在九周后失去了对驱逐内容的回忆（从96%降至72%），而一个来源类型图上升到90%；在完全跨家族重新评判下，所有六名用户的反转都是正向的（精确p=0.031）。一个全渲染历史基线在短期与最佳记忆系统持平或超越，但在九周时没有显示出评判员无关的优势，而读取成本大约是两倍。写入阶段质量与下游质量强相关（写得差的事实失败率为24%对比2%），注入抵抗力追踪来源边界是否在表示中存活。在两种情况下，分层架构在记忆系统中表现最佳（短期96.8%），并作为开源库Veracium发布，附带语料库生成器和框架。

## Abstract
Benchmarks for LLM-agent memory typically generate conversations first and extract answer keys afterwards -- with documented label-error and contamination problems -- and they overwhelmingly measure short interaction histories. We invert the pipeline: a seeded life-script sampler emits facts with validity intervals, volatility classes, and source channels before any text exists; an LLM renderer writes chat and email from per-event fact manifests; a fidelity verifier confirms every planted fact; and questions are instantiated mechanically from the script, so gold answers are script-valid by construction and separately validated for answerability. The synthetic, fictionalized corpus (~380 questions, 15 types) embeds features absent from the benchmarks we survey: per-fact validity intervals, sent/received trust distinctions, injection probes in a benign harness, and as-of-date question sets. Benchmarking five memory architectures against a no-memory control (fixed answerer, versioned LLM judge, three replicates, two horizons), we find backend rankings invert with history length: the budgeted curated-map memory that leads at three weeks loses recall of evicted content by nine weeks (96% to 72%) while a provenance-typed graph rises to 90%; the inversion is positive for all six users under complete cross-family re-judging (exact p=0.031). A full-rendered-history baseline ties or exceeds the best memory system at the short horizon but shows no judge-independent advantage at nine weeks, at about twice the read cost. Write-stage quality strongly correlates with downstream quality (weakly-written facts fail 24% vs 2%), and injection resistance tracked whether provenance boundaries survive representation. A layered architecture performs best among the memory systems in both regimes (96.8% short-horizon) and is released as Veracium, an open-source library, with the corpus generator and harness.

- **核心问题**：现有的LLM智能体记忆基准测试存在两个严重缺陷：

  - **评估短历史主导**：绝大多数基准仅测量短交互历史（通常几轮到几十轮对话），而长期运行（数周至数月）的智能体需要记忆大量跨会话信息。短历史下，完整上下文回答仍具竞争力，无法有效区分不同记忆架构的真实差异。
- **研究动机**：设计一种“地面真相优先”的评估方法，预先确定事实（带有效期、波动性、源通道等属性），再生成文本和问题，从而从根本上消除标签错误和污染，并支持长期、多通道、对抗性的记忆评测。
- **整体含义**：通过构造全合成、虚构化语料库，发现记忆架构的排名会随历史长度发生**反转**（“任期交叉”现象）——短历史基准可能错误排序长期智能体所需的系统；同时揭示写入质量对下游准确性的强关联、注入抵抗性与来源边界表示之间的依赖关系，以及准确性与校准性回避之间的不匹配。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程（用文字说明即可）

- **核心思想**：**地面真相先行（Ground Truth First）**。在生成任何文本之前，先通过确定性脚本采样器定义事实的时间线，再基于这些事实渲染对话/邮件，最后机械生成问题，确保黄金答案来自脚本本身。
- **关键技术细节**（整体流程）：
  1. **生活脚本采样器**（Life-Script Sampler）：一个配置种子的确定性流程，为每个虚构用户生成时间线，每条事件包含多个事实。每个事实携带：
     - **有效区间**（Validity Interval）：该事实成立的时间段（例如某年某月内成立）
     - **波动类别**（Volatility Class）：永久、持久、慢变、瞬态、短暂
     - **源通道**（Source Channel）：该事实是在聊天中陈述，还是通过电子邮件发送或接收（接收的邮件被视为第三方内容，属于更低信任的证据类别，同时是注入攻击面）
  2. **LLM渲染器**（Renderer）：使用Amazon Nova Pro模型，根据每个事件的“事实清单”将脚本事件渲染为聊天会话或电子邮件。确保每个植入事实在生成的文本中出现。
  3. **保真度验证器**（Fidelity Verifier）：检查每个植入事实是否真的出现在渲染文本中；若缺失则重新生成，多次尝试后仍缺失则发出警告。
  4. **问题机械实例化**：从脚本（而非渲染文本）中机械地生成问题。黄金答案自动成为脚本中对应事实的正确值（按构造即正确）。随后单独审计该答案是否在渲染语料中可被回答（可回答性审计）。
  5. **可回答性审计**：类似MemGym协议，将完整渲染语料开放给一个“预言机”，要求其回答每个生成问题；若失败则排除该问题。最终通过了97.7%的问题（215/220）。
- **语料特征**：全合成、虚构用户，无真实个人数据；包含15种问题类型（单事实、推理、临时、知识更新、偏好、冲突解决、工作记忆、回避、注入探测等）；长期语料提供“截至日期”（as-of-date）的问题集，支持纵向 tenure 曲线。
- **评判**：固定评判模型（claude-sonnet-5，版本化评分准则），视为基准的一部分；生成器与评判器分属不同模型家族；所有比较均为差分性（如排名反转）而非绝对分数。

## 6. 论文的主要结论与发现

1. **排名随历史长度反转（任期交叉）**：
   - 短期（3周）：策划地图领先（81.2%）> 图（75.9%）；长期（9周）：图（90.4%）显著超越策划地图（78.4%），混合v2（93.2%）最优。
   - 所有6个用户在第9周均显示图 ≥ 策划地图；交互效应在跨家族评判下对所有用户为正（精确p=0.031）。
   - 机制：预算驱逐淘汰最旧内容（策划地图早期章节召回从96.3%降至72.2%），而无界图保持100%召回。
   - 短期基准会错误排序长期智能体所需架构。

2. **全渲染历史在短期具竞争力，但长期无评判员无关优势**：
   - 短期：全历史97.9% vs 混合v2 96.8%（无统计显著差异），说明短历史下“读完所有内容”已接近最优。
   - 长期：混合v2在主要评判下领先全历史（93.2% vs 88.9%），但在跨家族评判下反列（全历史79.7% vs 混合v2 72.4%），表明无评判员无关胜者；同时混合v2的读令牌成本约是全历史的一半且增长更慢。

3. **写入阶段质量与下游质量强关联**：
   - 两步策划写入器的事实践召回84.5% vs 单步提取器74.6%；错误数量减半（4.0 vs 8.5）。
   - 写入弱的事实导致下游失败率24.2%，而写入佳的事实仅1.6%（比值比19.6，置换检验p<10⁻⁴）；79%的QA失误对应弱写入事实。
   - 写入路径消耗约4.6×的令牌但换来错误减半（写成本摊销到每次读）。

4. **注入抵抗力追踪来源边界是否在表示中存活**：
   - 来源类型化图在14个独特注入探测的42次试次中产生零不可支持断言；全原始文本（保留源框架）同样完全抵抗。
   - 扁平化的断言存储（策划地图、混合v2的维基部分）在2/14探测上被攻破。
   - “操作边界”是来源边界的表示存活（无论是结构化边还是原始文本），而非图拓扑本身。

5. **准确性与校准性回避不匹配**：
   - 混合v2（准确性冠军）在被判定错误时，93.9%为“自信断言错误细节”，仅有8/972次回避；向量较不准确但错误中62.7%为回避。
   - 最佳系统在错误时不回避，这是用户无法检测的静默失败模式。

6. **其他发现**：
   - 超期使用“替换勿删除”策略：内联历史优于显式双时态版本边（知识更新问题79/81 vs 72/81）。
   - 片段必须由构造存在：未经LLM提示，片段不会自动产生带日期的条目。
   - 波动性分类有效但存在结构性错误（永久性事实被错误放入功能槽后可能被覆盖）。

## 7. 优点：方法或实验设计上的亮点

- **方法创新**：“地面真相先行”彻底消除了标签错误和污染问题，使黄金答案通过构造正确，并支持细粒度的事实属性（有效期、波动性、来源信任度、注入探测）。
- **实验设计严谨**：
  - 固定回答模型、固定评判器（版本化）、三重复随机化，差分性比较。
  - 包含多个有意义的基线（无记忆、全历史、令牌匹配窗口），合理控制变量。
  - 主要结论经跨家族评判器完全重评判验证，增加鲁棒性。
  - 使用用户层面聚类分析、精确随机化检验，避免假阳性。
- **全面评估维度**：覆盖准确性、写入质量、注入抵抗、幻觉/回避、成本（读令牌）等多个维度，提供综合视角。
- **开源发布**：开源Veracium库（pip install veracium）和语料库生成器、评估框架，促进可复现性和扩展。
- **伦理友好**：完全合成虚构数据，无个人隐私风险；第三方文本默认不可信，符合安全设计原则。

## 8. 不足与局限：包括实验覆盖、偏差风险、应用限制等

- **合成语料的外部效度**：用户比真实用户更规整，渲染器的“杂乱”旋钮未调到最大，结果应视为受控条件下的架构比较；真实用户研究是未来工作。
- **单一回答者**：所有比较基于单一回答模型（Claude Haiku），未在不同LLM上验证；结论的可推广性受限。
- **长期Tenure用户数少**：仅6个用户，集群规模小导致部分统计检验分辨率不足（如符号翻转p=0.063）；虽跨家族评判改善，但仍需更多用户。
- **评判器偏差**：评判器与回答者属于同一模型家族（Anthropic），可能与答案风格交互；跨家族评判显示绝对分数系统偏低（12 pp），且某些微观比较失去显著性；计划中的人工评判尚未完成。
- **开发集信息污染**：混合v2的设计在观察短期结果后进行，短期96.8%为开发集数字；长期结果因用户生成在架构固定后而带有一定保持性，但并非完全盲测。
- **注入攻击范围有限**：仅测试非自适应、模板级注入，未涵盖洗钱通道（如TMA-NM中通过摘要或工具回显）和其他复杂策略；零失败只能将每个探测断言率上界限制在19%左右（95%置信）。
- **写入审计的评判器与QA评判器相同**：相关测量误差可能夸大关联幅度，需人工或跨家族验证。
- **类别级比较描述性**：某些分类（如短期某些类别仅差1-2个答案）仅描述性，未进行统计检验。
- **未进行因果隔离**：写入质量与下游质量关联确实存在，但未通过交叉消融（如相同写入器不同存储表示）分离写入路径与表示路径的因果贡献。
- **日志使用提供者默认解码参数**，未被归档，造成复现困难（作者已指出）。
- **实际应用限制**：Veraicium库的健壮性测试为非盲、非产品级；结果不应直接解释为生产级安全性。
