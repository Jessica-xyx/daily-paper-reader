## 摘要
近年来，内存管理已成为基于大语言模型（LLM）的智能体的关键基础设施，因为它直接影响长程推理、个性化响应和知识复用。然而，现有的LLM内存系统通常采用粗粒度（价值无关）的方式，统一处理异构的用户-LLM交互记录，导致内存库中持续存在冗余且低影响力的记录。为应对这一挑战，我们提出MemLens，一种将内存记录视为一等数据对象的价值感知内存管理系统。MemLens提供了一个端到端的交互式分析仪表盘，展示了完整的内存生命周期，包括Shapley风格的内存评估、价值感知存储以及内存辅助响应。通过一个研究助手应用，该系统使用户能够检查内存价值、可视化分层内存结构，并在响应质量、检索延迟和令牌消耗方面比较各种内存管理策略。因此，我们的MemLens可以作为一种高效、可解释且个性化的长期内存管理系统用于基于LLM的智能体。

## Abstract
Recently, memory management has become a key infrastructure for LLM-based agents, as it directly affects long-horizon reasoning, personalized responses, and knowledge reuse. However, existing LLM memory systems typically adopt a coarse-grained (utility-agnostic) manner that treats heterogeneous user-LLM interaction records uniformly, leading to redundant and low-impact records persisting in the memory repository. To address this challenge, we present MemLens, a value-aware memory management system that takes memory records as first-class data objects. MemLens provides an end-to-end interactive analytics dashboard that exposes the complete memory lifecycle, including Shapley-style memory evaluation, value-aware storage, and memory-assisted response. Through a study-copilot application, the system enables users to inspect memory values, visualize hierarchical memory structures, and compare various memory management strategies in terms of response quality, retrieval latency, and token consumption. Therefore, our MemLens can serve as an efficient, interpretable, and personalized long-term memory management system for LLM-based agents.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有面向 LLM 智能体的内存管理系统通常采用粗粒度、价值无关（utility-agnostic）或启发式（heuristic）的方式，将所有用户-LLM 交互记录统一处理，而不区分其未来效用。这导致大量冗余和低影响的记录持续累积，不仅稀释了任务相关上下文、增大了检索空间，还消耗了不必要的 token 开销，严重制约了长程推理、个性化响应和知识复用能力。
- **核心挑战**：内存单元的未来有用性不是均匀或静态的 —— 同一内存单元对不同查询的贡献不同，且其贡献还依赖于其他已存在的内存单元。因此，需要一种既能原则性地估计异构内存单元的下游效用，又能保证估计效率足够以支撑实际存储和检索决策的方法。
- **整体含义**：MemLens 提出将内存记录视为一等数据对象（first-class data objects），通过显式建模其“价值”（即对下游响应质量的贡献），实现选择性的高价值保留、层次化组织和个性化响应，从而提升 LLM 智能体长期内存管理的效率、可解释性和适应性。

## 2. 方法论
### 2.1 核心思想
- 基于 **Shapley 值** 的框架来定义并量化每个内存单元对下游推理任务的边际贡献，称为 **Memory Shapley Value (MS-value)**。
- 将完整内存生命周期分为三个相互衔接的模块：**内存评估**（分解与估值）→ **价值感知存储**（阈值筛选与组织）→ **内存辅助响应**（检索与注入）。

### 2.2 关键技术细节
#### （a）内存数据评估
- **内存单元构建**：将原始对话记录分割为句子级原子单元，再通过 LLM 聚合为多层摘要，形成层次化内存树，保留从摘要到原子单元的血缘链接，避免信息丢失。
- **内存价值估计**：
  1. 使用轻量级代理模型 \(M_p\)（默认 Qwen2.5-7B）和 **LLM-as-Judge** 评分函数定义效用：  
     \[
     V_q(S) = \text{Score}(M_p(q \oplus S)) - \text{Score}(M_p(q))
     \]
     其中 \(S\) 为内存子集，\(\oplus\) 表示 Prompt 注入。
  2. 定义 Memory Shapley Value：  
     \[
     \phi(m_i) = \sum_{S \subseteq M \setminus \{m_i\}} \frac{|S|!(M - |S| - 1)!}{M!} \left[ V_q(S \cup \{m_i\}) - V_q(S) \right]
     \]
     满足公平性性质（零玩家、对称性、线性可加性）。
  3. 为支持交互式响应，采用 **分层采样近似**（stratified sampling），将评估时间复杂度降至 \(O(\rho M)\)，其中采样预算 \(\rho\) 通常设为 20~100。

#### （b）价值感知存储
- **阈值筛选**：根据 MS-value 设阈值 \(\tau\)，保留 \(M^* = \{m_i \mid \phi(m_i) \ge \tau\}\)，用户可交互调整 \(\tau\) 观察压缩率与期望效用的权衡。
- **内存组织与整合**：维护一棵层次内存树，对新进入的内存单元 \(m'\) 采用 LLM 辅助的整合算子：高度相似则合并，部分重叠则更新，无关则新建节点。树节点颜色编码价值，便于可视化。

#### （c）内存辅助响应
- **响应生成**：先利用历史高价值内存构建的用户偏好配置作为系统 prompt，再检索相关内存，并按 MS-value 重新排序，优先注入既语义相关又经验上高价值的单元。
- **内存归档**：用户完成会话后，将交互记录送入价值感知管线，形成闭环生命周期。
