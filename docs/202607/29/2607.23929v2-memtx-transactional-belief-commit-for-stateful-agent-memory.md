## 摘要
LLM智能体越来越多地通过持久化共享记忆进行协调：一个智能体的写入成为另一个智能体的前提，并最终导致具有真实副作用的工具调用。当前的智能体记忆系统将每个接受的写入视为立即可行动的事实，因此被污染的工具结果、过期更新或队友未完成的笔记可能无声地驱动不可逆的动作。我们认为记忆写入不是信念提交。我们提出MemTX，一种事务性信念提交协议。每条记录携带证据、权限、来源和有效性。写入被暂存在快照隔离事务中，并通过验证并提交管道准入，不可逆的工具调用基于进行中的信念状态进行门控，撤回信念会触发对其衍生记录和工具副作用的类型化级联修复。两个不变量——动作安全门控和级联修复完整性——通过基于属性的测试和对550万个协议状态的有界穷举枚举进行机器检验，零违规。在来自三个模型系列的五个骨干模型上，MemTX在所有八个基线方法中领先，在四个骨干模型上具有配对麦克尼马尔显著性，在第五个最强的骨干模型上统计上持平于最佳基线，同时是唯一在每个骨干模型上具有零下游危害的方法。骨干模型的能力不能替代提交纪律。

## Abstract
LLM agents increasingly coordinate through persistent shared memory: one agent's write becomes another agent's premise, and eventually a tool call with real side effects. Current agent memory systems treat every accepted write as immediately actionable truth, so a polluted tool result, a stale update, or a teammate's half-finished note can silently drive an irreversible action. We argue that a memory write is not a belief commit. We present MemTX, a transactional belief-commit protocol. Each record carries evidence, permissions, provenance, and validity. Writes are staged inside snapshot-isolated transactions and admitted by a validate-and-commit pipeline, irreversible tool calls are gated on in-flight belief state, and retracting a belief triggers typed cascading repair of its derived records and tool side effects. Two invariants, action-safety gating and cascade-repair completeness, are machine-checked by property-based testing and bounded exhaustive enumeration of 5.5 million protocol states, with zero violations. Across five backbones from three model families, MemTX leads all eight baselines with paired-McNemar significance on four backbones and statistically ties the best baseline on the fifth and strongest, while remaining the only method with zero downstream harm on every backbone. Backbone capability does not substitute for commit discipline.

  - 过期的写入（stale late write）无声覆盖先前修正。

- **整体含义**：论文指出“内存写入 ≠ 信念提交”，现有的记忆系统将“记录观察”与“提交信念”两个事件混为一谈，导致正确性边界仅停留在写入时刻，而忽略了行动时刻（action time）和事后修复（post-hoc repair）的需求。这本质上是数据库领域数十年前就已解决的隔离性难题，但智能体系统尚未采用相应纪律。

## 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：受数据库事务隔离机制的启发，提出一种事务性信念提交协议，将记忆写入分为暂存（stage）、验证（validate）、提交（commit）三个阶段，并通过显式的信念生命周期（belief lifecycle）进行管理。
- **关键技术细节**：
  - **数据模型**：每条记录不仅是实体-属性-值，还携带证据权重、权限块（所有者、读者/写者角色、私有/共享/公共作用域）、来源DAG、类型（信念/摘要/配置文件/索引/工具动作）、有效性区间、写入者置信度。
  - **信念生命周期**：8个状态：raw → tentative → validated → committed → action-safe，外加quarantined（检疫）、superseded（被替代）、revoked（撤销）。每种状态转换有固定规则。
  - **隔离级别**：5种读取隔离级别（raw-read, committed-read, verified-read, causally-stable-read, action-safe-read），分别暴露不同状态的生命周期记录。
  - **风险分层事务**：4个风险等级（low, medium, high, external-action），不同等级映射到不同隔离级别。外部动作事务强制要求action-safe记录支持。
  - **提交管道**：四步检查——①证据检查（置信度≥0.6或源权威≥0.9）；②有效性检查（当前逻辑时间在有效性区间内）；③语义冲突裁决（同实体属性槽：时间上较晚的写入若在快照后提交则直接中止，否则比权威；阻止派生自已撤销父节点或权限泄露的记录）；④依赖稳定性检查（祖先中无待决撤销）。通过全部检查的记录晋升为committed；external-action事务中进一步升级为action-safe。
  - **动作门控（Action Gating）**：调用不可逆工具前必须检查两个条件：
    - 事务快照外无任何tentative记录在飞行中（包括自身未提交的暂存）。
    - external-action事务的快照中至少包含一个action-safe记录。
    阻塞返回结构化拒绝及原因，允许智能体提交、中止或解决冲突后重试。
  - **类型化级联修复**：撤销信念（通过事务中止或显式撤销）时，遍历派生DAG，按记录类型分发：
    - 信念 → 直接撤销（revoked）。
    - 摘要/配置文件/索引 → 检疫（quarantined）待重建。
    - 工具动作 → 若可逆则补偿，否则标记为“已泄露”。
    每一步写入审计日志。
  - **不变量与机器验证**：
    - I1: action-safety gating（不可逆工具调用仅在无飞行中tentative记录且external-action事务有action-safe记录时执行）。
    - I2: cascade-repair completeness（撤销后所有非终结派生记录处于非活动状态）。
    - G3（推论）：不存在committed/action-safe记录具有已撤销的祖先。
    通过基于属性的测试（10,000随机轨迹）和有界穷举枚举（4个记录+3个并发事务，深度10，5,530,160个状态，10,537,260次转换）验证，零违规，并发现并修复了一个事务中止路径上的级联缺陷。
  - **智能体集成**：提供5个内存工具（read, stage, commit, abort, revoke），域工具通过门控路由。

## 6. 论文的主要结论与发现
- MemTX在5个骨干中的4个上任务成功率排名第一（Qwen3-8B: 0.956, Qwen2.5-14B: 0.811, GLM-4.7-Flash: 0.944, GPT-5.4-mini: 0.922），在GPT-5.5上与带级联撤销的Cordon持平（0.756 vs 0.778），但在下游危害上零危害相比于0.25显著胜出。
- 在所有方法中，MemTX是唯一在所有骨干上实现**零下游危害**的。即使TOKI在中止召回上接近甚至超过MemTX，其危害仍为0.25-0.5，证明写时裁决不能代替提交纪律。
- **强化套件上差距更大**：MemTX最佳骨干GPT-5.5达到0.929，次优Cordon+revocation仅0.768，所有32对比较均显著。GPT-5.5在主套件持平但在强化套件重新分离。
- **消融表明**：语义冲突裁决、权限继承、级联回滚各贡献约11个点任务成功率，且每个组件在特定腐败家族上是负载关键的（如动作门控对应act-after-stale-write家族）。
- **核心结论**：骨干模型能力不能替代提交纪律。GPT-5.5可以作为代理指标改善基线，但无法弥补协议层面的缺陷。零危害只能通过事务性信念提交实现。
- 两个根本开放的盲区：
  - **源作用域**：智能体在不声明父记录情况下转录私有内容，所有方法均失败（即使MemTX的权限继承检查也无法拦截，因为无父记录）。
  - **时间作用域**：滞后写入被正确中止后，智能体在新的快照中重试，此时快照已包含对手写，导致“迟到”不再成立，所有方法（除GPT-5.5+MemTX外）中止召回归零。

## 8. 不足与局限
- **覆盖局限**：
  - 源作用域盲区：由于智能体可能不声明父记录就转录，基于声明式来源的权限检查无法拦截。论文承认这是一个“最原则性的开放问题”。
  - 时间作用域盲区：重试事务导致快照推移，使“迟到”检测失效。只有GPT-5.5+MemTX组合尚可处理，但未通用化。
  - 补偿仅限于日志级决策义务，不保证环境级重放（不可逆动作只能标记为泄露，无法物理撤销）。
  - 可逆性是静态工具级别的，无法处理运行时边界变化（如结算后的退款）。
  - 修复只覆盖记录的来源DAG，不覆盖未记录推导的沉默污染。
- **实验偏差风险**：
  - 所有方法使用相同的提示和工具模式，但可能对某些协议不友好（如TOKI的设计可能更适合其他设置）。
  - 闭源骨干的端点可能未来会改变，但单次快照验证了当前版本。
  - 主套件中MemTX的强门控形式从未激活（因为外部动作事务从未在LLM路径上被声明），因此实验仅验证了弱门控。仅通过了脚本化路径和定价实验来证明强门控有效。
  - 消融组件之间的冗余无法被单组件去除暴露（例如依赖稳定性门控在取消后无变化，因为它被冲突检测覆盖）。
  - 强化套件每个家族只有4-10个案例，无法对每个家族做统计学显著检验。
- **应用限制**：
  - 需要在智能体框架中集成额外的五个记忆工具，可能增加系统复杂性。
  - 延迟虽然处于基线范围内，但令牌消耗在某些骨干上最多增加14%（能力最差的骨干），成本开销可能在一些场景下不成比例。
  - 对于不需要持久化、无并发写或只有可逆动作的场景，MemTX的收益有限。
  - 未能与更复杂的环境（如动态权限、自我演进的可逆性）充分测试。
