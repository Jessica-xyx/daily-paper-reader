## 摘要
持久化内存使长期运行的大型语言模型智能体能够在会话和任务之间重用信息。然而，可写内存中的错误可能会持续存在并破坏未来行为。现有系统改进了存储和检索，但并未为可靠更新和恢复提供事务边界。因此，我们提出了MemTxn，这是一个位于答案模型之外的治理层。MemTxn验证更新是否受其来源支持。它还在事实冲突时选择可见版本，并在故障后恢复应用可见状态。该系统使用有序补丁测试来验证写入，使用时间解析器来选择版本，并使用持久化快照日志来恢复状态。在逐项不相交的审计中，MemTxn接受了全部60个受支持的原始项，并拒绝了全部179个硬负样本。在LongMemEval-S和LoCoMo状态上的持久多键故障下，它能在不知道实际物理写入集的情况下恢复完整的声明活动映射。在MemoryAgentBench的FactConsolidation任务中，MemTxn在所有十二种答案模型配置中取得了最高的平均F1分数。在五个代表性设置中，它比Dense高出17.06至24.07个百分点。

## Abstract
Persistent memory lets long-running large language model agents reuse information across sessions and tasks. Yet errors in writable memory can persist and corrupt future behavior. Existing systems improve storage and retrieval, but they do not provide a transaction boundary for reliable updates and recovery. We therefore propose MemTxn, a governance layer outside the answer model. MemTxn verifies whether an update is supported by its source. It also selects the visible version when facts conflict and restores the application-visible state after a fault. The system uses Ordered PatchTest to validate writes, a Temporal Resolver to select versions, and a durable snapshot journal to recover state. On an item-disjoint audit, MemTxn accepts all 60 supported originals and rejects all 179 hard negatives. Under persistent multi-key faults on LongMemEval-S and LoCoMo states, it restores the complete declared active map without knowing the actual physical write set. On MemoryAgentBench FactConsolidation, MemTxn achieves the highest average F1 across all twelve answer-model configurations. It outperforms Dense by 17.06--24.07 points in five representative settings.

## 1. 论文的核心问题与整体含义

**研究动机与背景**

- 长期运行的 LLM 智能体（agent）依赖持久化内存跨会话复用信息（对话事实、用户偏好、任务状态等），这是智能体长程决策的基础。
- 然而，**可写内存中的错误会持久化并污染未来行为**：无来源支持的抽取可能被写入内存，事实冲突时可能暴露错误版本，部分写入可能破坏后续任务。
- 现有系统主要关注存储组织与检索效率（如 MemGPT 的分级记忆、Mem0 的持久记忆、A-Mem 的自主笔记、Zep 的时间知识图等），**但缺乏一个“事务边界”**（transaction boundary）来保证：更新是否被可靠提交、冲突时哪个版本可见、故障后恢复哪个状态。

**核心洞察**

- 外部记忆更新可以被治理为**应用级事务**（application-level transaction）：
  - 证据支持（evidence support）规范写入准入；
  - 显式冲突契约（conflict contract）选择对答案可见的版本；
  - 持久化的前镜像（preimage）支持故障恢复。
- 存储层的原子性只能保证物理写入的全有或全无，**无法强制执行这些语义契约**——必须由更高层治理。

**两大核心挑战**

- **C1**：如何在无答案监督的情况下判定哪个提议状态可以提交、哪个冲突版本应可见？细微抽取错误可能保留几乎所有源词但改变顺序或极性，相关性或新颖性无法建立来源支持。
- **C2**：如何在不知道实际物理写入集的情况下，在多键持久故障后恢复完整预期应用状态？单次逻辑更新可能跨多个物理键修改版本、指针、事实键等。

## 2. 论文提出的方法论

**MemTxn 整体架构**

MemTxn 是一个位于答案模型之外（answer-model-external）的治理层，包含三条独立路径：

1. **有序补丁测试（Ordered PatchTest）** —— 来源支持的更新准入；
2. **时间解析器（Temporal Resolver）** —— 冲突条件下选择可见版本；
3. **持久快照日志（Durable Snapshot Journal）** —— 完整状态恢复。

这种分离防止了“答案路径的柔性回退”与“写入决策”混为一谈，也防止存储层修复被误认为应用状态恢复。

**系统模型与信任边界**

- 持久内存状态表示为 $S_t=(V_t, A_t, J_t)$：$V_t$ 为只追加版本集，$A_t$ 为活动版本映射（$\kappa \mapsto \text{vid}$），$J_t$ 为持久事件与恢复意图。
- 应用可见投影 $\Pi_{\text{app}}(S_t)=A_t$。
- 上游抽取器提出 $q=(id, \kappa, u, r, v, e, s, \nu)$，包含键、主谓关系、值、证据跨度、来源 ID、时间元数据；存储对接受的提议扩展为版本 $z=(\text{vid}, q, \rho, \sigma, t_c)$。
- **信任边界**：提议者、候选值、可写子版本不受信任；SQLite、持久化意图、保存的活动映射快照构成恢复信任基。运行时决策不接触金标答案、基准类型、会话 ID、安全标签、故障标签。

**来源支持更新准入（有序补丁测试）**

- 核心谓词（公式 1）：
  $$
  \text{Support}_{\text{ord}}(q) = F(q) \land Q(e, D_s) \land [T(v) \preceq T(e)]
  $$
  - $T(x)$ ：归一化内容 token 序列；
  - $Q(e,D_s)$ ：归一化证据是源文本子串；
  - $T(v) \preceq T(e)$ ：**值的每个 token 按源顺序出现在证据中**（有序子序列关系）。
- 这使系统能够拒绝：否定插入（如 "not"）、源外替换、token 重排等硬负样本，即使词法重叠度高达 1.0。
- 通过谓词则创建子版本并更新指针；否则持久状态不变。**激活是状态转移而非答案时评分**，与未来问题无关。

**冲突条件下的版本解析（时间解析器）**

- 确定性触发：在时间顺序上以贪婪方式规范化键，当规范化主-谓 Jaccard 相似度 ≥ 0.60 或键完全匹配时触发冲突检测。
- 冲突定义：不同源 ID 且值既非完全相等也非 Jaccard 等效（≥ 0.80）。
- 解析规则（公式 2）：
  $$
  \text{Resolve}(C_\kappa) = \arg\max_{q \in C_\kappa} \nu(q)
  $$
  即选择时间戳最新（recency-as-truth）的版本，平局由源顺序和提议 ID 确定性打破。
- **关键点**：解析器不建立语义真理，只应用基准或应用声明的时序规则；且解析不影响写入状态，仅选择答案上下文。

**持久审计与完整状态恢复**

- 恢复条件（公式 3），需满足 $RB(\tau)$ 的完整链条：
  $$
  \text{PersistIntent}(A_0) \land \text{Reopen}(S_1) \land \left([\Pi_{\text{app}}(S_1)\ne A_0] \lor \neg I(S_1)\right) \land \text{Restore}(A_0) \land \text{Reopen}(S_2) \land I(S_2) \land \Pi_{\text{app}}(S_2)=A_0
  $$
  其中 $I(S)$ 为一致性检查（指针/版本存在性、事实键一致性、活动状态、事件重放）。
- 实现采用 SQLite WAL 模式，`synchronous=FULL`。恢复契约从外部检测器调用控制器时开始，**不假设一个逻辑键就能确定完整物理写入集**；单次补偿事务恢复保存的活动映射、标记被替换版本为已回滚、记录修复并最终确定意图。

**复杂度**

- 冲突检测触发器 $O(n^2)$，分组后解析 $O(n)$；
- 有序补丁测试与检查的源和 token 序列呈线性，无验证器调用；
- 快照持久化/恢复成本 $O(|A_t|)$ 个键，换取了写集无关性。

## 6. 论文的主要结论与发现

1. **来源支持**：在逐项不相交审计中，有序补丁测试是唯一实现 100% 准确率、平衡准确率、精确率和 F1 的门控，接受全部 60 个支持原始项、拒绝全部 179 个硬负样本；最强替代（Hybrid）仍有 49 个错误接受。
2. **恢复完整性**：在持久多键故障（通过 reopen 的持久性边界）下，MemTxn 无需物理写集即可恢复完整声明的活动映射，272 次运行零失败；单键回退在所有 136 次部分提交和事件分歧运行中均失败。
3. **冲突可见性**：在 FactConsolidation 上，MemTxn 在全部 12 种答案模型配置中取得最高平均 F1；5 个代表性设置中优于 Dense 17.06–24.07 F1 点，条件陈旧率降低 15.97–37.6 点。
4. **匹配池控制**：6 模型 top-8 匹配对照中增益保持 15.01–22.93 F1 点（池化 +19.51，所有模型 95% CI 均高于 0），排除候选池大小效应的解释。
5. **端到端治理**：3 个 API 端点上 MemTxn 均值：合法写入 1.0、错误写入拒绝 1.0、旧任务保留 0.992（检索仅保留 0.225）。
6. **鲁棒性**：门控可靠性从 100% 降到 50% 时，整体准确率从 100% 平滑降至 62.47%，仍比最强非 MemTxn 控制高 11.35 点；增益跨 5 个敏感性轴一致存在。

## 7. 优点

- **概念清晰**：首次将数据库事务概念系统化地映射到代理内存治理，将“准入、可见性、恢复”三个语义契约正式分离，界定明确。
- **答案模型无关**：治理在答案模型之外，写入决策不需要金标、标签或未来查询，避免评估信号泄漏。
- **可证明属性**：冻结谓词、声明时序契约、恢复条件均有形式化定义（公式 1–3），与实现对应。
- **消融严谨**：包含词法覆盖基线、校准基线、语言模型判断基线，证明了有序规则的增量价值；恢复审计包含特权 oracle（写集）作为上界对照。
- **控制变量精细**：匹配预算（一次答案调用）、匹配候选池（top-8 控制）、匹配统计单位（API 案例、源项、基准历史、持久历史分开报告）。
- **恢复契约强大**：不依赖物理写集信息即可恢复完整应用状态，匹配特权基线的覆盖而无需其访问权限；跨持久性边界（close→reopen）验证。
- **工程可实现**：基于 SQLite WAL 的标准事务基础，计算开销低（线性序检查、无验证器调用），易于集成。

## 8. 不足与局限

- **不保证语义真理**：有序补丁测试只验证词法有序支持，不能验证语义角色绑定或事实真实性；时间解析器只应用声明时序规则，不建立语义正确性。
- **硬负样本为模板生成**：否定插入、重排、替换是特定模板，未覆盖自然分布的抽取错误（如释义改写、跨句融合），自然输入下的覆盖范围未评估。
- **恢复假设局限**：要求持久化意图与 $A_0$ 快照完好且控制器被调用；不支持并发故障、重复故障、意图本身损坏或物理存储丢失。
- **并发未处理**：没有并发写入事务或锁机制说明，多代理并发更新场景未验证。
- **部署要求**：生产部署需要额外解决用户同意、保留策略、加密、访问控制和审计最小化，论文未深入。
- **基线选择空间有限**：对比系统（Mem0、A-Mem、Zep 等）主要代表存取范式，没有与记忆编辑/安全领域的知识编辑基线（如 Memit、WISE 等）直接比较（尽管 MemTxn 不改权重，类别不同）。
- **报告量有一定代价**：MemTxn 的 token 消耗虽与 Dense 相同量级，但快照日志的存储开销与活动键数线性增长，大规模长时运行时成本未深入分析。
- **独立性局限**：所有作者来自同一机构（北京师范大学），无第三方复现报告。
