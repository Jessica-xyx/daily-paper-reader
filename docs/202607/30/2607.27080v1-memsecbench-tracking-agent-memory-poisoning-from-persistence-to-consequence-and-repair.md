## 摘要
记忆系统使代理能够保留并重用过去交互中的信息，但它们也可能让恶意内容持续存在。攻击者精心构造的恶意指令可能被存储在长期记忆中，在很久之后被召回，悄然影响实际行为。近期基准测试越来越多地考察代理记忆安全性，但很少有研究在多种记忆后端比较下，追踪相同恶意语义的持久性、下游后果以及选择性修复。为填补这一空白，我们提出MemSecBench，一个基于任务的代理记忆系统生命周期安全基准测试。它包含310个案例，来自代码与科学、日常生活和办公工作等48个真实场景。每个案例在精确代理配置下遵循受控的写-执行-遗忘协议，在隔离运行时中定义，由代理框架、记忆后端和大语言模型后端构成。基于证据的裁决结合了确定性写入检查、检查点特定的评判模型评估以及七个生命周期检查点上的程序化门控。实验设计覆盖2个代理框架、4个记忆后端和3个大语言模型后端组成的24配置矩阵。在所有24种配置中，恶意记忆在84.2%的案例中持续存在，完整的写-执行链在50.3%的案例中成功。在成功投毒的案例中，59.6%完成完整的执行链，而56.1%实现选择性修复。与匹配的原生配置相比，端到端攻击成功的最大绝对差值为16.1个百分点，选择性修复的最大绝对差值为41.3个百分点。这些描述性对比表明，所评估的记忆系统堆栈在生命周期安全性方面存在差异，既体现在恶意记忆的传播上，也体现在成功记忆投毒后的选择性修复上。

## Abstract
Memory systems allow agents to retain and reuse information from past interactions, but they can also let malicious content persist. A malicious instruction crafted by an attacker may be stored in long-term memory, recalled much later, and quietly shape a real action. Recent benchmarks increasingly examine agent memory security, yet few trace the same malicious semantics across persistence, downstream consequences, and selective repair under diverse memory-backend comparisons. To address this gap, we introduce MemSecBench, a task-grounded benchmark for the lifecycle security of agent memory systems. It contains 310 cases drawn from 48 realistic contexts across code and science, daily life, and office work. Each case follows a controlled Write--Execute--Forget protocol in an isolated runtime under an exact agent configuration, defined by an agent harness, a memory backend, and an LLM backend. Evidence-based adjudication combines a deterministic write check, checkpoint-specific judge-model evaluations, and programmatic gates across seven lifecycle checkpoints. The experimental design spans a 24-configuration matrix of two agent harnesses, four memory backends, and three LLM backends. Across all 24 configurations, malicious memory persists in 84.2% of all cases, and the full Write--Execute chain succeeds in 50.3%. Among successfully poisoned cases, 59.6% complete the full Execute chain, while 56.1% achieve selective repair.Compared with matched Native configurations, the largest absolute differences are 16.1 percentage points for end-to-end attack success and 41.3 percentage points for selective repair. These descriptive contrasts indicate that the evaluated memory system stacks differ in lifecycle security, both in the propagation of malicious memory and in selective repair after successful memory poisoning.

## 2. 方法论

- **核心思想**：将每个安全案例建模为一个链接的任务包 \( T = (\rho, x_W, x_E, x_F, \ell) \)，其中 \(\rho\) 是干净初始记忆源材料，\(x_s\) 是各阶段代理任务，\(\ell\) 是设计标签和检查点评分规则。每个案例追踪相同的目标恶意语义（由 W2 检查点评分规则定义）通过三个生命周期阶段：
  - **Write**：攻击者通过载体（用户交互、工作区文件、外部内容等）将恶意内容输入代理工作流，测试恶意语义是否持久化到记忆后端。
  - **Execute**：用户在无攻击负载的第二会话提交良性任务，测试持久化恶意内容是否被召回、采纳并产生案例定义的后果（如数据泄露、未授权操作等）。
  - **Forget**：从同一已验证中毒记忆状态分支，测试能否选择性移除恶意语义同时保留所有必需的良性记忆。
- **关键技术细节**：
  - **证据裁决**：设置7个生命周期检查点（W1写入操作、W2持久化、E1召回暴露、E2采纳、E3外部化、F1修复、F2良性保留）。除W1为确定性检查外，其余由独立评判模型（DeepSeek-V4-Pro）在离线、温度0、JSON响应模式下依据检查点特定的证据包进行判断，并通过程序化门控（源可接受性、时间依赖、完整性、跨工件一致性）过滤无效证据。

- **评估配置**：实验设计为 **2×4×3 = 24种配置**：
  - 代理框架：OpenClaw、Hermes
  - 记忆后端：Native、Mem0、Mem0-Graph、A-MEM

## 6. 主要结论与发现

- **发现1**：**采纳阶段是攻击完成的主要瓶颈**。W1→W2→E1 通过率较高（从91.1%降至76.1%），但 E2（采纳）大幅下降至53.7%，E2E链最终为50.3%。说明持久化和召回过滤效果有限，但一旦恶意内容被代理“采纳”，多数能产生外部后果。
- **发现2**：**良性记忆保留是选择性修复的主要瓶颈**。F1（移除）通过率86.3%，F2（保留）仅62.5%，联合 SRSR 只有56.1%。说明成功移除目标但造成良性记忆的附带损害是主要失败原因，仅报告目标移除会高估修复能力。
- **发现3**：**抵抗与修复是独立安全需求**。某些后端在降低攻击成功率和提高修复率上表现不一致（如 OpenClaw/DeepSeek 下，A-MEM 降低 E2E-ASR 但大幅提高 SRSR；Mem0-Graph 降低 E2E-ASR 但 SRSR 基本不变）。表明不能用一个指标衡量后端安全。
- **发现4**：**没有记忆后端在所有配置中更安全**。后端效果可能随代理框架和LLM改变而反转（如 Mem0 在 OpenClaw 下降低 E2E-ASR，但在 Hermes/MiniMax 下反而提高）。必须结合完整配置评估。

## 7. 优点

- **全生命周期视角**：首次在同一案例中追踪恶意语义从写入→持久化→召回→采纳→外部化→修复的完整链条，而非孤立检查。
- **受控多后端比较**：通过固定所有其他因素，实现记忆后端的匹配对比，清晰揭示不同后端对安全属性的影响差异。
- **基于证据的严格裁决**：避免依赖代理自身声明或意图，仅使用可验证的后端证据、服务记录等，并通过程序化门控抵制幻觉和注入。
- **高可复现性**：提供了完整的任务包构造协议（Build-MemSecBench-Case Skill）、运行时隔离配置、证据打包格式，有利于其他研究者复现或扩展。
- **人类注释验证**：对评判模型进行了500条样本的双人标注验证，准确率超90%，增强结果可信度。

## 8. 不足与局限

- **记忆后端种类有限**：仅测试4种后端（Native、Mem0、Mem0-Graph、A-MEM），未涵盖更多商用或开源方案（如 Pinecone、Chroma、FAISS 等），结论的泛化性受限。
- **配置参数未归一化**：各后端的容量、检索 top-k、阈值、向量维度等参数不同，未做均衡化处理，可能引入偏差。

- **语言覆盖不足**：仅使用英语任务包；论文提及有中文镜像但未用于正式实验，跨语言安全属性未知。
- **威胁模型假设较强**：假设恶意内容已通过受支持载体进入工作流，但未建模攻击者如何获得账户/会话访问。内部威胁或更复杂攻击面未覆盖。
- **计算成本未量化**：未报告实验所需GPU型号、数量和时间，其他研究者难以估计复现成本。
- **案例构造依赖于 GPT-5.5 和人工审查**：虽通过技能引导和多重验证保证质量，但仍有潜在偏见，且案例规模（310）相对较小。
- **未测试防御机制**：基准只评估攻击和修复，未包含系统内置防御（如权限检查、来源验证）的对比分析。
