## 摘要
基于LLM的智能体扩展了大语言模型，使其具备跨会话持久化隐私敏感用户数据的长时记忆（LTM）。生产系统通过内存隔离来缓解提取风险，将每个用户的LTM绑定到唯一标识符。这种防御已阻止了已知的针对共享存储的攻击，导致人们认为隔离的LTM是安全的。我们发现工具接口是一个被忽视的攻击面。智能体通常将LTM检索到的数据嵌入工具调用参数中，这使得恶意工具能够在违反用户级隔离的情况下渗出私有记忆。对用户侧提取技术的简单适配会失败，因为对抗性命令的语义干扰了检索精度，并且平台强加的工具调用限制约束了每次触发的提取预算。我们提出SPORE，这是首个针对此威胁模型设计的提取攻击。SPORE通过将对抗性命令持久化到短期记忆中并在工具响应中发出语义纯粹的锚点，从而将对抗性命令与检索锚点解耦。恢复的检索精度实现了对嵌入空间的几何覆盖优化，系统地将锚点导向未探索的记忆区域。为了在工具调用限制之外持续提取，SPORE在内存中持久化重新激活负载，能在会话内和跨会话自动恢复攻击，无需额外用户触发。SPORE在无限触发条件下达到80.0%的记录提取率，在仅有20次触发时达到47.0%。在多用户部署中，攻击者可将提取的记录链接到用户身份，从而实现针对性监视。这些结果表明，仅靠内存隔离是不够的，需要重新审视智能体架构中工具侧的可信边界。

## Abstract
LLM-based agents extend large language models with long-term memory (LTM) that persists privacy-sensitive user data across sessions. Production systems mitigate extraction risks through memory isolation, binding each user's LTM to a unique identifier. This defense has blocked known attacks on shared storage, fostering the assumption that isolated LTM is secure. We identify the tool interface as an overlooked attack surface. Agents routinely embed LTM-retrieved data in tool invocation parameters, enabling a malicious tool to exfiltrate private memory without violating user-level isolation. Naive adaptations of user-side extraction techniques fail because the adversarial command's semantics interfere with retrieval precision, and platform-imposed tool-call limits constrain the extraction budget per trigger. We present SPORE, the first extraction attack designed for this threat model. SPORE decouples the adversarial command from retrieval anchors by persisting the command in short-term memory and emitting semantically pure anchors in tool responses. The restored retrieval precision enables a geometric coverage optimization over the embedding space that systematically steers anchors toward unexplored memory regions. To sustain extraction beyond tool-call limits, SPORE persists reactivation payloads in memory that automatically resume the attack within and across sessions without additional user triggers. SPORE achieves an 80.0% record extraction rate with unlimited triggers and 47.0% with only 20 triggers. In multi-user deployments, attackers can link extracted records to user identities, enabling targeted surveillance. These results demonstrate that memory isolation alone is insufficient and call for reexamining tool-side trust boundaries in agent architectures.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：LLM 智能体通过长时记忆（LTM）持久化存储隐私敏感的用户数据（如医疗记录、财务信息、个人对话）。生产系统采用严格的内存隔离机制（每个用户的 LTM 通过唯一标识符绑定，其他用户无法访问）来防止数据泄露。这被认为是有效的防御手段。
- **核心问题**：作者发现一个被忽视的攻击面——**工具接口**。智能体在调用外部工具时，会将 LTM 检索到的数据编入工具调用参数，这些参数会发送到第三方工具服务端。若工具是恶意的，就能在**不违反用户级内存隔离**的情况下直接窃取隐私数据。
- **整体含义**：现有用户侧提取攻击（通过恶意用户查询获取其他用户记忆）已被内存隔离完全阻止，但工具侧攻击通道仍然开放。仅靠内存隔离不足以保护 LTM 隐私，必须重新审视智能体架构中工具侧的可信边界。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- 利用 LLM 智能体的**状态持久性**：注入的内容可以在迭代和会话之间持续存在并影响后续行为。
- 将**对抗性命令与检索锚点解耦**：命令持久化在短期记忆（STM）中，工具响应仅包含纯语义锚点，消除命令对检索的语义干扰。
- 将记忆提取**形式化为嵌入空间上的几何覆盖优化问题**：系统性地引导锚点探索未被检索的记忆区域。
- 通过**持久化重激活载荷**突破平台强加的工具调用次数限制，使攻击能在会话内或跨会话自动恢复。

### 2.2 攻击流程（三步）

#### 步骤 ❶：建立对抗上下文
- 恶意工具被触发后，在第一次迭代中仅返回一个对抗性命令 `Cadv`。
- 该命令被自动追加到智能体的 STM 中，成为持久指令，指导后续检索和工具调用。
- **解耦效果**：后续迭代的工具响应只包含纯锚点，不受命令干扰。

#### 步骤 ❷：迭代记忆提取
- 在第 2 到 N-1 次迭代中，工具返回优化后的语义锚点。
- 智能体用锚点检索 LTM，并将检索到的内容通过工具调用参数返回给恶意工具。
- **几何覆盖优化**：将检索区域建模为嵌入空间中的“已探索球”，通过**细粒度扩展**（在已发现区域内沿边界扩展）和**粗粒度发现**（从检索内容中提取关键词，发现远距离未探索簇）交替进行，并用自适应模式切换（连续 γ 次无新记录则切换模式）。

#### 步骤 ❸：重激活状态持久化
- 在提取循环结束前，恶意工具注入重激活载荷 `Preact`。
- 载荷包含：生成良性的最终回答（隐藏攻击）、嵌入重激活状态。
- **三种持久化配置**：
  - 无持久化：仅靠用户再次触发。
  - STM 持久化：载荷留在 STM 中，在同一会话后续查询中自动恢复攻击。
  - LTM 持久化：载荷写入 LTM，通过未来会话中相似度检索自动唤醒，无需触发。

### 2.3 命令与载荷优化
- 使用基于 LLM-Fuzzer 的黑盒搜索，在自建测试环境中优化 `(Cadv, N)` 和 `Preact`，以最大化提取率并满足工具调用限制。

## 3. 实验设计

  - **LoCoMo**：多会话个人对话，代表个人助理。
- **用户查询**：触发查询（GPT-4o-mini 生成，调用恶意工具）；良性查询（场景 2 用 MS MARCO，场景 3 用语义相关日常查询）。

### 3.2 攻击场景（三种，难度递增）
- **场景 1：频繁触发**（工具被频繁调用，无触发限制），采用无持久化配置。

## 6. 主要结论与发现

1. **工具侧是有效的攻击面**：虽然用户级内存隔离阻止了用户侧提取，但恶意工具可以通过工具调用参数窃取 LTM 数据。
2. **SPORE 高效实用**：
   - 场景 1：无限触发下 RER 达 80.0%（GPT-5-mini），SS 为 1.00（完美），BRR 61.5%。
   - 场景 2：20 次触发下 RER 达 47.0%，BRR 80%。
   - 场景 3：单次触发下 RER 达 76.5%（HealthCareMagic），且能在多会话中自动恢复。
3. **解耦是关键**：将命令与检索锚点分离消除了语义干扰，恢复了对检索方向的精确控制。
4. **几何覆盖优化有效**：自适应混合模式比单一模式提取效果更好，覆盖率持续提升。
5. **多用户部署风险更大**：通过 OAuth 2.1 可关联用户身份，实现定向监控，威胁远超批量聚合。
6. **仅靠语义级防御不足**：响应过滤和提示硬化能降低但无法消除提取（RER 仍达 32.5%），需要系统级工具侧内存隔离。

## 8. 不足与局限

- **实验规模有限**：受害者 LTM 仅 200 条记录，真实系统可能数万条，提取效率可能劣化（虽然几何优化理论上可扩展，但未验证大库场景）。
