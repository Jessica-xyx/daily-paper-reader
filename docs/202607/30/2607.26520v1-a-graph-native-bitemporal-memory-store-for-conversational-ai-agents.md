## 摘要
对话式AI代理通常缺乏跨会话的持久记忆。常见的修复方法，例如将完整的聊天历史注入上下文窗口，或委托给第三方记忆服务，要么会耗尽模型的上下文预算，要么通过用户无法控制的基础设施发送个人数据。我们描述了一种避免这两个问题的记忆存储：一个代理本地的Neo4j属性图，增强有HNSW向量索引和完整的双时态数据模型。每个记忆存储为一个不可变的身份节点，链接到带有两个闭开时间区间的版本化内容节点：有效时间（事实在现实世界中为真的时间）和事务时间（数据库记录它的时间）。这种设计支持时间点语义检索，无需物理覆盖历史。相关记忆之间的语义边在写入时自动通过1024维嵌入的余弦相似度维护。我们在LongMemEval上评估该系统，这是一个包含500个问题、跨越六种问题类型、旨在测试长期记忆的基准。在60个抽样问题上，当前状态的语义搜索路径总体达到46.7%的R@10，在知识更新问题上上升到80%。时间旅行路径在知识更新问题上达到80%的R@10，但在时间推理问题上召回率下降（50%到37.5%），这是后过滤稀释的结果，直接指向具体的设计改进。我们讨论了这些结果揭示了纯检索对不同问题类型的局限，以及每个失败模式对未来工作的启示。

## Abstract
Conversational AI agents commonly lack persistent memory across sessions. The obvious fixes like injecting full chat histories into the context window, or delegating to a third-party memory service, either exhaust the model's context budget or send personal data through infrastructure the user does not control. We describe a memory store that avoids both problems: an agent-local Neo4j property graph augmented with HNSW vector indexes and a full bitemporal data model. Each memory is stored as an immutable identity node linked to versioned content nodes carrying two closed-open time intervals: valid time (when the fact was true in the world) and transaction time (when the database recorded it). This design supports point-in-time semantic retrieval without physically overwriting history. Semantic edges between related memories are maintained automatically at write time using cosine similarity over 1024-dimensional embeddings. We evaluate the system on LongMemEval, a 500-question benchmark spanning six question types designed to stress long-term memory. Across 60 sampled questions, the current-state semantic search path achieves 46.7% R@10 overall, rising to 80% on knowledge-update questions. The time-travel path yields 80% R@10 on knowledge-update but decreases recall on temporal-reasoning questions (50% to 37.5%), a consequence of post-filter dilution that points directly to a concrete design improvement. We discuss what these results reveal about the limits of pure retrieval for different question types and what each failure mode suggests for future work.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 在Neo4j属性图上实现**双时态向量索引**，将记忆的**不可变身份**与**版本化内容**分离，并通过**有效时间**和**事务时间**两个闭开时间区间记录事实在现实世界中和在数据库中的时间状态，支持历史回溯而不物理覆盖。
- 自动维护语义边（`RELATED_TO`）连接相关记忆，实现图遍历式关联检索。

### 关键技术细节
- **数据模型**：
  - `:Memory` 身份节点（永久、不可变）。
  - `:MemoryVersion` 版本节点（包含内容、嵌入、类别、标签及四个时间戳：`valid_from`, `valid_to`, `tx_from`, `tx_to`；当前版本额外标注 `:CurrentVersion`）。
  - 关系：`HAS_VERSION`（身份→版本）、`RELATED_TO`（语义相似，写入时自动构建）。
- **双时态模型**：
  - 有效时间：`[valid_from, valid_to)`，表示事实在现实世界为真的区间。
  - 事务时间：`[tx_from, tx_to)`，表示数据库记录该版本的时间区间。
  - NULL 上界表示区间仍开放。更新时关闭旧版本（设置`tx_to`、移除`:CurrentVersion`），创建新版本。
  - 删除仅关闭时间区间，不物理移除版本，保留完整历史。
- **双索引检索**：
  - **当前状态索引**：仅索引 `:CurrentVersion` 节点，返回最新版本。
  - **历史检索索引**：索引所有版本节点，采用 **10×k 过采样**后按时间条件后过滤。
  - 过滤条件：`valid_from <= $valid_at AND (valid_to IS NULL OR valid_to > $valid_at)` 与 `tx_from <= $tx_at AND (tx_to IS NULL OR tx_to > $tx_at)`。
  - 复合B树加速过滤。
- **语义边自动构建**：每次写入时，对当前版本索引执行 top-5 ANN 搜索，余弦相似度 ≥0.75 则创建/更新 `RELATED_TO` 边。
- **工具函数**：暴露9个工具，包括 `save_memory`、`update_memory`、`as_of_semantic_search` 等，通过 Claude 工具循环调用。
- **存储策略**：仅索引用户消息（role="user"），忽略助手回复。

## 3. 实验设计：数据集、Benchmark 、对比方法

- **数据集**：使用 **LongMemEval** 基准，包含 500 个问题，由合成多会话对话构建，覆盖六种类型：
  1. 单会话用户陈述（ss-user）
  2. 单会话助手输出（ss-asst）

- **实验设置**：从每种类型中**采样 10 个问题**，共 60 个问题（随机种子 42）。每次清空数据库后，只摄入长度≥20字符的用户消息（`valid_from`设置为会话日期）。

## 6. 论文的主要结论与发现

- **直接事实回忆表现良好**：单会话用户陈述 R@10=90%，知识更新 R@10=80%。
- **结构性问题导致两类问题低分**：
  - 助手输出（20%）和偏好推断（10%）低分是因为**未索引助手消息**和**偏好答案非用户原文**，而非检索算法本身问题。
- **时间旅行路径存在后过滤稀释**：在时间推理问题上，时间旅行路径召回率（37.5%）反而低于当前状态路径（62.5%），原因是过采样 10×k 后过滤，目标答案可能被大量无效候选稀释到 top-10 之外。这是一个可复现的设计缺陷，而非双时态模型的根本局限。
- **跨会话计数问题纯检索无效**：多会话类型 R@10=30%，大部分答案需要多会话事件聚合，无法通过简单向量检索获得。
- **总体性能**：当前状态路径整体 R@10=46.7%；时间旅行在知识更新上与当前状态持平（80%），但对时间推理表现更差。

## 7. 优点

- **隐私保护设计**：本地部署为主（默认 `bolt://localhost:7687`），用户数据不离开自有环境，避免第三方服务隐私风险。
- **双时态模型融合向量检索**：将纯关系数据库的时态理论巧妙应用于非结构化的 LLM 记忆场景，在 Cypher 中直接表达时间旅行查询，同时保留 HNSW 的语义检索能力。
- **自动语义图链接**：基于余弦相似度阈值的 `RELATED_TO` 边构建，提供廉价的关联记忆遍历操作，思路简洁。
- **版本化历史保留**：旧版本数据永久保存，支持审计和时间点回溯，符合 AI 记忆可解释性需求。
- **系统实现完整**：包括工具循环、迁移脚本、索引管理，展示了从设计到部署的完整工程方案。

## 8. 不足与局限

### 实验覆盖不足
- 仅抽样60个问题，未对全部500问题进行评测，统计结果可能存在偏差。
- 未与任何现有记忆系统（如 MemGPT、Mem0、Zep、LangChain ConversationSummaryMemory）进行公平对比，无法证明本方法的相对优劣。
- 缺乏消融实验：未检验不同过采样倍数（如5×、20×）、不同相似度阈值（0.7/0.8）、不同的嵌入模型对结果的影响。
- 仅用 R@k 一个指标，缺少对检索精确率、检索延迟、内存占用等指标的评估。

### 实验偏差风险
- 手动抽样（seed=42）可能无意中偏向某些类型；未说明全量数据分布。
- 时间推理问题的“null”结果被解释为正确（两个例子），但缺乏进一步验证其是否符合预期。
- 助手消息不索引导致两个类型的结果无效，削弱了对系统全面性的评估。

### 应用限制
- **不支持事件聚合**：纯检索无法处理计数、推理等需要多步聚合的问题，需额外事件抽取和计数节点支持。
- **时间旅行路径性能瓶颈**：10×过采样导致后过滤稀释，时间推理召回率反而下降，当前设计不适合时间敏感查询。
- **不存储助手消息**：限制了回忆助手过去输出的能力，尽管设计上可扩展。
- **图边维护代价可控但未量化**：每次写入增加一次 ANN 查询，但实验中未报告写入延迟或边密度对图检索的影响。
- **嵌入模型与LLM强耦合**：依赖于特定的闭源模型（Titan Embed, Claude），可能引入供应商锁定风险。
