## 摘要
大语言模型日益成为持久会话助手，需要记忆来保留相关经验并维持跨交互的连续性。现有方法通过长上下文处理、选择性检索和结构化记忆组织来改进对会话历史的访问。然而，大多数系统将记忆访问视为检索相关历史信息，而未先确定当前轮次续接的是哪个先前的交互状态。当对话交织着多个任务、人物和计划，且可能中断后再次回归时，这一局限变得尤为重要。我们提出ArborMem，一种在线记忆框架，将长时对话表示为可导航的交互状态森林。每个分支保留局部连贯的轨迹，而森林则维护多条日后可恢复的轨迹。对于每个新输入，ArborMem定位相关状态，恢复其分支局部上下文，并用跨分支检索到的可复用证据进行增强，从而在保留交互连续性的同时，不混淆语义相关但结构不同的轨迹。现有的长期记忆基准涵盖了多种记忆与推理能力，但未明确分离出分支结构挑战。为此，我们提出BranchMemEval，一个用于交织和可恢复交互轨迹的受控诊断基准。在LongMemEval、LoCoMo、BEAM 100K和BranchMemEval上的实验表明，ArborMem在三个既定基准上以3.36至10.31个百分点优于最强基线，在BranchMemEval上则高出5.0个百分点。在受限的读取预算下，其优势进一步扩大，而完整的记忆查询仍保持在半秒以内。

## Abstract
Large language models increasingly serve as persistent conversational assistants, requiring memory that preserves relevant experience and maintains continuity across interactions. Existing methods improve access to conversational history through long-context processing, selective retrieval, and structured memory organization. However, most systems treat memory access as retrieving relevant past information without first determining which prior interaction state the current turn resumes. This limitation becomes particularly important when conversations interleave multiple tasks, people, and plans that may be interrupted and later revisited. We introduce ArborMem, an online memory framework that represents a long-running conversation as a navigable forest of interaction states. Each branch preserves a locally coherent trajectory, while the forest maintains multiple trajectories that may later be resumed. For each new input, ArborMem localizes the relevant state, restores its branch-local context, and augments it with reusable evidence retrieved across branches, preserving interaction continuity without conflating semantically related but structurally distinct trajectories. Existing long-term memory benchmarks cover diverse memory and reasoning capabilities but do not explicitly isolate branch-structured challenges. We therefore introduce BranchMemEval, a controlled diagnostic benchmark for interleaved and resumable interaction trajectories. Experiments on LongMemEval, LoCoMo, BEAM 100K, and BranchMemEval show that ArborMem outperforms the strongest baselines by 3.36 to 10.31 percentage points on the three established benchmarks and by 5.0 points on BranchMemEval. Its advantage grows under constrained read budgets, while complete memory queries remain below half a second.

### 1.1 背景

### 1.2 核心问题
- 大多数记忆系统将记忆访问视为"**检索相关的历史信息**"，但**没有先确定当前输入续接的是哪个具体的先验交互状态**。
- 在对话交织多个任务、人物和计划（可能中断并被重新拾起）时，这种"忽略状态定位"的做法会导致：
  - 轨迹混淆：相关性检索将语义相近但结构不同的线程混合；
  - 连续性受损：无法正确识别被恢复的上下文的"本地连贯轨迹"。
- 论文以实例说明：虽然最近数轮都在讨论"会议出行"，但用户一句"修订后的数字上传了吗"实际续接的是**更早的论文修订轨迹**——这需要状态定位而非单纯相关性检索。

### 1.3 核心研究问题
> 在长期会话记忆系统中，**如何先定位当前轮次所续接的交互状态，再选择历史证据**，以在多任务交织场景下保持连续性？

## 二、方法论：ArborMem

### 2.1 总体框架
- ArborMem 将长期对话表示为**可导航的交互状态森林**，核心记忆状态定义为：**S_t = (F_t, M_t)**
  - **F_t（对话森林）**：每个节点对应一次"用户-助手"交互交互产生的**局部状态**；父边编码"状态延续"，根到节点的路径构成一条**局部连贯轨迹**；森林允许多条轨迹共存、随时恢复。
  - **M_t（可复用证据库）**：包含**原子事实**（偏好、标识符、日期、项目细节）与**结构化记录**（助手生成的工件、事件、可变状态条目），每项保留来源与修订元数据。
- 在线运行流程呈"三段式"：**状态定位 → 上下文组装与生成 → 在线提交**，并且严格遵守**因果边界**——每次只读取已提交状态 S_{t-1}，生成后才提交新状态 S_t。

### 2.2 状态定位（State Localization）
- **优先级快速通道**：
  - 显式延续线索 → 直接挂在当前活动状态；
  - 显式时间回归线索 → 通过全局交互时间线解析。
- **混合候选集构建（三路召回）**：
  - **语义召回**：FAISS 向量检索；
  - **关键词召回**：词法/实体索引；
  - **主题锚点**：检测到显式主题时加入主题匹配节点。
- **分支感知重排序**：对候选节点用"主题键 + 路径摘要 + 节点摘要 + 实体"组合表征，由交叉编码器打分。
- **综合定位分数**：
  s_t(v) = s_ce(v) + s_key(v) + s_rec(v) + s_topic(v)
  - s_ce：交叉编码器重排分；s_key：关键词/实体修正；s_rec：近期偏置；s_topic：主题锚点修正。
- **父状态选择**：取最高分节点作为父状态 p_t（需超过阈值 τ，否则开始新根）。默认 τ = 8.0。

### 2.3 上下文组装与生成
- **分支局部轨迹**：从根到 p_t 的路径；在读取预算内保留原文，超限时早段压缩为摘要、末段保留 4 个节点原始轮次。
- **跨分支证据（三个来源）**：补充轮次、原子事实、结构化记录（工件/事件/可变状态）。
- **四通道证据束**：
  E_t = [C_local^t; E_turn^t; E_fact^t; E_struct^t; u_t]
  - 分支局部上下文作为主语境，跨分支证据作为补充。
- **响应生成**：a_t = G(E_t)，使用共享的生成器 LLM。

### 2.4 在线记忆提交
- 生成完成后，新交互作为子节点挂接到 p_t 下（或成为新根）；
- 更新路径摘要、语义/关键词索引、结构元数据、活动状态指针；
- 用专门的**后置提取器**提取原子事实与结构化记录，链接到来源节点并执行修订检查（新事实可能将旧值标记为过时）；
- 从 (u_t, a_t) 提取的信息**仅从第 t+1 轮起可读**，严格保持因果边界。

### 2.5 关键设计思想
> "连续性 ≠ 相关性"：森林拓扑编码的是**话语连续性和状态演化**，而语义相关未必属于同一轨迹；这使 ArborMem 能结合局部连续性与跨分支信息复用，而不混淆不同结构轨迹。

### 3.2 BranchMemEval 设计
- **五个诊断维度**：
  - B1 **backjump**（跳回更早轨迹，26 题）
  - B2 **state update**（在正确轨迹内取最新值，16 题）
  - B3 **assistant artifacts**（回忆助手生成的列表/记录，24 题）
  - B4 **cross-branch bridging**（跨轨迹组合证据，14 题）
  - B5 **twin threads**（区分结构相似的平行议程，20 题）
- **四个构建族**：Backjump、Artifact、Twin、Bridge，每个会话含 3–4 个交织主题分支，平均 46.73 轮。
- **构造方式**：程序化规划器（指定分支、事实槽位、更新、工件、干扰项、题目位置、金答案）+ 语言模型自然化（非问题轮次）→ 自动验证（证据有效性、防泄漏、维度检查），配对**结构上相似的混淆答案**以区分"检索失败"与"轨迹混淆"。
- **在线协议**：逐轮回放；问题仅用已提交前缀回答；之后用数据集标准轮次继续，防止模型输出污染后续历史。
- **评分**：规则化的归一化精确匹配，定义四类结果（正确 / 轨迹混淆 / 歧义 / 未命中）。

- **整体结论**：交互状态定位是可靠长期记忆的基础；"局部轨迹连续性 + 跨分支可复用证据"的组合在长时多任务场景下优于纯长上下文、纯检索与现有结构化记忆系统。
