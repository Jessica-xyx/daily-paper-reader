## 摘要
大型语言模型（LLM）代理越来越多地使用外部记忆系统，通过利用漫长且不断演变的交互历史来支持个性化，其中用户偏好可能随时间分布、随情境变化，并与早期证据相冲突。然而，现有系统面临三个局限性：固定轮次、固定令牌或基于会话的边界可能混合不相关的对话，或将事件与其原因、决策和结果分割开来；将同一交互中的多条用户信息存储为单一记忆会将功能不同的项目绑定在一起，这些项目应可独立检索；以及将当前任务视为单个top-$k$检索查询可能返回个别相关但无法共同捕捉偏好演变、时间有效性和情境适用性的片段。我们引入了\textsc{QUMem}，一种用于查询条件用户状态推断的结构化记忆框架。\textsc{QUMem}首先根据语义连续性将交互历史分割为可变长度的片段，然后将每个片段分解为可独立检索的事实、偏好和可迁移见解记忆，同时保留时间位置和来源证据。在推理时，三个顺序代理识别任务特定的信息需求，在类型化记忆存储上规划多查询检索，并联合推断出在时间和情境上有效的用户状态，以用于下游响应生成。\textsc{QUMem}在PersonaMem和KnowU-Bench上均取得了最先进的性能，证明了查询条件用户状态推断对长期个性化的有效性。

## Abstract
Large language model (LLM) agents increasingly use external memory systems to support personalization by drawing on long and evolving interaction histories, in which user preferences may be distributed across time, change with context, and conflict with earlier evidence. However, existing systems face three limitations: fixed-turn, fixed-token, or session-based boundaries can mix unrelated dialogue or split an event from its causes, decisions, and outcomes; storing multiple pieces of user information from the same interaction as a single memory binds together items that serve different functions and should be independently retrievable; and treating the current task as a single top-$k$ retrieval query can return fragments that are individually relevant but fail to jointly capture preference evolution, temporal validity, and contextual applicability. We introduce \textsc{QUMem}, a structured memory framework for query-conditioned user-state inference. \textsc{QUMem} first segments interaction histories into variable-length episodes according to semantic continuity, then decomposes each episode into independently retrievable factual, preference, and transferable insight memories while preserving temporal positions and source evidence. At inference time, three sequential agents identify task-specific information needs, plan multi-query retrieval over the typed memory stores, and jointly infer a temporally and contextually valid user state for downstream response generation. \textsc{QUMem} achieves state-of-the-art performance on both PersonaMem and KnowU-Bench, demonstrating the effectiveness of query-conditioned user-state inference for long-term personalization.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 代理正越来越多地扮演持久个人助理角色，需要长期与同一用户交互并在此过程中完成多步任务。为支持个性化，代理依赖外部记忆系统来保存和利用长期交互历史。
- **核心问题**：现有记忆系统在从长且不断演变的交互历史中提取用户状态时，存在三个关键局限：
  1. **边界失配**：固定轮次、令牌数或会话边界的记忆单元容易混入无关对话，或割裂同一事件的原因、决策与结果，从而破坏事件级上下文。
  2. **语义耦合**：同一次交互中往往包含多条功能不同的用户信息，若整体存储为单条记忆，后续检索无法只取与当前查询相关的部分。
  3. **单一查询检索不足**：将当前任务直接作为单个 top-k 检索查询，可能返回个别相关但无法共同反映偏好演变、时间有效性和情境适用性的碎片化证据。
- **研究意义**：长期个性化的核心不仅在于"找到相关记忆"，更在于"推断一个在时间和情境上均有效的、与任务相关的用户状态"。QUMem 正是针对这一核心问题提出解决方案。

## 2. 方法论：核心思想、关键技术与算法流程

### 2.1 核心思想

QUMem 将长期个性化问题形式化为从交互历史 H 和当前查询 q 出发，推断查询相关的用户状态 Zq，再据此生成个性化响应：

```
Zq = Φ_mem(H, q)， ŷq = Ψ(q, Zq)
```

其中 Φ_mem 即 QUMem 记忆框架，Ψ 为下游响应模型。整体框架包含三个核心模块，分两阶段（记忆构建阶段和查询推断阶段）。

### 2.2 动态片段构建（Dynamic Episode Construction）

- **目的**：替代固定边界（固定轮数/令牌数/会话），按语义连续性组织事件级对话片段。
- **实现方式**：系统维护一个开放候选片段，对每对相邻用户话语 xt-1 和 xt 调用轻量级连续性分类器 fθ：
  ```
  ct = fθ(xt−1, xt)， ct ∈ {0, 1}
  ```
  - ct = 1：继续当前片段，追加 xt 及对应助手回复；
  - ct = 0：终结当前片段，以 xt 初始化新片段。
- **关键细节**：
  - 分类器只接收相邻用户话语，不纳入中间的助手回复；
  - 分类器采用轻量级微调模型（基于 Qwen3.5-4B 微调），避免大规模生成模型的高延迟；
  - 历史结束时，将剩余开放片段一并终结构建。

### 2.3 类型化记忆分解（Typed Memory Decomposition）

- **目的**：避免将同一事件中的多条用户信息绑定存储，支持细粒度独立检索。
- **三类记忆**：
  1. **事实记忆（F）**：记录具体经历、行为、活动、状态或事件，不做倾向性推断；
  2. **偏好记忆（P）**：记录用户对特定对象或情境的选择、倾向、要求和约束，附有直接相关的理由；不假设永远有效，其时间位置可能反映持续性倾向或偏好演变的某个阶段；
  3. **可迁移见解记忆（I）**：从具体选择、反馈及其理由中抽象出的用户特有决策原则，可应用于新对象或新情境，但须扎根于具体的交互证据。
- **实现方式**：对每个片段 Ek，对同一 LLM 分解器 gφ 调用三次（每次对应一种记忆类型 d）：
  ```
  gφ(Ek, d) = {m_{d,k,j}}， d ∈ {F, P, I}
  ```
- **记忆表示**：每条原子记忆存储为：
  ```
  m_{d,k,j} = ⟨v_{d,k,j}, d, p_{d,k,j}, E_{d,k,j}⟩
  ```
  其中 v 为内容、d 为类型、E 为来源交互轮次集合（溯源），p 为最新来源轮次的时间位置（用于时间有效性判断），k 链接到源片段。
- **存储**：按类型分别存入事实、偏好、可迁移见解三个记忆库。

### 2.4 查询条件用户状态推断（Query-Conditioned User-State Inference）

该模块由三个顺序协作的 LLM 代理组成，逐步完成从任务目标到用户状态的转化：

1. **信息需求代理 A1**：分析当前查询 q 和任务上下文，确定需要从历史中核实的用户信息及其对状态推断的意义。它不指定具体检索查询或记忆库，将"需求识别"与"检索规划"分离。
2. **检索规划代理 A2**：将每条信息需求改写为若干自包含查询，并为每个查询选择目标记忆类型。形成检索计划：
   ```
   Pq = {(e_qj, D_j)}，∅ ≠ D_j ⊆ D
   ```
   按照计划从类型化记忆库检索并合并去重，得到候选记忆作为证据。
3. **用户状态推断代理 A3**：从候选中筛选任务相关信息，组织成查询条件化的用户状态：
   ```
   Zq = (Fq, Tq, Iq)
   ```
   - Fq：按时间排序的相关事实（描述经验/状态的演变发展）；
   - Tq：偏好演变轨迹，识别当前情境下适用的偏好；
   - Iq：历史抽象决策原则在当前任务中的适用方式。

最终将 Zq 与 q 一并交给下游响应模型 Ψ 生成个性化响应。

## 6. 主要结论与发现

1. **整体性能领先**：QUMem 在 PersonaMem 上全面超越所有基线。GPT-4o-mini 下总体准确率从 52.99% 提升至 61.02%；Gemini-3.5-flash 下从 63.29% 提升至 70.58%。
2. **收益来源明确**：最大优势出现在追踪完整偏好演变、偏好一致推荐、跨情境泛化等需要跨时间联合解释证据的任务上；而"识别最新偏好"提升较小，说明主要增益来自对分布式证据的联合解释，而非单纯检索最近的偏好表述。
3. **上下文长度影响**：随着交互历史增长（32K→128K→1M），QUMem 相对最强基线的优势不断扩大，表明结构化记忆与推断流程在证据愈发分散时更有价值。
4. **KnowU-Bench 验证泛化性**：QUMem 在所有指标上最佳，总体成功率比最强基线提升 4.6 个百分点，验证了查询条件用户状态推断对个性化任务执行同样有效。
5. **组件互补性**：三个组件均贡献积极效果，其中查询时用户状态重建影响最大。
6. **效率优势显著**：相比基线，QUMem 在构建频率、LLM 调用数和 token 消耗上均为最低，原因是"低构建频率 + 每次构建固定 3 次 LLM 调用"的设计。

## 7. 优点

- **方法设计层面**：
  - 通过轻量级分类器实现语义连续性切分，兼顾事件上下文完整性与推理效率；
  - 三类记忆分解（事实/偏好/可迁移见解）贴合用户信息的功能差异，支持按需独立检索，避免了无关信息绑定问题；
  - 三代理顺序协同机制清晰分离了"需求识别—检索规划—证据解释"，克服了单次 top-k 检索无法联合解释分布式证据的根本缺陷；
  - 保留时间位置和来源链接，使时间有效性判断和溯源成为可能；
  - 连续的语义边界划分器替代生成式模型，大幅降低了记忆构建成本。
- **实验验证层面**：
  - 在多个上下文规模、多个基座模型、两个不同性质基准上验证，提高了结论的可信度；
  - 效率分析揭示了一个关键洞察：构建频率低不等于生成开销低（Mem0 反例），具有方法论参考价值。

## 8. 不足与局限

- **实验覆盖不足**：
  - 消融和超参实验仅使用单一基座模型（GPT-4o-mini）和单一基准（PersonaMem），未在 KnowU-Bench 或其他数据集上验证组件贡献；
  - 缺乏多轮重复实验的方差与显著性检验。
- **绝对的性能局限**：
  - 即使在 QUMem 下，1M 上下文场景的绝对准确率仍明显低于 32K 场景，说明"长历史下性能保持"仍未完全解决；
  - "提出新想法"在所有方法中都是最弱类别，表明从偏好推断到生成"既新颖又符合偏好"的响应之间仍存在显著差距；
  - KnowU-Bench 的绝对成功率较低（总体 17.4%），尤其在困难任务上（11.6%），提示端到端可靠执行仍是重大挑战。
- **泛化性风险**：
  - 语义连续性分类器基于 Qwen3.5-4B 在 LoCoMo 数据集上微调，该分类器在不同语言、领域和交互形态上的迁移能力未经验证；
  - 方法依赖三个 LLM 代理的顺序调用，虽然构建阶段效率高，但查询阶段的多代理推理可能引入额外延迟；
  - 未讨论多用户、多代理共享记忆或隐私约束下方法的适用性。
