## 摘要
随着智能体任务日益复杂，LLM智能体越来越依赖经验记忆以跨任务重用程序性知识。有效的记忆设计必须同时解决存储什么、记忆如何结构化与检索，以及记忆如何进化等问题。现有系统仅部分解决这些问题：它们将轨迹、见解或工作流存储为孤立条目，丢弃了子任务与可复用技能之间的组合关系；通过忽略关系信号的扁平嵌入相似性进行检索；并且在维护记忆时未利用其关系结构。我们提出HyperSkill，一种基于超图的记忆框架，共同改进上述三个方面。HyperSkill将记忆表示为具有两种节点类型（子任务步骤和可复用技能）的超图，其中每条超边连接来自单条轨迹的子任务与技能。双路径检索同时查询子任务层和轨迹层，根据检索到的轨迹中的共现对技能进行排序。周期性结构感知维护通过质量加权传播剪枝低效用节点并合并冗余技能。在xBench、GAIA和WebWalkerQA上，使用GPT-4o与Qwen3-30B-A3B，HyperSkill优于十种记忆基线，在GAIA上获得高达+11.51的提升，在WebWalkerQA上获得高达+11.18的提升。

## Abstract
As agentic tasks grow in complexity, LLM agents increasingly rely on experiential memory to reuse procedural knowledge across tasks. Effective memory design must jointly address what to store, how memory is structured and retrieved, and how memory evolves. Existing systems tackle each only partially: they store trajectories, insights, or workflows as isolated entries, discarding compositional relationships among subtasks and reusable skills; retrieve by flat embedding similarity that ignores relational signals; and maintain memory without leveraging its relational structure. We propose HyperSkill, a hypergraph-based memory framework that jointly improves all three. HyperSkill represents memory as a hypergraph with two node types, subtask steps and reusable skills, where each hyperedge links the subtasks and skills from a single trajectory. Dual-path retrieval queries both subtask and trajectory levels, ranking skills by co-occurrence across retrieved trajectories. Periodic structure-informed maintenance prunes low-utility nodes and merges redundant skills via quality-weighted propagation. Across xBench, GAIA, and WebWalkerQA with GPT-4o and Qwen3-30B-A3B, HyperSkill outperforms ten memory baselines, yielding gains of up to +11.51 on GAIA and +11.18 on WebWalkerQA.

### 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：随着LLM智能体在长时程网页导航、交互式计算机使用、多步科学推理等复杂任务中的广泛应用，单次交互往往无法可靠完成任务。智能体记忆系统通过存储和检索超越单一上下文窗口的信息来解决这一问题。
- **核心问题**：**经验记忆**（experiential memory）——即将智能体自身过去的轨迹（trajectories）提炼为可复用知识以支持自我进化——至关重要，但现有记忆系统在三个基本维度上均存在不足：
  - **存储什么（What to store）**：现有系统要么存储原始轨迹（含噪声），要么提炼为孤立的工作流/技能条目，未保留子任务与技能之间的组合关系。
  - **如何结构化和检索（How is structured and retrieved）**：多数方法采用扁平向量库或简单二元图，仅依赖嵌入相似度检索，无法表达"技能与子任务模式之间重复成功共现"这类n元关系。
  - **记忆如何演化（How memory evolves）**：多数系统无条件累积知识而无精炼机制，少数轻量级操作（剪枝、去重）未利用图拓扑结构信号。
- **核心观点**：一条轨迹不是单一的知识单元，而是子任务、技能与结果之间的n元关联（n-ary association），扁平列表和成对边（pairwise edges）只能有损地表示这种结构。超图（hypergraph）天然能同时连接两个以上节点，适合保存这种组合结构。
- **整体含义**：论文提出超图结构化记忆框架，统一解决上述三个维度的缺陷，为LLM智能体的经验记忆设计提供了新范式。

### 2. 方法论：HYPER SKILL 框架

#### 2.1 总体架构

- 将经验记忆组织为超图 G = (V, E)，其中：
  - **节点 V = Vu ∪ Vs**，分为两类：
    - **子任务节点 Vu**：每个节点捕获任务分解中的一个步骤，内容含步骤描述和适用前置条件。
    - **技能节点 Vs**：通过结果条件提示（outcome-conditioned prompting）从轨迹中提取的可复用知识。成功轨迹产出正向策略，失败轨迹产出错误模式（error patterns）。
  - **超边 E**：每条超边对应一条轨迹 τj，将轨迹中提取的子任务节点集合和技能节点集合连接起来，同时记录任务描述、提炼的经验教训和效用分数。
- 每个节点表示为三元组：vi ≜ (ci, ℓi, γi)，其中 ci 为自然语言内容，ℓi 为类型标签，γi ∈ [0,1] 为动态效用分数。

#### 2.2 效用分数计算（公式3）

γ(·) = β · σ(·)/ν(·) + (1−β) · (1 − (T̄(·) − T_min)/(T_max − T_min))

- σ(·) 为成功次数，ν(·) 为总检索次数，T̄(·) 为运行平均步数，β = 0.7 平衡成功率与步数效率。

#### 2.3 双路径超边检索（Dual-Path Hyperedge Retrieval）

- **子任务路径（Subtask Path）**：
  - 对新任务dq，先用LLM生成子任务分解 P0 = {d1, ..., dm}；
  - 用固定长度编码器 ϕ 编码整个分解并检索 top-ku 相关子任务节点（公式4）；
  - 匹配到的子任务节点通过其关联超边扩展到候选轨迹集合 E_sub。
- **轨迹路径（Trajectory Path）**：
  - 直接将完整任务描述编码为 h_dq，与超边表示 he = ϕ(dq ∥ ℓe) 计算相似度，检索 top-ke 条超边（公式5）；
  - 超边表示拼接了原始任务描述和提炼的经验教训，可同时捕获表面措辞和潜在可迁移模式。
- **融合**：E* = E_sub ∪ E_traj，两路径互补——子任务路径捕获共享过程结构，轨迹路径捕获高层语义相似性。

#### 2.4 技能检索：共现排序（Co-occurrence Ranking）

- 从融合后的轨迹集合 E* 中，候选技能池为其并集（公式7）；
- 对每个候选技能统计其在检索超边中的共现次数 κ(v)（公式8）；
- 按共现次数降序选取 top-ks 技能，平局按与任务的嵌入相似度打破（公式9）。
- **核心洞察**：语义相似性只衡量技能描述是否像当前任务，不能衡量技能是否在相关轨迹中被实际应用过；共现频率是语义相似度无法提供的结构信号。

#### 2.5 执行与记忆更新

- 检索上下文（Sq, Lq）一次性组装并全程固定，智能体在每步行动时结合当前观察、技能、经验教训和最近交互滑动窗口。
- 任务完成后，通过结果条件LLM调用提取新技能和经验教训；子任务节点直接取自已分解 P0；新技能与现有技能计算嵌入相似度，超过阈值 δ_dedup 则合并而非重复插入。

#### 2.6 记忆演化：周期性维护（每 ⌈0.1×N⌉ 个任务触发）

- **质量驱动剪枝（公式11）**：删除检索次数足够（ν(v) ≥ N_min）但效用分数低于阈值（γ(v) < τ_prune）的节点，并从所有超边成员中移除。
- **结构感知合并（公式12-14）**：
  - 构建质量加权的技能共现矩阵 W（公式12），嵌入超边大小归一化和节点效用最小值加权；
  - 通过L步对称传播获得结构嵌入 Ẑ（公式13），同时反映结构共现和技能质量；
  - 结构嵌入相似度超过阈值 δ_merge 的技能对，由LLM推理合并为更高阶技能，并将超边成员关系重新指派。

### 6. 主要结论与发现

- **① 一致且显著的收益**：HYPER SKILL 在几乎所有基准×骨干组合上取得最高成功率。在 GPT-4o 下，相对第二好方法：xBench +3.00、GAIA +2.30、WebWalkerQA +0.59；相对 No Memory：GAIA 最高 +11.51、WebWalkerQA +11.18。
- **② 高效率——无膨胀执行成本**：在 GPT-4o / xBench 上，以最高成功率同时匹配最少步数（5.27），而 ReasoningBank、Voyager 等需 8+ 步、12+ 次工具调用却成功率更低。
- **③ 无原则的累积会伤害性能**：Cheatsheet 在 Qwen3-30B-A3B / xBench 上比 No Memory 低 -9.00，Voyager 在 GPT-4o / xBench 上低 -7.00，说明缺乏维护的记忆引入噪声反而有害。
- **④ 检索预算要紧凑**：k=2 最优，增大 k 会稀释最相关技能信号；
- **⑤ 轻量维护即可**：ρ=0.1 最优，ρ=0（不剪枝）积累低效用条目损害检索质量，ρ=0.4（过度剪枝）移除仍有效技能；
- **⑥ 双路径互补**：去掉子任务检索在 GAIA 下降至 32.73，去掉轨迹检索在 WebWalkerQA 下降至 43.53（完整模型 50.59），去掉超图结构则全面最差；
- **⑦ 技能共享是关键**：可视化显示技能节点跨超边共享（如 Cross-Source Validation、Targeted Database Search 在多条轨迹中出现），失败轨迹的"错误模式"技能独立聚集，可在类似子任务模式重现时提供定向警告；
- **⑧ 自主进化能力**：唯一呈现持续上升累计成功率轨迹的方法；在任务多样性高的基准（GAIA、WebWalkerQA）上自进化效应更明显；
- **⑨ 对噪声结果信号鲁棒**：self-judge 保留 GT-judge 性能的 87.7%-96.8%，共现排序稀释了偶尔错误标签的影响。

### 7. 优点（方法/实验设计的亮点）

- **结构创新**：首次将超图（而非成对图）用于经验记忆系统，天然保存轨迹中"子任务-技能-结果"的n元组合上下文；
- **三方面统一解决**：同时改进存储内容、检索方式和演化机制，而非仅修补单一环节；
- **共现排序新颖且有效**：利用技能节点跨轨迹复用这一特性，以共现频率为排序依据提供了语义相似度之外的结构信号；
- **结构感知维护**：质量加权共现 + 超图传播的合并策略同时考虑节点质量和拓扑结构，优于逐节点独立操作；
- **双路径检索互补**：子任务级匹配捕获表面不同但程序结构相似的轨迹，任务级匹配捕获语义相似的轨迹，两者融合更全面；
- **高效率表现**：不依赖昂贵的LLM微调或额外复杂模块，在中等token成本下达到最佳性能；
- **良好的鲁棒性**：在无真实标签（self-judge）情况下仍保持大部分性能，利于实际部署；
- **实验充分**：覆盖多维度分析（成本、延迟、记忆增长、敏感性、鲁棒性、可视化、案例研究），评估体系完整；
- **工程细节完善**：如技能去重、效用分数设计、滑动窗口历史、任务分解提示词等均有详尽描述，可复现性强。

### 8. 不足与局限

- **额外推理开销**：任务分解、技能提取、合并决策均需额外LLM调用，引入额外推理成本和延迟（延迟分析显示HYPER SKILL在部分设置中比No Memory慢约1.6-2倍）；
- **低数据场景局限**：超图检索和演化的有效性依赖足够多的累积轨迹，在记忆图稀疏的极低数据环境中收益可能有限；
- **评估范围有限**：仅覆盖网页导航和多步推理基准，未涉及交互式计算机操作、科学发现、复杂软件工程等场景；所有基准为英文为主，未测试多语言场景；
- **统计显著性缺失**：未报告多次试验的标准差或置信区间；
- **LLM调用引入的不确定性**：任务分解质量、技能提取质量、合并推理质量均依赖底层LLM能力，框架整体性能可能受制于所用LLM；
- **人为设定参数较多**：β、τ_prune、N_min、δ_dedup、δ_merge、k、ρ等多个超参数需调优，虽提供敏感性分析但最优值可能随任务分布变化；
- **无结构性基线**：与成对图基线的对比尚不充分，表4中列出的PlugMem、G-Memory等使用的图结构较简单，未与更精细的成对图记忆方法深度比较；
- **潜在偏差风险**：作者自述记忆累积可能强化早期轨迹中存在的偏差，虽在伦理声明中提及，但未提供检测或缓解偏差的机制；
- **并行或团体场景未覆盖**：如表4所示，G-Memory支持多智能体系统（MAS），HYPER SKILL当前设计未讨论多智能体共享/协作记忆的场景；
- **结果受限于固定任务顺序**：虽然使用固定随机种子保证公平，但未分析任务顺序对记忆演化的影响。
