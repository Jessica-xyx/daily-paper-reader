## 摘要
长期记忆使个性化对话代理能够在会话间保留用户信息。然而，现有的记忆架构主要优化效用，而忽视了不必要地存储和重用个人身份信息（PII）等私有属性的风险。解决个性化记忆中的隐私风险具有挑战性，因为简单地移除敏感值可能会损害系统效用。因此，记忆代理的隐私保护应管理敏感值的完整生命周期，而不仅仅是净化个别记录。为解决这一差距，我们引入了隐私映射净化记忆（Sanitized Privacy-Mapped Memory, SP-Mem），一种隐私感知的记忆架构，将记忆效用与精确私有值暴露解耦。SP-Mem提供完整的生命周期隐私设计，从原始用户输入中识别并分离敏感信息，将净化后的内容和精确私有值存储于隔离结构中，并根据任务要求和用户同意选择性检索私有值。我们进一步引入了一个隐私感知记忆基准，联合评估响应质量、隐私行为和推理成本。跨多个基于LLM的智能体的广泛实验表明，SP-Mem在实现更强个性化的同时减少不必要的隐私暴露。代码和数据可在https://github.com/Jensassss/SP-Mem获取。

## Abstract
Long-term memory enables personalized conversational agents to retain user information across sessions. However, existing memory architectures primarily optimize for utility while neglecting the risks of unnecessarily storing and reusing private attributes such as personally identifiable information (PII). Addressing privacy risks in personalized memory is challenging because simply removing sensitive values can undermine system utility. Therefore, privacy protection for memory agents should govern the full life cycle of sensitive values rather than only sanitizing individual records. To address this gap, we introduce Sanitized Privacy-Mapped Memory (SP-Mem), a privacy-aware memory architecture that decouples memory utility from exact private-value exposure. SP-Mem provides a full life-cycle privacy design that identifies and separates sensitive information from raw user inputs, stores sanitized content and exact private values in isolated structures, and selectively retrieves private values based on task requirements and user consent. We further introduce a privacy-aware memory benchmark that jointly evaluates response quality, privacy behavior, and inference cost. Extensive experiments across multiple LLM-based agents show that SP-Mem achieves stronger personalization while reducing unnecessary privacy exposure. Code and data are available at https://github.com/Jensassss/SP-Mem.

**关键洞见**：隐私保护不能只靠“净化单条提示”，而应覆盖敏感值的**全生命周期**，即管控记忆的**写入、存储、检索和使用**四个环节。论文据此提出 SP-Mem（Sanitized Privacy-Mapped Memory），将“记忆效用”与“精确私密值暴露”解耦，在保持个性化能力的同时系统性约束隐私风险。

> 整体含义：从“最大化记住”转向“受控地记住”——确定什么是可搜索记忆、什么是受保护私密存储，以及何时在任务必要与用户授权下恢复精确私密值。


## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想
SP-Mem 采用**三层解耦架构**，将“可搜索的净化记忆”与“受保护的精确私密值”分离，并通过任务必要性与用户授权来桥接二者。其核心设计围绕三个组件展开：
1. **隐私感知记忆写入（Privacy-Aware Memory Writing）**：识别并净化敏感信息；
2. **分区存储（Partitioned Storage with Privacy Mapping）**：隔离存放净化内容与精确私密值，并维护映射关系；
3. **查询时隐私推理与授权检索（Query-Time Privacy Reasoning & Authorized Retrieval）**：按需、按授权恢复私密值。

### 2.2 关键技术细节

**（1）隐私感知记忆写入**
- 将原始用户输入转换为两种互补表示：
  - **自然语言事实**（供向量分支使用）：`f = (y_f, A_f)`，其中 `y_f` 是事实文本，`A_f` 是检测到的隐私标注集合 `{(v_j, τ_j)}`；
  - **关系三元组**（供图分支使用）：`r = (s_r, ρ_r, d_r)`，三元组若 `ρ_r` 对应隐私敏感属性，目的值 `d_r` 视为隐私。
- 隐私检测采用基于规则的类型化提取策略，覆盖 8 个大类、37 种细粒度隐私类型。

**（2）隐私净化策略（四类）**
- **名称/别名替换**：适用于姓名、性别、邮箱等；
- **保留后缀的掩码**：适用于电话号码、银行账户、信用卡、税号等结构化标识符（如 `id_****7561`）；
- **数值分桶**：将年龄、收入、信用分等数值映射为语义区间（如 `age_adult`、`upper_middle_income`）；
- **LLM 泛化**：将开放式内容重写为更宽泛的描述（如 `nurse → healthcare_professional`）。

> 每种细粒度隐私类型 τ 通过类型到策略映射 `g(τ)` 分配到对应净化策略，即 `˜v_j = SANITIZE(v_j, g(τ_j))`。

**（3）分区存储**
- **可搜索记忆层**：存放非隐私事实/三元组 + 净化后的记忆（向量库 + 图数据库）；
- **隐私映射层**：记录净化条目与精确私密值之间的映射键；
- **受保护私密存储**：仅存放精确私密值，不参与常规检索。

**（4）查询时隐私推理与授权检索**
- 查询分析器将用户查询转换为任务需求计划，判定是否涉及私密信息；
- 若涉及私密信息，则请求用户授权：
  - **有授权**：恢复任务所需的精确值；
  - **无授权**：退化为仅使用净化记忆；
- 若无需私密信息，则仅从净化可搜索层检索。

## 6. 论文的主要结论与发现

1. **隐私识别准确率高且稳定**：SP-Mem 在隐私实体识别上达到 Accuracy 0.996、Recall 0.992、Precision 0.965，四领域表现一致，为后续隐私保护提供坚实基础。

2. **隐私感知净化不损害响应质量**：
   - 在允许访问私密值的任务中，SP-Mem 对 MemOS / Mem0 / Zep 的 P-TC 与 P-PQ 胜平率大多超过 85%；
   - 在**私密值不可用**的任务（denied 类）中优势更明显：对全部基线的胜平率超过 86%，说明净化记忆仍能提供有效的任务与个性化信号。

3. **隐私行为得到有效控制**：
   - PAR 精确率在所有后端上均达到 1.00，无多余权限请求；召回率 0.84–0.92，能识别大多数需要隐私的任务；
   - UPU 暴露率极低：Preference-only 为 0.33%，Privacy-only-denied 为 1.12%，Mixed-denied 为 1.21%，远低于 Full-context（Preference-only 达 16.00%）。

4. **推理成本可控**：SP-Mem 仅使用 Full-context 约 26–31% 的 Token，虽略高于其他记忆基线，但换来了更强的响应质量与隐私控制，对长期代理是可接受的权衡。

5. **混合向量–图记忆优于单一分支**：向量+图组合对任意单分支消融的胜平率均超过 80%，表明语义检索与结构化关系检索确实互补。

> **总结论**：隐私保护应贯穿记忆全生命周期，SP-Mem 通过“净化写入—隔离存储—授权恢复”的设计，在不牺牲个性化的前提下显著降低了不必要隐私暴露。


## 7. 优点

   - 位置交换与一致性判定降低评判偏差；
   - 同时关注效用（P-TC/P-PQ）、隐私（PAR/UPU）和成本（Token），三维度评估较为完整。

5. **结果一致性好**：在四个领域、四个骨干后端、五种任务上的结果方向高度一致，结论可信度较高。

6. **消融设计清晰**：通过 graph-only 和 vector-only 两种消融分别验证两种记忆表示的独特贡献，支撑了混合架构的设计选择。


## 8. 不足与局限

1. **合成数据限制**：所有用户画像、对话和查询均为合成数据。真实用户交互往往更模糊、更不完整、随时间演化，且私密信息的表达方式更多样，SP-Mem 在真实场景的泛化性能尚未验证。

2. **隐私风险覆盖有限**：
   - UPU 仅检测精确值暴露，不覆盖以下风险：泛化属性仍可能助长重识别、多轮交互可被用于推断攻击、对抗者可尝试反推净化值；
   - 缺乏强威胁模型下的评估（如水疗攻击、成员推断、记忆提取等）。

3. **隐私实体识别依赖规则策略**：虽然准确率很高，但规则方法在开放性表达（隐喻、间接提及、跨句子隐式关联）上的鲁棒性未得到充分验证。

4. **资源与成本信息不完整**：未报告 GPU 数量、训练/推理总耗时、API 调用成本，影响可复现性与大规模部署成本预估。

5. **用户偏好粒度单一**：未考虑用户对不同隐私类型可能有不同的敏感级别（如医疗信息 vs. 联系方式），统一处理可能不够精细。论文也承认此局限。

6. **模型与评判偏差**：全部结果基于 GPT-4.1 的 LLM 评判，即使有位置交换，也可能存在系统性偏好（如偏爱某种写作风格、自我偏好偏差等）。记忆构建模型单用 GPT-5.2 也可能掩盖不同构建模型的差异。

7. **授权模型简化**：授权以二元“允许/拒绝”为主，未建模更复杂的授权逻辑（如部分授权、条件授权、用途限制等）。
