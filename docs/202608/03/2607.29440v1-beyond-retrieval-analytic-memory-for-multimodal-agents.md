## 摘要
长期多模态记忆不仅需要支持检索相关信息，还需要对跨交互积累的观测进行计算。现有系统主要强调检索记忆，通过摘要和索引组织交互历史，以多种粒度返回查询相关信息，从高级抽象到底层记录。在本文中，我们将分析记忆表述为一种补充抽象，它将重复出现的多模态观测组织成可查询的结构，支持过滤、聚合、排序和时间比较。我们提出了AdaMM，一个联合支持检索和分析记忆的框架。AdaMM不依赖应用定义的模式，而是从对话、图像和上下文元数据中提取带有来源链接的属性-值观测，发现重复出现的字段结构，并将其物化以供分析访问。在推理时，一个具有记忆意识的规划器将查询分解为检索和分析操作，并将每个操作路由到适当的工具。在两个长期多模态记忆基准测试MemEye和MemGallery上的实验表明，AdaMM分别将性能提高了11.3%和7.3%。

## Abstract
Long-term multimodal memory must support not only retrieving relevant information but also computing over observations accumulated across interactions. Existing systems largely emphasize \emph{retrieval memory}, organizing interaction histories through summaries and indexes to return query-relevant information at multiple granularities, from high-level abstractions to underlying records. In this paper, we formulate \emph{analytic memory} as a complementary abstraction that organizes recurring multimodal observations into queryable structures supporting filtering, aggregation, ranking, and temporal comparison. We present AdaMM, a framework that jointly supports retrieval and analytic memory. Rather than relying on application-defined schemas, AdaMM extracts provenance-linked attribute-value observations from dialogue, images, and contextual metadata, discovers recurring field structures, and materializes them for analytical access. At inference time, a memory-aware planner decomposes queries into retrieval and analytic operations and routes each operation to the appropriate tools. Experiments on two long-term multimodal memory benchmarks, MemEye and MemGallery, show that AdaMM improves performance by up to 11.3\% and 7.3\%, respectively.

## 1. 论文的核心问题与整体含义

**研究动机与背景**

- 大语言模型（LLM）智能体与用户的交互时间跨度不断延长，积累了大量多模态历史信息（对话、截图、图像、文档、上下文观察等），这些信息远超骨干模型的有限上下文窗口，因此多模态记忆系统成为支撑长期推理的关键组件。
- 现有主流记忆系统大多遵循"先检索后回答"（retrieve-then-answer）范式，即从交互历史中选出与查询相关的有限记忆片段作为上下文提供给 LLM，这类方法被称为**检索记忆（retrieval memory）**。
- 然而，长期交互历史本质上是一个不断追加的日志（append-only log），其中积累了大量重复出现的观测。诸如"过去一个月的平均睡眠时长是多少？"这类问题需要对完整的记录进行聚合、过滤、排序和时间选择等分析操作，而基于相关性排序的检索机制在处理这类问题时存在**覆盖度-上下文预算的两难困境**：较小的检索集合可能遗漏关键观测，较大的检索集合则消耗有限的上下文窗口并引入冗余或干扰信息。
- 论文将这种"基于相关性的检索"与"分析性操作"之间的能力差距称为**检索-分析不匹配（retrieval-analysis mismatch）**。

**核心主张**

- 长期多模态记忆系统应当耦合两个互补的子系统：**检索记忆**负责识别和提供相关历史记录作为上下文；**分析记忆（analytic memory）**则主动将交互历史组织为可复用的、可查询的结构化形式，使系统能够对累积的观测执行确定性分析操作（过滤、聚合、排序、时间比较等），而不是每次由 LLM 从原始检索到的记录中反复重建所需组织。

## 2. 论文提出的方法论

### 2.1 总体框架：AdaMM

AdaMM（Adaptive Multi-view Memory）包含两条并行的记忆构建通路和一个查询时规划模块：

- **分析记忆（Analytic Memory）**：从多模态交互中提取带来源的属性-值对，通过数据驱动的模式归纳发现重复出现的字段结构，物化为可查询的关系表。
- **检索记忆（Retrieval Memory）**：按"主题→片段→事件"（topic → episode → event）的三层层次结构组织开放式的语义事件，保留多模态视觉细节和来源信息。
- **自适应查询处理（Adaptive Query Processing）**：一个记忆感知的规划器将用户查询分解为检索和分析操作序列，并逐步实例化工具调用。

### 2.2 分析记忆构建

分析记忆构建分为三个阶段：

**(a) 属性提取（Attribute Extraction）**

- 对每条交互轮次 $R_t = (d_{t}, V_{t}, \tau_t)$，使用基于 LLM 的提取器联合检查对话和视觉内容，识别所有有据可依的属性-值对应关系：
  $$O_t = \text{Extractor}(R_t) = \{(a_t^\ell, x_t^\ell, p_t^\ell)\}_{\ell=1}^{m_t}$$
  其中 $a_t^\ell$ 是属性名，$x_t^\ell$ 是忠于来源的值，$p_t^\ell$ 是指向支撑对话片段或图像的来源链接（provenance）。
- 不在提取阶段预设任何模式，仅保留每轮中显式的分析性观测。

**(b) 模式归纳（Schema Induction）**

- **候选模式挖掘**：基于 Apriori 频繁项集挖掘框架，用支持度（support）衡量属性组合的重复出现程度：$\text{supp}_t(C) = \sum_{s=1}^{t} \mathbb{I}[C \subseteq A_s]$，当 $\text{supp}_t(C) \geq \theta_s$ 时保留为候选模式。
- **模式发现（Schema Discovery）**：对每个频繁候选 $C$，使用 **all-confidence** 度量其内部共现一致性：$\text{all-conf}_t(C) = \frac{\text{supp}_t(C)}{\max_{a \in C} \text{supp}_t(\{a\})}$，当 $\text{all-conf}_t(C) \geq \theta_a$ 时将其接纳为新模式，并使用包含最大化（inclusion-maximal）策略避免同时接纳候选模式及其合格子集。
- **模式演化（Schema Evolution）**：对已有模式 $A$，若候选 $C \supseteq A$，用**扩展置信度**决定是否将新增属性 $\Delta = C \setminus A$ 并入模式：$\text{ext-conf}_t(C|A) = \frac{\text{supp}_t(C)}{\text{supp}_t(A)}$，当 $\text{ext-conf}_t(C|A) \geq \theta_e$ 时更新模式。

**(c) 记忆物化（Memory Materialization）**

- 每个归纳出的模式 $A$ 被物化为一张关系表 $T_A$：模式属性作为列，匹配的交互作为行；每行记录交互轮次的属性值，并附加 `order` 和 `time` 两个辅助列标注来源交互的位置和发生时间，缺失值留空。
- LLM 根据属性的采样值生成表的元数据（表名、描述、列类型）。
- 模式演化时，新属性作为新列追加，并依据原始观测重新物化行。

### 2.3 检索记忆构建

- 按三层层次组织：**事件（Event）** 保存单次交互的细粒度证据；**片段（Episode）** 聚合时间相邻且语义连贯的事件；**主题（Topic）** 将相关片段聚为更广的语义上下文。
- 每个层级维护简洁描述、多模态表示、时间信息和来源信息，使规划器可以先定位相关主题/片段，再定位支持事件。

### 2.4 自适应查询处理

- **记忆访问工具**：将分析记忆和检索记忆的原生能力抽象为操作特定的工具，每个工具定义为 $\xi_i = (d_i, \Theta_i, \Omega_i)$，其中 $d_i$ 是功能描述，$\Theta_i$ 是类型化参数，$\Omega_i$ 是返回模式。分析记忆提供 LOOKUP、FILTER、COMPUTE、RANK 四个工具；检索记忆提供 SEMANTIC MATCH、EVENT LOCATE 两个工具。
- **规划上下文构建**：将每个分析表 $T$ 和检索片段 $P$ 的元数据作为规划候选（表元数据包含名称、描述、列、采样值；片段直接用描述），用混合打分函数 $h_\lambda(q, \mu) = \lambda \cos(E(q), E(\mu)) + (1-\lambda)\text{TokSim}(q, \mu)$ 对元数据排序，保留 Top-相关条目并附上可用工具描述，形成有效规划上下文。
- **渐进式工具执行规划**：先由 LLM 规划器生成高层抽象计划（信息目标+指定工具类型），然后在执行时逐步实例化各工具调用的参数，后一步的工具参数可以依赖前一步的中间结果（例如 EVENT LOCATE 返回的时间戳可作为后续 COMPUTE 的时间约束）。
- **答案生成**：最终答案模型基于查询和实例化计划及工具输出构成的证据上下文生成回答。

## 6. 论文的主要结论与发现

1. **AdaMM 在两个基准上一致优于所有基线**：
   - 使用 GPT-4.1-nano 时，在 MemEye 上超过最强基线 MCQ 7.3%、开放题 LLM-Judge 5.8%；在 MemGallery 上 F1、BLEU-1、LLM-Judge 分别提高 4.2%、4.3%、7.0%。
   - 使用 GPT-5.4-mini 时，在 MemEye 上提高 3.2%（EM）和 11.3%（LLM-Judge）；在 MemGallery 上分别提高 2.6%、2.2%、5.2%。
2. **分析记忆的增益集中在需要精确操作的场景**：MemEye 中 Card Playlog（18.8%）和 Personal Health（16.7%）提升最大，两者均要求对重复记录执行过滤、比较值或跟踪变化等确定性操作。
3. **检索记忆对视觉语义回忆类任务仍不可替代**：Brand 任务在去除检索记忆后下降 9.9%，说明分析记忆与检索记忆是互补关系而非替代关系。
4. **记忆感知规划的两个机制均有贡献**：去除规划上下文导致整体下降 3.3%；去除渐进式执行在 Health 任务下降 4.2%——当后一步工具依赖前一步结果时，渐进式实例化比一次性规划更可靠。
5. **方法泛化性**：在不同骨干容量、不同基准、不同答案格式下均取得一致改进，说明"检索+分析"双记忆范式具有较好的通用性。
