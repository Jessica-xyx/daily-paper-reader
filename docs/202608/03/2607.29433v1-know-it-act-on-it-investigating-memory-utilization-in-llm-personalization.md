## 摘要
随着大型语言模型（LLM）智能体演变为个性化伴侣，记忆已成为核心能力。然而，LLM面临知识利用问题：即使相关用户偏好完全在上下文中，它们也可能无法据此行动。当智能体在先前共享的用户偏好应该重要的情境中未能定制响应时，不清楚是模型未能记住该信息，还是记住了但未能使用它。为了隔离这种故障，我们引入了一种解耦评估范式，对同一用户偏好进行配对的Know和Act测试。我们在16个系统和五种记忆架构中进行了大规模实验，评估了嵌入在三种表达强度级别的1000个偏好。我们的结果显示Know和Act结果之间存在巨大差距：智能体通常通过用户偏好的回忆测试，但未能在配对的行为场景中反映该偏好。虽然记忆架构缩小了这一差距，但在健康和治疗相关的偏好上，利用仍然特别薄弱，而这些偏好上的失败行动具有最大的现实风险。

## Abstract
As large language model (LLM) agents evolve into personalized companions, memory has emerged as a core capability. However, LLMs face a knowledge utilization problem: they may fail to act on relevant user preferences even when they are fully present in context. When an agent fails to tailor its response in a context where previously shared user preferences should matter, it is unclear whether the model failed to remember that information or remembered it but failed to use it. To isolate this breakdown, we introduce a decoupled evaluation paradigm that administers paired Know and Act tests to the same user preference. We conduct large-scale experiments across 16 systems and five memory architectures, evaluating 1,000 preferences embedded at three levels of expression strength. Our results show a large gap between Know and Act outcomes: agents often pass the recall test for a user preference but fail to reflect that same preference in the paired behavioral scenario. While memory architectures reduce this gap, utilization remains especially weak for health and therapy-related preferences, where failures to act carry the greatest real-world stakes.

### 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体正从无状态工具演变为具备长期记忆的个性化伴侣，记忆（Memory）被视为核心能力。工业界与学术界已开发出多种记忆架构（如 ChatGPT 记忆、Claude 记忆、Mem0、Letta/MemGPT、Zep/Graphiti、HippoRAG 等）。
- **核心问题**：LLM 存在"知识利用问题"——即使相关用户偏好已完整出现在上下文（甚至被记忆模块正确存储）中，模型仍可能在生成响应时忽略该偏好。例如，用户此前在邮件润色请求中透露了花生过敏，但次日系统仍向其推荐含花生碎的泰式炒河粉。
- **关键痛点**：当个性化失败发生时，无法判断模型是**没记住**还是**记住了但没用**。现有研究要么只测知识回忆、要么只测行为响应，**从未对同一条用户偏好同时测试这两种能力**，因此无法区分失败根源。
- **整体含义**：个性化成功的真正标准不应是"能否回忆起用户偏好"，而是"能否将已记住的偏好转化为恰当的行为响应"。本文系统性地量化了这一"知道—行动"差距，为个性化记忆评估提供了新范式。

### 2. 方法论

#### 核心思想
- 提出**解耦评估范式（Decoupled Evaluation Paradigm）**，对**同一条用户偏好**分别施加两个独立测试：
  - **Know 测试**：直接询问模型是否记得该偏好（第一人称提问，如"我有季节性过敏吗？"），考查纯记忆/检索能力。
  - **Act 测试**：在**不提及该偏好**的自然场景中，考察模型是否将该偏好体现在响应行为中（如"请为五月春游推荐地点和打包清单"），通过对比零记忆基线响应来判断偏好是否真正影响了行为。

#### 关键指标
- **Know Accuracy**：Know 测试通过率。
- **Act Accuracy**：Act 测试通过率。
- **利用率（Utilization Rate）**＝ Know 通过且 Act 通过的偏好数 ÷ Know 通过的总偏好数。该指标聚焦"记住的人中真正用到的比例"，是高等级别、行为导向的核心度量。

#### 数据构造技术要点
- **Persona 选择**：从 PersonaMem-v2 的 999 个 persona 中，经国籍非空、偏好数 >70、纯英文三步过滤，再按 11 个文化区域分层抽样出 50 个 persona。
- **偏好采样**：每人 20 条目标偏好，按固定配额（刻板 5 / 反刻板 5 / 中性 4 / 健康医疗 4 / 治疗情绪 2）抽样，并保证每条偏好只对应一个会话片段（single-snippet 约束），同时保留约 50–70 条非目标片段作为检索噪声。
- **三级表达强度梯度**（扩展自 Rich 1979 的显式/隐式区分）：
  - **Explicit（显式）**：用户直接以偏好为核心主题陈述。
  - **Incidental（附带）**：偏好嵌入任务导向的对话中，从不直接说出，需跨上下文阅读理解才能提取（直接使用 PersonaMem-v2 原始对话）。
  - **Inferential（推断）**：偏好从不被提及，但可通过行为线索经一步推理得出（如提到户外花粉打喷嚏、询问不嗜睡的药片，推断花粉过敏）。
- **三种表达变体共享完全相同的非目标块和完全相同的 Know/Act 测试题**，确保性能差异仅反映表达强度而非题目难度。
- **Know/Act 测试题**由 GPT-5 生成，Know 题附有 ground truth，Act 题附有自然场景。

#### 测试评估方法
- **Know 评判**：GPT-5 作为 judge，将模型回答与 ground truth 对比，给出二元 Pass/Fail。
- **Act 评判**：采用**配对比较法**——将"带记忆的响应"与"同一 backbone 模型无任何记忆输入的零记忆基线响应"对比，由 GPT-5 judge 判定前者是否明显体现了对用户偏好的考虑。
- **记忆注入协议**：采用 MemoryAgentBench 的增量注入协议，将对话块逐一送入各系统的原生管道（Mem0 做事实抽取、Letta 管理分层记忆、知识图谱系统逐步建图），注入完成后在独立会话中分别施测 Know 与 Act，避免互相 priming。

### 6. 主要结论与发现

1. **记住 ≠ 行动，Know–Act 解离在所有架构中普遍存在**。即使最佳系统（Claude 4.6 Sonnet）在显式条件下也仅将约三分之二已记住的偏好转化为恰当行为；GPT-4o-mini 的利用率仅 16.3%（Explicit Know 83.7%）。
2. **长上下文模型总体领先，但窗口大小非唯一决定因素**。1M 窗口的 Claude 4.6 Sonnet 与 Gemini 3.1 Flash 全面优于 128K 窗口的 GPT-4o/4o-mini；但同窗口下模型能力影响巨大（GPT-4o 约为 GPT-4o-mini 的两倍），且 Gemini 在 Know 上领先、Claude 在 Utilization 上领先。
3. **记忆架构能显著缩小差距，最大增益来自 Mem0**。Mem0 将 GPT-4o-mini 的利用率从 16.3% 提升至 54.6%（约 3 倍），达到与 Gemini 3.1 Flash 相当的水平；增益主要在行为侧而非记忆侧，表明好的架构不只是"检索更多"，而是**以更可执行的形式呈现信息**。
4. **Incidental 条件比 Inferential 更难记忆**。所有类别在附带表达下 Know 最低——因为附带场景中偏好从不是对话焦点，难以被标记为值得记忆；而推断场景的对话围绕相关主题展开，语义线索更丰富。
5. **显式表达暴露利用瓶颈，非显式表达暴露存储瓶颈**。显式条件下 Know 高而 Utilization 低，Know–Act 差距最大；附带/推断条件下差距主要源于未能存储。
6. **偏好类型差异显著：健康与治疗类利用最弱**。Therapy & Emotional 的 Know 最高（易回忆）但 Utilization 第二低；Health & Medical 两项均为最低，而这类失败恰恰实际风险最高——安全攸关。
7. **GPT-4o-mini 骨干依赖人口先验，记忆架构则反转该模式**。骨干在刻板偏好上优于反刻板偏好，符合已知的人口统计偏好偏向；接入记忆后该模式反转，表明**检索到的记忆压倒了模型先验**。
8. **失败归因：理解缺陷是最大瓶颈**（占 53.0%），即对话块已在上下文中但模型无法从中提取出偏好；检索失败占 30.7%（主要出现在显式条件，占该条件 48.7%，此处语义匹配意外的更困难）；应用失败占 16.2%，且在三种表达条件下比例稳定，反映 LLM 固有的"给出明确约束仍不遵循"的限制。

### 7. 优点

- **问题定位精准**：首次对同一条用户偏好做"记忆—行为"配对解耦测试，直接回答了"没记住还是没用上"这一此前无法回答的问题，方法设计指向清晰。
- **评估范式可复用**：Know/Act 双测 + Utilization Rate 指标概念简单、可迁移至任何个性化/记忆系统，具备较强实用价值。
- **表达强度三级梯度设计严谨**：同一偏好、同一测试题、仅改变偏好嵌入的对话形式，将表达强度作为唯一变量，归因干净。
- **公平性控制到位**：所有非长上下文系统共享同一 backbone，且给出零记忆 Know 基线验证题不可猜测，使记忆增益的归因更有说服力。
- **失败归因方法论清晰**：通过 oracle 注入逐层 bypass 管道（跳过检索 → 跳过理解），将失败精确拆为检索/理解/应用三层，为后续针对性优化提供了直接指引。
- **评估质量保障完善**：人类与 LLM judge 双重一致性检验、Act judge 盲化验证、multiple judge 交叉验证，评测可信度较高。

### 8. 不足与局限

- **评测依赖 LLM judge**：可能引入系统性偏差（如冗长偏好、对细微行为线索不敏感），尽管有校准验证，但无法完全排除。
- **合成数据生态效度有限**：使用 PersonaMem-v2 的合成 persona 与偏好，缺乏真实世界纵向用户历史中的话题漂移、偏好矛盾等复杂情况。
- **检索任务被人为简化**：每条偏好仅对应单个目标片段、干扰项有限，是"有利"设定；作者自认现实部署中的 Know–Act 差距大概率更大，故结果是保守下界，但也意味着实验可能低估了实际部署难度。
- **只对单个系统（Mem0）做了失败归因**：未对长上下文模型及其他架构类型做同样的 oracle 分析，归因结论的普适性受限。
- **未报告方差与显著性检验**：缺乏多次重复运行的统计区间，系统间差异的显著性未作验证。
