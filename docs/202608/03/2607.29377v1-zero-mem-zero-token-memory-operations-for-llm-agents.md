## 摘要
LLM代理需要记忆以在长时间交互中保持一致行为，然而许多系统使用额外的LLM调用来操作该记忆。生成中间记录并调解其检索会带来循环的标记和时间成本，而省略或合并的细节可能掩盖原始证据。我们质疑结构化记忆访问是否完全需要生成。零记忆引入了零标记记忆操作：在最终问答之外的任何步骤都不调用LLM或消耗LLM输入或输出标记；编码器计算单独核算。零记忆保留原始交互轨迹作为其记录来源。它以两种互补方式组织轨迹。实体-上下文图揭示跨交互的连接，而时间层次保留对话局部性和会话状态。对于每个查询，零记忆权衡这两种视图，从两者中检索，并遵循其结构以恢复支持关系或周围上下文。确定性校准首先丢弃冲突证据，然后保持阅读器的答案基于检索到的轨迹。只有最终问答阅读器调用LLM。在长记忆和长上下文问答基准测试中，零记忆在消除LLM调用和记忆操作中的LLM标记消耗的同时，实现了有竞争力的性能。使用相同的最终问答阅读器和上下文预算，相对于最快的比较基线，它将记忆操作时间成本降低了57.6%。消融研究支持这两种视图及其基于查询的协调的贡献。总体而言，结果表明结构化代理记忆无需生成过去的中间表示。在同行评审后，代码和实现细节将在https://github.com/TheMoon0815/Zero-mem上提供。

## Abstract
LLM agents need memory to act consistently over long interactions, yet many systems use additional LLM calls to operate that memory. Generating intermediate records and mediating their retrieval adds recurring token and time costs, while omitted or merged details can obscure the original evidence. We ask whether structured memory access requires generation at all. Zero-Mem introduces \emph{zero-token memory operations}: no step outside final question answering invokes an LLM or consumes LLM input or output tokens; encoder computation is accounted for separately. Zero-Mem preserves original interaction traces as its source of record. It organizes the traces in two complementary ways. An entity--context graph exposes connections across interactions, while a temporal hierarchy preserves conversational locality and session state. For each query, Zero-Mem weighs the two views, retrieves from both, and follows their structure to recover supporting relations or surrounding context. Deterministic calibration first discards conflicting evidence and then keeps the reader's answer grounded in the retrieved traces. Only the final-QA reader invokes an LLM. Across long-memory and long-context question-answering benchmarks, Zero-Mem achieves competitive performance while eliminating LLM calls and LLM-token consumption from memory operations. With the same final-QA reader and context budget, it reduces memory-operation time cost by 57.6\% relative to the fastest compared baseline. Ablations support the contribution of the two views and their query-dependent coordination. Overall, the results show that structured agent memory need not generate an intermediate representation of the past. After peer review, the code and implementation details will be available at \textcolor{blue}{https://github.com/TheMoon0815/Zero-mem}.

### 1. 核心问题与整体含义

- **背景**：LLM 智能体在长时间交互中需要不断积累与检索历史信息，以保持行为一致性。常见的智能体记忆系统依赖额外 LLM 调用生成摘要、笔记、图索引等中间表示，再在这些抽象上进行检索。

  - 生成式记忆操作（如摘要、反思、图构建）带来持续的 token 和时间开销；

  - 纯原始文本的平面检索（如 RAG）又容易混淆不同会话、用户或时间状态，且在证据分散时检索失败。
- **核心质疑**：结构化记忆访问是否必须依赖“生成”？能否让最终问答成为唯一调用 LLM 的阶段？
- **整体含义**：论文提出 **零标记记忆操作（zero-token memory operations）** 框架 Zero-Mem，证明结构化智能体记忆不需要生成过去的中间表示，也能在性能上超越现有生成式记忆系统，同时彻底消除记忆操作的 LLM token 消耗。

### 2. 方法论：Zero-Mem 框架

#### 核心思想
- 以**原始交互轨迹为唯一记忆来源**，不使用任何 LLM 生成摘要、总结或结构化三元组；
- 通过非生成方式构建两种互补的检索视图：**实体–上下文图（entity–context graph）** 和 **时间层次结构（temporal hierarchy）**；
- 查询时通过轻量路由、双视图检索与融合、证据闭合、确定性校准，构造证据集，最后仅由最终 QA 阅读器调用一次 LLM 生成答案。

#### 关键技术细节

**(1) 无生成记忆基底（Provenance-preserving Token-Free Memory Substrate）**
- 使用非生成 NER 模型（如 spaCy）识别实体；
- 构建图 \(G=(V_d\cup V_e, E_{de}\cup E_{dd})\)：
  - \(V_d\)：上下文单元节点；
  - \(V_e\)：实体节点；
  - \(E_{de}\)：实体–上下文共现边，权重 \(w(d_i,e)=\frac{c(e,d_i)}{\sum_{e'\in E(d_i)} c(e',d_i)}\)；
  - \(E_{dd}\)：相邻上下文单元之间的邻接边。
- 构建多粒度时间层次：turn → window → episode → local span；
- 建立 BM25 词法索引和 BGE-M3 稠密向量索引，仅用于检索/打分，不生成新内容。

**(2) 查询条件化证据路由（Query-Conditioned Evidence Routing）**
- 为每个查询构造轻量画像 \(\phi(q)=\{\text{subject}, \text{keywords}, \text{answer-type}, \text{temporal-cues}, \text{boundary}\}\)；
- 路由决策 \(Route(q)\in\{\text{relational},\text{local}\}\)，由确定性查询结构信号决定（问题形式、时间/聚合需求、主客体的可用性）；
- 全局共享主视图权重 \(\rho=0.6\)，关系型查询以图为重，局部型查询以层次为重。

**(3) 双视图证据检索**
- **图视图**：使用稠密对齐匹配查询实体，通过共现句子传播激活值（公式9），再通过 Personalized PageRank（公式10）对上下文节点排序；
- **层次视图**：按 episode → window → turn → local span 逐级检索，结合主题、时间、边界、答案类型等兼容性信号精化排序。

**(4) 双视图证据闭合与融合**
- 对两张视图的分数进行查询级归一化（公式12）；
- 按路由系数 \(\rho\) 加权融合（公式13）；
- 对主证据补充图关系的桥接证据和局部相邻上下文（公式14），去重后形成闭合证据集。

**(5) 确定性校准**
- 证据级校准：过滤违反 provenance 或边界约束的证据，并按主题、时间、答案类型兼容性排序（公式15）；
- 答案级校准：对可确定性验证的答案形式，从证据中提取候选、进行格式检查、列表裁剪或规范化（公式16）；仅最终阅读器输出不被支持时做修正，不额外调用 LLM。

### 3. 实验设计

#### 数据集 / Benchmark
- **LoCoMo**：长对话记忆基准，包含四类问题：单跳、多跳、时间推理、开放域；用于评估多会话、长时间跨度的记忆能力。
- **HotpotQA**（记忆评估变体）：基于 Wikipedia 的多跳问答，使用关键支撑文档 + 干扰段落，构造 56K / 224K / 448K 三种上下文长度设置，评估超长上下文下的分散证据检索。

#### 对比方法
- **无记忆基线**：LONG-LLM（滑动窗口分段推理）、RAG（分块稠密检索）。
- **记忆基线**：A-Mem、Mem0、MemoryOS、LightMem、SimpleMem、CompassMem、GAM 等当前主流生成式记忆系统。

#### 实验设置
- 基座 LLM：GPT-4o-mini（闭源）和 Qwen2.5-14B-Instruct（开源）；
- 同一设置内，所有方法使用相同的最终 QA 阅读器和上下文预算，Top-K = 5；
- 硬件：NVIDIA RTX 4090 GPU，4 并发线程；
- 评估指标：F1 和 BLEU-1。

### 6. 主要结论与发现

- Zero-Mem 在 LoCoMo 上，在 GPT-4o-mini 和 Qwen2.5-14B 下平均 F1/BLEU-1 均为最优，分别比最强基线 GAM 提高 5.40/5.45 和 4.87/4.86 分。
- 在 HotpotQA 上，Zero-Mem 在所有阅读器和上下文长度设置中均取得最高 F1，平均比最强基线提升 5.52 分，在 448K 超长上下文下依然保持领先。
- 效率对比中，Zero-Mem 将记忆操作的 LLM token 消耗降为 **0**，记忆操作总时长相对最快的基线 LightMem 降低 **57.6%**（334.77s vs 788.76s），同时答案质量仍最高（F1 59.15 vs GAM 53.75）。
- 消融实验表明：图视图与层次视图互补，证据闭合与校准均带来显著增益；检索预算在 Top-5 到 Top-10 之间性能稳定。

### 7. 优点

- **概念新颖**：首次正式提出“零标记记忆操作”这一记忆运行范式，将记忆开销与最终推理清晰分离。
- **可追溯性强**：所有检索证据均来自原始交互轨迹，保留 provenance，不产生因压缩/抽象导致的信息失真。
- **双视图互补设计巧妙**：关系图解决跨会话实体关联，时间层次保留局部语境和会话状态，双视图融合显著优于单视图。
- **确定性校准设计完整**：证据级和答案级两级校准低成本、可复现，不引入额外 LLM 调用。
- **实验公平度高**：统一阅读器、统一上下文预算、统一检索上限，隔离记忆管线差异，结论可信。
- **性能与效率双优**：不是以牺牲质量为代价换效率，而是同时取得最优性能和最低内存开销，说服力强。
