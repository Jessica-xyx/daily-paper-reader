## 摘要
基于大语言模型（LLM）的搜索智能体通过与外部环境的多步交互来回答问题。然而，将完整的执行轨迹提供给LLM会导致上下文无限增长并引入噪声。现有的压缩方法在牺牲重要细节的情况下缩减上下文，并且常常替换错误事实而不修复由这些事实推导出的下游推理。为解决此问题，我们提出了ReTree，一种用于搜索智能体的自校正树结构记忆机制。ReTree构建有界的每步推理上下文，同时保留来源引用的证据。它将搜索建模为一棵证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与早先的声明相矛盾时，ReTree回溯到引入该声明的节点，替换过时证据，重新生成摘要，修剪受影响的支路，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并使最终声明可追溯至检索到的段落。在四个公开的问答和搜索基准上的实验表明，ReTree始终优于全轨迹ReAct，将答案准确率最高提升25.6个百分点（pp）；全轨迹ReAct的平均最大每步推理上下文是ReTree的$1.27$--$1.51$倍。这些结果确立了ReTree作为长周期搜索的一种有效的自校正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

## 1. 核心问题与整体含义

### 研究动机与背景

- **问题根源**：基于大语言模型（LLM）的搜索智能体需要通过与外部环境（如搜索引擎）的多步交互来回答复杂问题。标准的做法是将完整的执行轨迹（思考、动作、观察）直接提供给 LLM，导致两个严重问题：
  - **上下文无限增长**：随着检索步数增加，每步推理所需的上下文（trajectory）越来越长，超出模型有效处理范围；
  - **错误级联（error cascade）**：某一步检索到错误或过时的信息后，后续查询和中间结论都会基于该错误前提进行推理，导致错误被不断传播和放大。
- **现有方案不足**：
  - 压缩方法（如滚动摘要、报告重构）虽然能控制上下文长度，但会丢失关键细节；
  - 更重要的是，仅仅替换错误事实并不能修复那些**基于旧事实推导出的下游结论**——即"替换事实"与"修复派生推理"之间存在断裂。
- **核心见解**：一个可靠的搜索记忆不仅需要紧凑的状态表示，还必须具备**可追溯的证据来源**和**依赖一致性**，即在证据变化时能够识别并修复受影响的派生状态。

### 论文贡献

- 将检索导致的错误级联形式化为**结构化状态修复问题**，提出三个联合需求：有界上下文、声明到来源的可追溯性、依赖一致的修订；
- 提出 **ReTree** 树状记忆机制，实现矛盾触发的回溯、摘要重新生成和子树剪枝；
- 实现**段落级来源绑定**，确保最终答案声明可解析到当前证据对象和原始检索段落；
- 在四个公共基准、2,149 个问题上验证了有效性。

## 2. 方法论：ReTree

### 核心思想

ReTree 将搜索过程建模为一棵**证据树（evidence tree）**，每个节点保存以下内容：

- **有界摘要 $s_n$**：至多 140 词的任务状态总结；
- **本地证据 $E_n$**：原子化的事实陈述及其稳定标识符和来源 URL；
- **修订历史 $H_n$**：记录该节点发生过的证据替换与冲突处理记录；
- **父节点指针 $p_n$**。

### 关键技术细节

#### （1）有界上下文构建

- 策略每步只看到 **当前节点的摘要 + 与问题最相关的 top-5 证据**（$k=5$），而非全部路径证据；
- 上下文构建函数：$C_k(M_t, q) = s_{n_t} \| \text{TopK}_k(A(n_t), q \| s_{n_t})$，其中 $A(n)$ 是根节点到当前节点的路径证据并集；
- 由此实现**每步推理上下文 O(1)**，不随轨迹长度增长。

#### （2）扩展与来源绑定

- 检索到的段落被解析为至多 6 条原子证据；
- 证据的来源通过"段落索引"绑定而非要求模型复述 URL，避免不可验证的引用；
- 新证据与原状态兼容时，创建子节点并压缩摘要，以**追加式**方式扩展树。

#### （3）矛盾触发的回溯与修复

- **冲突检测**：新证据与 top-k 已有证据进行比较，仅当在同一实体、同一属性、同一范围和时间下出现不兼容值时才判定为冲突；不同实体义项、补充性信息或并列候选则直接扩展树；
- **二次确认**：由另一轮"修订调用"结合分支摘要、目标证据的变更历史进行确认，防止在同一值之间反复震荡；
- **修复流程**（当冲突确认后）：
  1. 定位引入被反驳证据的节点 $\iota(j)$；
  2. 替换该节点的证据文本和来源；
  3. 将该节点的修订历史追加一条记录；
  4. 仅基于修正后的累积证据重新生成该节点摘要；
  5. **修剪该节点的所有后代**；
  6. 将当前节点重置为该修复节点，恢复搜索。
- 该回溯操作对应了**依赖定向修订**（dependency-directed revision，源自 Doyle 1979 的真值维护系统）的思想。

#### （4）依赖一致性形式化

- 定义依赖集合 $\text{Dep}_{t-1}(j) = \{z \in Z(M_{t-1}) : e_j \rightsquigarrow z\}$；
- 依赖一致性更新需满足：$\text{Dep}_{t-1}(j) \subseteq I_t \cup G_t(e'_j)$，即所有依赖被修订证据的组件必须被**无效化**或**基于修正值重新生成**。

#### （5）声明级归因

- 最终生成器将推理分解为原子声明，每个声明关联一个或多个证据标识符；
- 通过映射链：$c_i \rightarrow j \rightarrow (x_j, u_j) \rightarrow \text{Passage}(u_j)$，实现从最终答案到原始检索段落的追溯；
- 使用独立的 NLI 评判器判定引用的段落是否蕴含（而非仅陈述与）对应声明。

## 3. 实验设计

### 数据集

|--------|--------|------|
| Bamboogle | 125（全部） | 组合性缺口暴露 |

### 对比方法

- **Full-Trajectory ReAct**：完整保留未压缩的观察轨迹，是标准基线；
- **FlatUpdate**：机制匹配的扁平记忆更新基线，共享 ReTree 的摘要、证据预算和冲突检测器，但**冲突时仅原地替换事实**，不做依赖追踪和后代剪枝（用于隔离 ReTree 结构化修复的贡献）；
- **ReportMemory**：类似 ReSum/IterResearch 的迭代综合基线，将检索折叠为单一有界报告，保留无序 URL 集合（用于测试纯摘要压缩是否足够）。

### 评估指标

- **答案质量**：GPT-5 判定准确率（Judge Accuracy）+ 归一化精确匹配（EM）；
- **归因质量**：引用精确率（CitePrec）、召回率（CiteRec）、F1 和未引用率（Uncited）；
- **上下文与计算**：平均最大每步策略上下文（字符数）、模型调用次数、token 用量。

## 6. 主要结论与发现

- **答案质量显著提升**：ReTree 在所有 4 个数据集上均优于 Full-Trajectory ReAct，准确率提升 8.3–25.6 pp；综合 2,149 题，Judge Accuracy 提升 13.9 pp，EM 提升 7.4 pp；
- **优于有界扁平更新**：ReTree 在每个数据集上比 FlatUpdate 高 2.2–4.7 pp，证明**结构化依赖修复**（而非仅原子证据替换）是关键；
- **优于纯报告综合**：ReTree 整体准确率比最强的综合基线 ReportMemory 高 3.0 pp，说明**仅压缩上下文不够**，还需保留可修复的证据结构；
- **上下文压缩有效**：Full-Trajectory ReAct 的平均最大每步上下文是 ReTree 的 1.27–1.51 倍；在长轨迹中 ReAct 上下文可超过 5.6K 字符，而 ReTree 保持稳定窄带；
- **归因质量最优**：ReTree 的引用精确率和召回率（44.5/41.3）高于 Full ReAct（37.7/27.1）和 ReportMemory（16.8/21.4）；
- **回溯机制确实被触发**：9.6–17.5% 的运行中发生了自然回溯，证明现实检索中冲突是常见的，结构修复是有实际需求的。

## 7. 优点

1. **问题形式化清晰**：将"检索错误级联"正式定义为三个可验证的需求（有界上下文、可追溯性、依赖一致性），特别是用公式严格界定了"依赖一致性更新"的含义；
2. **结构设计合理**：树形记忆将 compact 上下文构建、持久证据来源和结构无效化三者解耦，设计清晰；
3. **自校正能力强**：矛盾触发回溯 + 二次确认 + 历史感知的机制设计，兼顾了修复能力和对震荡的抑制；
4. **归因可验证**：段落级来源绑定 + NLI 验证链，避免了幻觉性引用；
5. **消融设计严谨**：FlatUpdate 与 ReTree 共享除结构化修复外的全部机制，精确隔离了树结构修复的贡献；ReportMemory 隔离了"压缩 vs 结构"的影响；
6. **公平性较好**：所有方法使用同一骨干模型、同一搜索 API、同一问题顺序、同一超参数，配置对齐良好。
7. **对 LLM 记忆设计有启发意义**：论文明确指出"记忆不仅是更短的转录，而是可编辑的状态表示"，为后续研究提供了新视角。

## 8. 不足与局限

1. **硬剪枝过度粗暴**：ReTree 将修订节点的**所有**后代视为依赖，会误删实际上独立的派生状态，造成不必要的重新检索和计算浪费；需要显式证据到摘要/查询的依赖追踪才能实现选择性修复；
2. **外部存储无界**：虽然单步上下文有界，但外部证据树随检索不断增长，线性证据选择（lexical TopK）和树遍历在超长周期下会变慢；
3. **冲突判断是瓶颈**：冲突检测器的假阴性会保留污染证据，假阳性会过度剪枝有用状态；同范围规则和历史确认只能降低而不能消除误判；
4. **额外计算开销**：结构化修复需要额外的 LLM 调用（冲突提议 + 修订确认 + 摘要重新生成），比 FlatUpdate 多 7–11% 模型调用和 10–13% tokens；
5. **实验覆盖有限**：仅 Qwen3-8B 一个骨干；未评估跨模型迁移；2Wiki/HotpotQA 仅用子集；归因诊断仅 FRAMES；
6. **评估依赖 LLM 裁判**：GPT-5 判定存在系统偏差可能性；无人工评估验证；
7. **上下文选择策略原始**：当前用词法重叠（lexical）检索 top-k 证据，未利用向量语义检索，可能影响证据召回质量；
8. **架构场景局限**：ReTree 定位为搜索场景的工作记忆，不是通用长期记忆系统，不适用于需要无限制回顾所有历史声明的任务。
