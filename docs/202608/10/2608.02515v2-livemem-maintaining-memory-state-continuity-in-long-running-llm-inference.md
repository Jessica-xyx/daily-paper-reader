## 摘要
长时间运行的助手和代理会消耗交互流，最终超出上下文限制。现有的上下文保留、摘要和检索方法仅提供对选定历史的访问，但在工作上下文变化时，并未提供跨越完整生命周期的持久状态。我们将这种缺失的推理能力定义为“上下文更替下的状态连续性”：通过一个固定容量的记忆状态来推进计算，该状态的寿命与活动上下文无关。我们提出了一种内在记忆方法——LiveMem，它为预训练的全注意力LLM增强了一个记忆状态，该状态在完整生命周期内保留历史信息，而主注意力路径则保留一个有界的KV窗口。上下文更替与记忆状态维护、面向记忆的后训练以及状态感知服务共同使这一记忆状态在其来源标记被释放后仍能承载信息。实验表明，LiveMem在评估系统中及与其他内在记忆方法相比，取得了领先的整体性能。在LongMemEval上的实验表明，即使支持性证据已从当前上下文中移除，LiveMem仍能基于记忆状态回答问题，且证据距离分析显示有用信息能持续存在于活动窗口之外。因此，LiveMem确立了状态连续性作为持续LLM推理的一种独特且互补的抽象。

## Abstract
Long-running assistants and agents consume interaction streams that eventually outgrow the context. Existing context retention, summarization, and retrieval preserve access to selected history, but do not provide a persistent state over the full lifecycle when working context changes. We formulate this missing inference capability as \emph{state continuity under context turnover}: carrying computation forward through a fixed-capacity memory state whose lifetime is independent of the active context. We introduce an intrinsic memory method, \textbf{LiveMem}, which augments a pretrained full-attention LLM with a memory state that preserves the historical information over the whole lifecycle while the main attention path retains a bounded KV window. Context turnover and memory state maintaining, memory-oriented post-training, and state-aware serving jointly make this memory state load bearing after its originating tokens are released. Our experiments show that LiveMem achieves leading overall performance among evaluated systems and other intrinsic memory methods. Experiments on LongMemEval show that LiveMem is able to answer the question based on the memory state, even when the supporting evidence has been removed from the current context, and evidence-distance analysis shows that useful information persists beyond the active window. LiveMem thus establishes state continuity as a distinct and complementary abstraction for continual LLM inference.

## 1. 核心问题与整体含义（研究动机和背景）

长期运行的 LLM 助理与智能体会产生持续增长的交互流，最终超出上下文窗口的容量极限。现有解决方案（如上下文保留、摘要、RAG 式检索）本质上属于**工程化记忆管理**，提供的是"历史访问"能力——即将选定内容以显式记录或表征形式重新注入当前计算，属于**重建式推理（reconstructive inference）**范式。这类方法无法提供作者定义的**状态连续性（state continuity）**：一种与活动上下文寿命无关、跨越完整生命周期持续更新的内在记忆状态。

作者将这一需求形式化为"上下文更替下的状态连续性"（state continuity under context turnover）。其核心观点是：外部检索系统（"历史访问"）与内在循环记忆状态（"状态连续性"）不是竞争关系，而是在时间尺度和信息表征上正交互补的两种机制。仅有名义上的循环状态并不足以实现真正的记忆承载——模型必须经历上下文更替的训练，学习将信息写入并保持于记忆状态中，才能让记忆状态真正发挥作用。

## 2. 方法论

### 2.1 核心架构：注意力路径 + 循环记忆旁路
- 在预训练全注意力 Transformer 的每一层增加一个**并行循环记忆分支**，基于 **Gated DeltaNet-2 (GDN2)** 实现。
- 主注意力路径提供有界工作上下文的精确访问；记忆分支以固定容量状态 $M_t$ 在完整生命周期内持续读写。
- 注意力输出 $a_t^\ell$ 与记忆分支输出 $r_t^\ell$ 逐层相加：$o_t^\ell = a_t^\ell + r_t^\ell$。

### 2.2 记忆状态更新（GDN2 核心公式）
单头状态 $S_t \in \mathbb{R}^{d_k \times d_v}$ 的更新包含三个关键操作（公式 7–9）：
- **遗忘**：$S_t = \text{Diag}(\exp(g_t)) S_{t-1}$，通过学习得到的对数衰减 $g_t \leq 0$ 沿 key 维度选择性遗忘；
- **擦除与写入准备**：$\rho_t = w_t \odot v_t - S_t^\top (b_t \odot k_t)$，用擦除门 $b_t$ 移除旧关联以减少写入干扰；
- **写入与读取**：$S_t = S_t + k_t \rho_t^\top$，$r_t = S_t^\top q_t$。

其中 $g_t$（衰减）、$b_t$（擦除门）、$w_t$（写入门）均由输入 token 学习得到，实现逐 token 的实时记忆更新。

### 2.3 上下文更替机制（Context Turnover）
- 输入按有序 chunk 序列 $X_0, X_1, \dots$ 处理；系统提示保留为**注意力锚点（attention sink）**。
- 主注意力路径维护 FIFO 有界窗口，旧 chunk 超出阈值后被逐出（公式 10），但信息已保留在循环记忆状态中。
- **训练和推理使用完全一致的更替策略**：训练时通过 FlexAttention 动态注意力掩码实现；推理时直接释放被逐出的 KV 页面。这一设计保证了训练-推理一致性，是方法的关键工程要点。

### 2.4 记忆导向的后训练
- **SFT 阶段**：先用长文档 QA 数据冷启动（激活侧分支），再用重平衡后的混合数据（QA、分类、多查询任务）正式训练；损失仅作用于答案 token（公式 11）。
- **RL 阶段**：采用 GRPO 算法，结合 DAPO 实践（clip-higher、token 级损失、动态采样、去除 KL）；奖励函数基于准确率并设格式惩罚（公式 12–14）。
- 训练时冻结骨干参数，只训练记忆分支全参数；输出投影零初始化，保证初始时等价于原模型。

## 6. 主要结论与发现

- **LiveMem 在整体性能上领先**：在 Wiki QA 和 Long QA 上取得 SOTA；在 Conversation 和 TTL 上位居第二，仅次于各自特化的基线方法（RAG 和 Context2LoRA），但其他基线一旦脱离其擅长任务性能即大幅下降，而 LiveMem 表现均衡稳定。
- **MQ 任务上是标志性优势**：多跳单问任务中 Qwen3-4B 与 δ-mem 接近或超过 LiveMem，但多问题并行场景下其他方法性能断崖式下跌，LiveMem 保持领先，说明记忆状态能同时支撑多条推理链路。
- **记忆状态确实承载被逐出的证据**：LongMemEval 子集分析显示，证据完全移出上下文时，LiveMem-RL 准确率（16.5%）比无历史访问的 Qwen3-4B（3.1%）和 δ-mem（3.6%）高约 13 个百分点。
- **遗忘机制服从距离衰减但性能不崩塌**：证据距窗口越远准确率略有下降，但经过多个更替间隔后仍保持可测量水平（图 4）。
- **训练课程（curriculum）很重要**：先长文本激活侧路径、再重平衡数据正式训练的效果最佳；直接将全部数据混合效果最差。
- **侧路径必须全参数训练**：LoRA 因与 GDN2 分布差异大而效果不佳；主路径加 LoRA 反而削弱侧路径记忆。

## 7. 优点

- **概念贡献清晰**：将"状态连续性"与"历史访问"明确区分为正交的记忆维度，为长时 LLM 推理提供了新的设计视角。
- **方法设计端到端完整**：从架构（GDN2 侧分支）、训练（SFT+RL 记忆导向后训练）、推理调度（chunk 更替、分页 KV 管理）到服务（状态感知的多请求隔离），形成了完整闭环，而非仅提出一个记忆模块。
- **训练-推理一致性是亮点**：上下文更替策略同时用于 SFT、RL recomputation 和 serving，页面大小（32 token）与 chunk 边界对齐，避免了训练与推理行为漂移。
- **零初始化保护预训练模型**：记忆分支输出投影初始化为零，引入侧分支不破坏原始模型能力，降低了后训练风险。
- **诚实的消融与局限讨论**：明确报告了 NIAH 任务上的失败（有损记忆无法精确恢复任意 token）、位置编码的有界性限制，并对与检索/外部存储的互补关系给出了务实建议。

## 8. 不足与局限

- **无法精确归档（损失性记忆）**：RULER NIAH 实验显示，在 32K 有界上下文下 LiveMem 与基线同样低（0.19–0.23），无法从记忆状态精确重建任意细粒度"针"。对于需要无损档案回忆的应用，必须结合检索或外部存储。
- **位置编码有界**：Qwen3 骨干的 RoPE 最大位置为 262,144 token，实验中限制在 256K；真正无限上下文需要 NoPE 或位置泛化骨干（作者指出 Kimi Linear/K3 为可行方向，但未实证验证）。
- **RL 收益不总是显著**：LiveMem-RL 相比 LiveMem-SFT 的提升在部分数据集较小（如 Banking +0.02、CLINC −0.01），RL 阶段的边际收益需要在更大规模上验证。
- **固定容量有损记忆的理论边界未系统刻画**：结论指出"有用信息持续存在于窗口之外"，但没有给出记忆容量、压缩率与可恢复信息量之间的理论关系或上界分析。
- **多问任务奖励设计的探索空间**：RL 奖励中"全部答对 +0.5"和格式惩罚为启发式设计，缺乏系统性消融。
- **计算开销**：每层 32×128×128 的 FP32 循环状态带来额外显存与计算开销，论文未报告实际的吞吐/时延对比数据。
- **公平性讨论不足**：Context2LoRA 在 TTL 上的"超常"表现被归因于其记忆假设与任务天然匹配，但未做同等条件下的对照实验来排除评估协议偏向。
