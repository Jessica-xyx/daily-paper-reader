## 摘要
长期记忆对于基于LLM的智能体维持交互并可靠地利用遥远历史至关重要。然而，现有记忆系统通常通过统一的摘要和检索流程处理异构对话内容，导致要么令牌消耗过多，要么细粒度证据不可逆转地丢失。我们认为历史对话内容应根据其可压缩性、时间动态性和保真度要求区别处理。基于这一见解，我们提出了LeanMem，一个轻量级长期记忆框架。LeanMem首先过滤低价值内容，然后根据信息性质将信息丰富的片段存储为紧凑的画像记忆、时间结构化事件记忆或基于来源的记录记忆。在维护过程中，仅选择性更新动态演化的事件记忆，避免对稳定画像和不可变记录进行冗余整合。在推理过程中，LeanMem根据查询特定的证据需求动态选择记忆类型并分配检索预算，按需组装相关证据。在LoCoMo和LongMemEval-S上使用GPT-4.1-mini和Qwen3-8B进行实验，LeanMem在每种设置下均比最强的基于记忆的基线提高了准确性，最高提升15.1个百分点，同时构建成本、推理令牌和延迟最低或接近最低。代码和数据集包含在补充材料中。

## Abstract
Long-term memory is essential for LLM-based agents to sustain interactions and reliably leverage distant history. However, existing memory systems typically process heterogeneous dialogue content through a uniform summarization and retrieval pipeline, leading to either excessive token consumption or irreversible loss of fine-grained evidence. We argue that historical dialogue content should be handled differently according to its compressibility, temporal dynamics, and fidelity requirements. Based on this insight, we propose LeanMem, a lightweight long-term memory framework. LeanMem first filters out low-value content, then stores informative segments as compact profile memory, temporally structured event memory, or source-grounded record memory, depending on the nature of the information. During maintenance, only dynamically evolving event memories are selectively updated, avoiding redundant consolidation of stable profiles and immutable records. During inference, LeanMem dynamically selects memory types and allocates retrieval budgets according to query-specific evidence demands, assembling relevant evidence on demand. On LoCoMo and LongMemEval-S with GPT-4.1-mini and Qwen3-8B, LeanMem improves accuracy over the strongest memory-based baseline in every setting, by up to 15.1 points, at the lowest or near-lowest construction cost, inference tokens, and latency. The code and datasets are included in the supplementary materials.

## 1. 核心问题与整体含义

### 研究动机与背景
- 基于LLM的智能体（LLM-based Agents）在长周期交互中面临固定上下文窗口的限制，难以可靠访问遥远历史，因此**长期记忆（Long-term Memory）** 成为关键机制。
- 现有长期记忆系统通常采用**统一的摘要与检索流水线**处理所有异构对话内容，导致两大问题：
  - **效率问题**：对完整对话反复调用LLM进行摘要，消耗大量构建令牌（construction tokens）；
  - **保真度问题**：激进的压缩会不可逆地丢失未来查询所需的细粒度证据。
- 这形成了**效率-保真度权衡**（efficiency-fidelity trade-off）：轻量记忆构建方法减少输入，但可能丢失细节；检索侧方法提升保真度，却增加推理令牌和延迟。
- 论文的核心洞见是：**对话信息在可压缩性、时间动态性和保真度要求上存在本质差异**，不应使用统一的压缩策略处理所有内容，而应区分对待。

## 2. 论文提出的方法论

### 核心思想
LeanMem主张按信息的**可压缩性、时间动态性和保真度要求**对对话内容进行差异化处理，而不是统一压缩。其总体流程包括三个阶段：

### （一）受控记忆写入（Controlled Memory Writing）
将对话历史划分为主题段落后，按信息类型分配存储策略：

- **关键话语过滤（Key Utterance Filtering）**：
  - 使用基于规则的方法过滤问候、确认、重述等结构性低信息轮次；
  - 利用用户-助手交互的不对称性，以用户话语为路由锚点，助手话语不独立保留。
- **主题分割（Topic Segmentation）**：
  - 以主题段落（topic segments）而非单轮或整个会话作为基本构建单元；
  - 通过计算相邻话语余弦相似度的"谷值深度"（valley depth）检测主题转换边界，阈值 $\tau = \mu_D + 0.05\sigma_D$ 自适应确定。
- **写入调度（Write Scheduling）**：
  - 设计目标形式化为 $y_i = \arg\min_{y \in Y} C(y,S_i) \ \text{s.t.} \ L(y,S_i) \leq \epsilon$，即选择成本最低且信息损失可接受的表示；
  - 通过LLM调度器沿三个判别维度评估：**稳定性**、**时间依赖性**、**保真度要求**；
  - 输出路由结果 $r_i = \langle y_i, I_i, \xi_i \rangle$。
- **记忆物化（Memory Materialization）**，按路由结果存储为三类记忆：
  - **画像记忆（Profile Memory）**：稳定的用户属性与偏好，直接存储结构化属性-值对，无需额外LLM调用；
  - **事件记忆（Event Memory）**：状态变化、进度、时间有序的状态，存储为 $\langle e_i, t_i, z_i \rangle$（事件主题、时间锚点、状态描述）；
  - **记录记忆（Record Memory）**：密集细节内容（如列表、排班表），存储检索要点（gist）+ GLiNER提取的关键词/实体 + 指向原始对话的源指针，保留可追溯性；
  - **忽略（Ignore）**：无长期证据价值的主题段落（如临时请求）。

### （二）选择性记忆演化（Selective Memory Evolution）
- 仅对**事件记忆**进行演化和整合，画像记忆与记录记忆不进行多余整合；
- 采用**延迟更新**（deferred updates）：新事件先进入缓冲区，达到容量阈值后再触发整合，摊薄LLM调用开销；
- 通过主题和状态检索相关事件，按时间锚排序，由LLM增量更新状态而非全局重建。

### （三）自适应证据组合（Adaptive Evidence Composition）
- LLM规划器根据查询生成检索计划 $\pi_q = \langle C_q, d_q, M_q, w_q, k_q \rangle$，包含约束条件、证据需求描述、所需记忆类型、各类型依赖权重和检索深度；
- 按记忆类型分别检索，再进行重排序：$score(q,m) = w_q^c [Rel_c(q,m) + Match(C_q, m)]$；
- 根据证据角色组合记忆：画像提供稳定上下文、事件按时间序排列以暴露状态转换、记录在需要细节时展开源指针。

## 6. 主要结论与发现

### 核心结论
1. **差异化存储优于统一压缩**：按信息类型分别使用画像、事件、记录三种记忆表示，相比统一摘要策略，准确率显著更高且令牌成本更低；
2. **在所有设置下超越最强基线**：
   - LoCoMo上相对最强记忆基线提升5.54/5.84个百分点（GPT-4.1-mini/Qwen3-8B）；
   - LongMemEval-S上提升15.07/2.80个百分点；
   - 构建令牌在LongMemEval-S上仅需117.61K/160.35K（A-Mem需超1.2M）；
3. **效果提升主要来源于记忆设计而非骨干模型**：两个骨干模型呈现一致的改进趋势；
4. **各组件的贡献不同**：
   - 存储调度（差异化表示）贡献最大，移除后准确率大幅下降；
   - 主题分割和检索规划对长对话场景（LongMemEval-S）尤为关键；
   - 事件演化对跨会话时间跟踪类任务至关重要；
   - 关键话语过滤主要带来效率收益。

## 7. 优点

### 方法设计上的亮点
- **"最小充分表示"原则**：设计目标明确为在可接受信息损失范围内选择成本最低的表示方式，具有理论上的清晰性；
- **三类记忆的分工合理**：画像（稳定）、事件（动态）、记录（高保真）恰好对应对话信息的三种根本属性，分类维度正交、决策清晰；
- **记录记忆的溯源设计**：使用源指针而非完全压缩，兼顾效率与保真度，避免了不可逆信息损失；
- **选择性演化**：只演化需要跟踪状态变化的事件记忆，避免了稳定记忆的冗余整合；
- **延迟更新机制**：缓冲累积后再整合事件，摊薄了LLM调用开销；
- **查询自适应的检索预算分配**：根据查询类型动态分配各记忆类型的检索深度，而非固定Top-k，减少了不必要的检索开销；
- **轻量化实现**：使用GLiNER提取关键词、all-MiniLM-L6-v2编码，构建成本低，易部署。

### 实验设计的亮点

## 8. 不足与局限

### 应用与泛化限制
- 依赖固定决策协议和预定义Schema，对开放域、高度异构的对话类型适应性可能有限；
