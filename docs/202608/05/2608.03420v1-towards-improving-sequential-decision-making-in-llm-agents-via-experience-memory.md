## 摘要
大型语言模型在单次推理任务上已取得显著进步，但其在序贯决策中的表现尚不明确。我们在完全可观测的双人零和游戏中对此进行了研究，这些游戏提供了真实结果评估：结果由规则决定，个体走棋的最优性可计算或近似，无需依赖评判模型。跨模型层级下，LLM 在井字棋或四子棋等简单游戏中表现欠优，并输给 MCTS 对手。保持游戏树不变但改写其表面形式的混淆处理对性能影响不大，表明这一差距不能完全由对记忆策略的回忆来解释。鉴于这一性能差距，我们引入了一个增强代理框架，包含专为序贯设置设计并应对序贯决策常见挑战（如信用分配）的经验记忆。我们表明，赛后反思和规则提取可在不修改模型权重的情况下，显著提升井字棋的表现。

## Abstract
Large language models have improved substantially on single-shot reasoning tasks, but their performance in sequential decision-making is less well understood. We study this on fully-observable two-player zero-sum games, which provide ground-truth evaluation: outcomes are determined by the rules, and optimality of individual moves can be computed or approximated, without relying on a judge model. Across model tiers, LLMs play suboptimally in simple games such as tic-tac-toe or Connect Four, and lose to MCTS opponents. Obfuscations that preserve the game tree but rewrite its surface form leave performance largely unchanged, indicating the gap is not fully explained by recall of memorized strategies. Motivated by this performance gap, we introduce an agentic framework enhanced with an experience memory designed for the sequential setting and addressing common challenges of sequential decision-making such as credit assignment. We show that post-game reflection and rule extraction yield measurable improvements on tic-tac-toe without modifying the model weights.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大语言模型（LLM）在单次推理（single-shot reasoning）任务上表现优异，但其在序贯决策（sequential decision-making）场景中的能力尚未被充分理解。论文的核心问题是：LLM 在需要多步交互、对手对抗、延迟奖励的环境中，能否做出可靠的决策？
- **研究背景**：现有评估常依赖 LLM 评判器或代理指标，容易混淆推理质量与表面合理性。论文选择完全可观测的双人零和博弈作为测试平台：这类游戏的结果由规则决定，单步最优性可通过经典算法精确计算，无需人工或模型评判，从而提供 ground-truth 级别的评估。
- **核心发现**：即使是井字棋、Nim、四子棋这类人类轻易掌握的游戏，当前最先进的 LLM（包括 GPT-5.4、Gemini 3.1 Pro、GLM-5.2 等 Frontier 模型）仍表现欠佳；高级模型在四子棋中几乎全部输给中等强度的 MCTS 对手，且失败多发生在开局阶段（平均仅约 10 步即落败），而非战术复杂的残局。
- **深层含义**：通过规则混淆实验（保持游戏树不变、仅改写表面形式），发现性能几乎不受影响，说明 LLM 的缺陷并非单纯源于对已记忆策略的不完美回忆，而是存在决策时推理（decision-time reasoning）瓶颈。这提示需要从代理层架构改进，而非仅依赖模型规模或权重更新。

## 2. 论文提出的方法论（核心思想、技术细节、算法流程）

- **核心思想**：在保持 LLM 为主要推理器的前提下，通过外部经验记忆（experience memory）为其提供决策时所需的结构化上下文，无需修改模型权重。借鉴 Memento 的案例推理（case-based reasoning）和 Reflexion 的反思机制，但针对序贯博弈环境进行适配。
- **REAPER 框架**（Reflective Experiential Agent with Periodic Extraction of Rules）由以下关键组件构成：
  - **规划器-执行器循环（Planner-Executor Loop）**：规划器生成计划或最终动作，执行器逐步执行；通过结构化 JSON 输出保障交互可靠性，最多迭代 3 次，若未产生合法动作则记为失败。
  - **案例记忆（Case Memory）**：以单步走棋（而不是整个轨迹）为存储单元，按“状态-动作-奖励”三元组去重，避免重复案例主导检索。
  - **赛后反思器（Self-Reflector）**：每局结束后，对整个轨迹做单次分析，为每步生成结构化反思，沿两个维度评分：(1) 局部质量（该步在当下是否合理）；(2) 结果贡献（对最终胜负的影响）。该机制解决了延迟奖励下的信用分配难题——输棋中的好棋不会被一概否定。
  - **规则提取器（Rule Extractor）**：每固定局数后，将近期反思案例提炼为一组通用战略规则（约 20 条），注入规划器提示中，用于泛化到未见状态。规则集自我修正：合并重叠规则、删除被新证据反驳的规则。
  - **分层检索（Stratified Retrieval）**：用句向量编码器（SimCSE）对状态嵌入，按余弦相似度检索 k=8 个案例，并确保正例/反例大致均衡，避免单一结果主导。
  - **状态描述器（State Descriptor）**：可选组件，在嵌入前将原始观测转写为自然语言描述，以解耦检索与表面编码；实验显示此组件反而有损性能，故不纳入主配置。

## 3. 实验设计（基准、场景、对比方法）

- **评估平台**：论文开发了 PlyBench，基于 OpenSpiel 游戏引擎，通过接口适配器统一各类玩家（LLM、MCTS、Minimax、随机），支持游戏、玩家与规则混淆的模块化扩展。
- **游戏场景**：三种完全可观测双人零和博弈，各具不同挑战：
  - **井字棋**：小博弈树、短视域，最优结果为平局，考验避免输棋的能力。
  - **Nim**（初始局面 {1,3,5,7}）：小博弈树但需 Nim-sum 计算，先手必败，考验符号推理。
  - **四子棋**：博弈树巨大，需长视域规划与多重威胁预判，先手必胜。
- **对手设定**：Random（均匀随机）、MCTS（n=1000/5000，强但可被利用）、Optimal（Minimax，均匀打破平局）。
- **评估模型**：共 9 个模型分三档：Efficient（GPT-5 nano、Gemini 3.1 Flash Lite、GPT-OSS 120B）、Intermediate（GPT-5 mini、Gemini 3 Flash、Qwen 3.5 122B）、Frontier（GPT-5.4、Gemini 3.1 Pro、GLM-5.2）。
- **对比方法**：
  - 单次调用（single-call）LLM 玩家（Section 3 的基线）
  - Original：Memento 直接移植到博弈场景
  - Baseline：改进通信健壮性、去重、分层采样的工程化案例推理基线
  - REAPER 变体：反思单独、反思+规则提取、V再叠加状态描述器
- **混淆实验**：井字棋 4 种保树混淆（Hidden、Magic Square、Magic Square +5、Story），Nim 3 种（Hidden、Inverse、Story），用于区分记忆与推理。
- **指标**：每步最优率（排除全部走法均最优的无判别力状态）、胜/平/负/失败计数、平均步数、输出 token 数/步、识别率（推理痕迹中明确点出底层游戏的占比）。

## 6. 论文的主要结论与发现

- **序贯推理差距真实且普遍**：Efficient/Intermediate 档 LLM 在井字棋上每 100 步失误 4~12 次，部分模型偶发非法动作；Frontier 档在四子棋中无一胜绩，开局即崩溃。
- **差距不是单纯记忆问题**：保持游戏树的表面混淆几乎不改变最优率；即使模型未识别出底层游戏（如 Gemini 3.1 FL 在 M.Sq+5 中仅 25.6% 识别率），性能依然稳定，指向决策时推理瓶颈而非回忆失败。
- **Nim 比井字棋更容易**：Nim 存在简洁的符号策略（Nim-sum），多数模型可近乎最优，而井字棋需要空间布局与战术模式推理，暴露更多缺陷。
- **REAPER 有效**：在 GPT-5 nano（medium effort）井字棋对 Optimal 对手设置下，REAPER（反思+规则）达到 0.868 平局率，显著优于 Baseline 的 0.818（p=0.018）；反思+规则相对纯反思也显著提升（0.826→0.868，p=0.039）。同时输出 token 量持续下降并低于单次调用基线——性能提升源于更有用的决策上下文而非更长的推理。
- **原始 Memento 移植不可用**：Original 平局率始终为 0，多数局因格式解析失败而终止，说明直接移植案例推理到博弈环境是不充分的。

## 7. 优点（方法与实验设计的亮点）

- **评估范式严谨**：利用双人零和博弈的 ground-truth 可计算性，完全摆脱 LLM 评判器的主观偏差，单步最优率提供了比终局胜负更细粒度的诊断信号。
- **混淆实验设计精巧**：Magic Square（和 15 取数游戏）与井字棋同构，加偏移量（+5）和故事化改写逐步推远表面相似度，干净地隔离了记忆与推理的贡献；推理痕迹识别率作为下限估计，进一步支持结论稳健性。
- **不依赖权重更新的实用取向**：REAPER 在外部增强而非微调，规避了前沿模型权重不可得、微调昂贵且可能损伤既有能力的问题，对部署友好。
- **信用分配的细粒度化**：反思器区分“局部合理的输棋步”与“导致失败的臭棋”，以双轴评分（局部质量/结果贡献）解决了延迟奖励下“一刀切”信用分配的缺陷，是该领域方法的重要改进。
- **消融设计完整**：反思、规则提取、状态描述器、推理 effort 等均做了独立开关消融，且统一使用同一模型做所有组件（避免辅助模型额外能力混淆结论），实验归因清晰。

## 8. 不足与局限

- **任务覆盖有限**：REAPER 仅在井字棋（小博弈树、短视域）上验证，四子棋和更复杂游戏的可扩展性未测试；论文也明确承认了这一开放问题。混淆实验的个别模型-组合性能下降（如 GPT-5 nano 在 M.Sq+5 降至 0.785）显示结论在部分配置下不够稳定。
- **评估成本较高**：每步检索需嵌入向量，反思和规则提取需要额外模型调用，虽然 token 总量下降，但延迟可能增加，实时决策场景受限。
- **检索依赖表面相似度**：状态嵌入对表面形式敏感，状态描述器尝试解决但反而降低检索成功率（因描述文本的嵌入未必靠近原始状态嵌入），说明检索环节仍有工程化改进空间。
- **资源与完整可复现信息缺失**：远程 API 掩盖了硬件层面的精确算力数据，token 统计间接反映但无法直接估算经济成本；部分概率为 0 或 1 的置信区间（四子棋随机对手胜率）缺乏判别力。
- **记忆与泛化的权衡**：规则提取器虽能泛化到未见状态，但规则规模小（约 20 条）且偏向高置信模式，在需要密集战术知识的大型博弈（如四子棋）中可能不足；分层检索的 k 值、周期长度等超参数也未做敏感性分析。
- **对记忆效果的归因边界**：混淆实验中模型识别出底层游戏后仍可能调用记忆策略，无法完全排除记忆因素的残余影响——论文对此持诚实态度，但这也意味着“决策时推理瓶颈”的解释是部分性的。
