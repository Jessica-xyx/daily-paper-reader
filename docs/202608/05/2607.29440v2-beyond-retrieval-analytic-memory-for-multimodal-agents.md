## 摘要
长期多模态记忆不仅需要支持检索相关信息，还需要对跨交互积累的观测进行计算。现有系统主要强调检索记忆，通过摘要和索引组织交互历史，以多种粒度返回与查询相关的信息，从高层抽象到底层记录。在本文中，我们将分析记忆定义为一种补充性抽象，它组织重复出现的多模态观测为可查询结构，支持过滤、聚合、排序和时间比较。我们提出了AdaMM，一个联合支持检索和分析记忆的框架。AdaMM不依赖于应用定义的模式，而是从对话、图像和上下文元数据中提取具有来源关联的属性-值观测，发现重复出现的字段结构，并将其物化以供分析访问。在推理时，一个具有记忆感知的计划器将查询分解为检索和分析操作，并将每个操作路由到适当的工具。在两个长期多模态记忆基准MemEye和MemGallery上的实验表明，AdaMM分别将性能提高了11.3%和6.9%。

## Abstract
Long-term multimodal memory must support not only retrieving relevant information but also computing over observations accumulated across interactions. Existing systems largely emphasize \emph{retrieval memory}, organizing interaction histories through summaries and indexes to return query-relevant information at multiple granularities, from high-level abstractions to underlying records. In this paper, we formulate \emph{analytic memory} as a complementary abstraction that organizes recurring multimodal observations into queryable structures supporting filtering, aggregation, ranking, and temporal comparison. We present AdaMM, a framework that jointly supports retrieval and analytic memory. Rather than relying on application-defined schemas, AdaMM extracts provenance-linked attribute-value observations from dialogue, images, and contextual metadata, discovers recurring field structures, and materializes them for analytical access. At inference time, a memory-aware planner decomposes queries into retrieval and analytic operations and routes each operation to the appropriate tools. Experiments on two long-term multimodal memory benchmarks, MemEye and MemGallery, show that AdaMM improves performance by up to 11.3\% and 6.9\%, respectively.

### 1.2 核心问题：检索-分析不匹配（Retrieval-Analysis Mismatch）
论文指出一个关键缺陷：长期交互历史本质上是不断追加的日志（append-only log），许多用户查询需要对完整范围的记录进行**过滤、聚合、排序、时间比较/选择**等分析性操作，而非仅仅相关性检索。检索式方法面临如下"覆盖-上下文"困境：
- **检索集过小**：可能遗漏必要记录，导致结果偏差（如计算过去一个月的平均睡眠时长，遗漏部分测量值）；
- **检索集过大**：消耗有限上下文，引入冗余和干扰证据。

### 1.3 整体含义
论文提出**分析记忆**（analytic memory）作为检索记忆的互补抽象——将重复出现的多模态观测组织为可查询的结构化形式（支持过滤、聚合、排序和时间比较），并构建了 **AdaMM框架**，实现"语义灵活召回 + 结构化可执行分析"的联合支持。这是对多模态智能体记忆范式的重要拓展。

## 二、论文提出的方法论

### 2.1 核心思想
AdaMM将历史交互 `H` 转换为两种互补记忆：
- **分析记忆 `M_ana`**：通过模式归纳（Schema Induction）将重复出现的属性结构物化为可查询表格，支持可执行计算；
- **检索记忆 `M_ret`**：以"话题→片段→事件"（Topic→Episode→Event）三级层次组织开放事件和视觉细节，支持灵活语义检索。

### 2.2 分析记忆构建（三步流程）

#### （1）属性提取（Attribute Extraction）
对每个交互轮 `R_t`，使用 LLM 抽取所有有依据的属性-值对：
```
O_t = Extractor(R_t) = {(a_tℓ, x_tℓ, p_tℓ)}
```
其中 `a_tℓ` 为属性，`x_tℓ` 为忠实值，`p_tℓ` 指向支撑该观测的对话片段或图像。

#### （2）模式归纳（Schema Induction）
**候选模式挖掘**：基于 Apriori 频繁项集思想，用支持度（support）筛选在足够多轮中共同出现的属性集合：
```
supp_t(C) = Σ_{s=1}^{t} I[C ⊆ A_s]
```
当 `supp_t(C) ≥ θ_s` 时保留候选。

**模式发现（Schema Discovery）**：用全置信度（all-confidence）衡量模式内部共现一致性：
```
all-conf_t(C) = supp_t(C) / max_{a∈C} supp_t({a})
```
当 `all-conf_t(C) ≥ θ_a` 时，且候选是包含最大新结构（inclusion-maximal），则建立新模式。

**模式演化（Schema Evolution）**：当已有模式 `A ⊂ C` 时，用扩展置信度（extension confidence）判断新属性 `Δ = C \ A` 是否稳定伴随 `A` 出现：
```
ext-conf_t(C|A) = supp_t(C) / supp_t(A)
```
若 `ext-conf_t(C|A) ≥ θ_e`，则将模式从 `A` 扩展为 `C`。

#### （3）记忆物化（Memory Materialization）
每个模式 `A` 被物化为关系表 `T_A`：属性作为列，匹配的交互作为行。每条记录包含辅助列 `order` 和 `time`；缺失值留空。LLM生成表的名称、描述和列类型元信息。模式演化时，新属性追加为新增列并重新物化。

### 2.3 检索记忆构建
采用话题→片段→事件三级层次结构：
- **事件**：每个交互轮直接实例化为事件，保留原始证据；
- **片段**：时间相邻且语义相似的事件聚合，相似度通过文本/视觉的晚融合（late fusion）评分：
```
s(u,v) = λ_text·cos(z_text_u, z_text_v) + λ_vis·cos(z_vis_u, z_vis_v)
```
- **话题**：相关片段聚合为更粗粒度的语义上下文。

事件直接保留原始轮次证据，无需LLM额外抽取步骤，避免信息丢失。

### 2.4 自适应查询处理
- **记忆访问工具**：将两种记忆的底层能力抽象为6个工具——分析工具：`LOOKUP`、`FILTER`、`COMPUTE`、`RANK`；检索工具：`SEMANTIC_MATCH`、`EVENT_LOCATE`。每个工具带类型化参数和返回schema。
- **规划上下文构建**：将表和片段的元数据（名称、描述、列、抽样值）通过语义编码 + BM25 混合排序筛选 top-k 相关项，搭配工具描述形成规划上下文，缩小规划空间。
- **渐进式工具执行规划（Progressive Tool-Execution）**：
  - ① 高层计划生成：LLM Planner先生成抽象计划 `π̄ = {(g_ℓ, ξ_ℓ)}`，指定每一步的信息目标和工具类型，不绑定具体参数；
  - ② 渐进式工具实例化：逐步骤决定具体参数，后一步可消费前一步的输出（如 `EVENT_LOCATE` 返回的时间戳可作为 `COMPUTE` 的过滤条件）：
```
Θ_ℓ = Planner(q, D_q, Z_{<ℓ}, g_ℓ, ξ_ℓ)
Z_{<ℓ+1} = Z_{<ℓ} ∪ Invoke(ξ_ℓ, Θ_ℓ)
```
- **答案生成**：最终答案模型基于查询 + 实例化计划 + 工具输出生成回答。

## 六、论文的主要结论与发现

1. **AdaMM在两个基准上全面领先**：
   - GPT-4.1-nano下：MemEye EM提升7.3%、LLM-Judge提升5.8%；MemGallery F1提升4.3%、LLM-Judge提升6.9%；
   - GPT-5.4-mini下：MemEye EM提升3.1%、LLM-Judge提升11.3%；MemGallery F1提升2.6%、LLM-Judge提升5.2%。

2. **分析记忆擅长处理需要精确操作的任务**：最大增益出现在 MemEye 的 Card Playlog（+18.8%）和 Personal Health（+16.7%），以及 MemGallery 的 Conflict Detection（+10.6%）和 Knowledge Resolution（+10.5%）——这些任务要求过滤、值比较、变化追踪等结构化计算。

3. **检索记忆对视觉语义召回仍不可或缺**：在 Brand Memory 等依赖视觉-语义直接匹配的任务上，检索记忆贡献显著（移除后 Brand 下降9.9%）。

4. **两个记忆子系统能力互补**：移除分析记忆导致 Health 任务下降14.9%；移除检索记忆导致 Brand 任务下降9.9%——不同任务的退化模式证实了两者的互补性。

5. **记忆感知的规划机制有效**：移除规划上下文导致总体下降3.3%，一次性实例化（无渐进执行）同样造成一致退化，证明提前了解记忆结构、逐步实例化工具是必要的。

6. **成本开销可控**：AdaMM在MemEye上查询消耗8.3k token，仅比 MM-RAG 多0.6k、比 UniversalRAG 多0.3k，但LLM-Judge准确率提升了11.3%，性价比高。
