## 摘要
记忆对于语言智能体从孤立任务转向长时程、有状态的工作流至关重要，然而现有评估往往将其简化为检索或问答。我们引入了ContextWeave，一个纵向基准，用于评估 recalled experience（回忆的经验）是否提升智能体在真实办公工作流中的下游性能。ContextWeave 将14名参与者的隐私保护、跨月工作流重建为1005个可执行任务，包括568个核心评估任务，并提供指令、容器化环境、轨迹和任务特定的评分标准。它衡量工作区质量以及与参与者特定偏好的对齐程度，并辅以相关性、连续性、可解性和对误导性回忆的鲁棒性诊断。在固定模型下的六种记忆组件中，最强配置将Workspace Score（工作区得分）从68.08提升至78.20，Preference Score（偏好得分）从41.50提升至70.60。在固定记忆组件下，回忆对所有五种测试基础模型的结果都有所提升，尽管增益差异显著。我们的分析表明，可操作的、经验丰富的记忆比紧凑摘要更能支持工作流延续并减少冗余探索，但也可能更容易受到误导性回忆的影响。这些发现促使记忆系统不仅要优化检索相关性，还要优化执行过程中的可靠使用。

## Abstract
Memory is essential as language agents move from isolated tasks to long-horizon, stateful workflows, yet existing evaluations often reduce it to retrieval or question answering. We introduce ContextWeave, a longitudinal benchmark that evaluates whether recalled experience improves downstream agent performance in realistic office-work streams. ContextWeave reconstructs privacy-preserved, multi-month workflows of 14 participants into 1,005 executable tasks, including 568 core evaluation tasks, with instructions, containerized environments, trajectories, and task-specific rubrics. It measures workspace quality and alignment with participant-specific preferences, complemented by diagnostics of relevance, continuity, solvability, and robustness to misleading recall. Across six memory components under a fixed model, the strongest configuration raises Workspace Score from 68.08 to 78.20 and Preference Score from 41.50 to 70.60. With a fixed memory component, recall improves both outcomes for all five tested base models, although gains vary substantially. Our analysis shows that actionable, experience-rich memory supports workflow continuation and reduces redundant exploration more effectively than compact summaries, while it can also be more susceptible to misleading recall. These findings motivate memory systems that optimize not only retrieval relevance but also reliable use during execution.

## 2. 论文提出的方法论

### 2.1 设计原则

- **隐私保护的真实性**：使用真实世界工作流数据，同时通过结构化匿名化保留任务顺序、实体一致性和依赖关系。
- **可执行、可复现的环境**：提供 Docker 容器、模拟 API、本地文件等可交互环境，控制外部依赖。
- **受控纵向评测**：将历史经验与工作环境演进解耦，通过“轨迹对齐”提供固定、规范的 pre-task 状态。
- **下游导向评估**：主要指标是任务完成质量与用户偏好一致性，而非中间记忆操作指标。

### 2.2 数学形式化

- 定义顺序任务流：

  \[
  D = (T_1, T_2, \ldots, T_n), \quad T_1 \to T_2 \to \cdots \to T_n
  \]

- 对目标任务 \(T_i\)：
  - 无记忆性能：\(R(T_i)\)
  - 有记忆性能：\(R_M(T_i)\)，其中 \(M\) 先处理历史任务 \(\{T_1...T_{i-1}\}\) 再辅助解决 \(T_i\)
  - 记忆贡献：\(\Delta R_M(T_i) = R_M(T_i) - R(T_i)\)

### 2.3 数据构建流程

1. **真实工作流提取**：从开源项目收集 14 名参与者多月的文档编辑事件，按时间排序，用 LLM 分段+人工校验形成任务单元（1005 个任务，其中 568 个主流程核心任务）。
2. **隐私保护**：规则检测 + agent 辅助验证，对姓名、路径、凭证等实体做保持结构一致的替换；公共资源尽量保留。
3. **任务重建**：
   - 指令生成：根据前后文档状态、diff、任务注解，由 LLM 推断自然语言、目标导向、不泄漏最终文本的指令。
   - 观测与环境构建：对可恢复的静态资源物化为本地文件/笔记；对不可恢复的第三方服务或昂贵资源用受控模拟 API（simulator agent 生成与原始工作流一致的回应）。
   - 重建循环：执行 → 验证是否与原工作流“同一任务” → 修订指令 / 补充环境，循环至语义对齐。
4. **受控轨迹对齐**：将验证过的执行轨迹改写成“结果对齐轨迹”，使其产生与真实 worklog 相同的最终 workspace 变化，从而得到规范化的 post-task 状态，防止下游任务因执行漂移不可比。
5. **日志与评分设计**：提供任务消息日志（平均 36.3K token，最长 212.3K）和任务特定 rubric。

## 6. 结果与洞见

- **记忆总体带来增益，但幅度差异极大**：a-mem 相比无召回基线 Workspace Score 提升约 10 分（68→78），Preference Score 提升约 29 分（41.5→70.6），win rate 达 72.7%；而 mem0 等摘要型记忆提升有限（Workspace 约 +4 分，win rate 约 50.7%）。
- **经验型记忆优于摘要型记忆**：能够保留具体操作轨迹（如 a-mem）的方法，比只生成概括性事实的摘要方法更能提升下游完成度；摘要型记忆容易丢失过程性细节，导致“知道该做什么但不知怎么做”。
- **记忆提升的主要是非功能性“偏好对齐”**：在 Workspace Score 上增益较小（最高 +10 分），但 Preference Score 增益非常显著，说明记忆最大的价值在于让产出符合用户的既定习惯、写作风格与工作流模式，而非简单提高任务本身的可完成性。
- **有记忆不等于自动可用**：很多情况下，即使召回条目被判定为“相关”，模型也未将其用于实际操作（Continuity 分析显示探索调用未减少）；召回与利用之间存在明显鸿沟。
- **长距离依赖更依赖记忆能力**：任务间相关链接距离越长，无记忆条件下失败率越高，有记忆条件则能部分弥补；但记忆系统若只保留近期信息，则对远距离依赖几乎无帮助。
- **模型差异显著**：更强的基础模型（如 GPT-5.5、Kimi-K2.6）在 Recall-Solvable 问题占比上更高，说明模型本身的推理能力限制了记忆信息的有效利用；而较弱模型即使获得正确记忆也可能不会使用。
- **记忆的“毒性”**：部分记忆组件（尤其摘要型）会在 open-ended 任务中引入误导性先验，导致模型按照错误模式输出，反而降低任务完成度；Hallucination Robustness 指标显示这类记忆诱导错误约占 10%–20%。

## 7. 局限性与不足

- **数据规模有限**：仅 14 名参与者的工作流记录，虽然任务数不少，但参与者多样性、职业领域覆盖不足，可能使偏好对齐和任务模式偏向特定人群。
- **外部服务模拟的失真**：对不可恢复的第三方服务（邮件、日历、数据库等）使用 simulator agent 模拟，模拟响应可能与真实服务行为存在分布偏移，影响评测的真实性。
- **重建过程中的人为偏差**：任务指令由 LLM 根据原始 worklog 推断生成，并经人工校验重建；这一过程可能引入对“原始意图”的猜测误差，不完全是真实用户原话。
- **评分依赖 LLM 判断**：Workspace Score、Preference Score 均基于固定提示的 GPT-5.5 对最终工作区与偏好提示的比对，LLM 评分的偏差和噪声未做严格校准（例如未与人类评分者计算一致性系数）。
- **未考察记忆写入的副作用**：所有记忆组件均默认“历史任务可被写入记忆”，未量化记忆写入对在线性能（时间、token 消耗）的影响，也未比较不同写入策略（如每步写 vs 任务结束后写）的差异。
- **缺少跨 harness 验证**：全部实验基于 Codex harness，记忆组件的效果可能因 agent 框架而不同，结论外推需谨慎。
- **经济成本高**：约 $200/模型-harness 配置，扩展模型数、任务数时成本线性上升，限制了大规模评测的可行性。

## 8. 个人思考与启示

- **记忆评测应以下游任务成功率为核心**：ContextWeave 的方式——把历史记忆作为“条件变量”而非直接打分对象——更具实践说服力，是未来记忆评测的可行范式。
- **摘要型记忆的失效并非偶然**：真实工作流中的技能性知识高度依赖时序和操作细节，摘要化会丢失“如何做”的关键信息；记忆系统设计应保留结构化事件序列与工具调用记录，而不仅是语义浓缩。
- **偏好对齐是记忆的“杀手级场景”**：在重复性任务中，用户成熟的工作风格比正确性更难模仿，记忆若能捕捉并通过演示（ICL）传递偏好，会带来远大于信息检索的业务价值。
- **“记忆注入”只是第一步，模型的使用能力是瓶颈**：实验中出现的“召回相关却不用”现象提示，我们需要更好的记忆-推理接口（如主动查询、逐步验证记忆可信度），或通过微调强化 agent 对记忆的跟随能力。
- **评测成本仍需优化**：$200/配置的成本不低，未来可考虑用子集采样、分层评分或轻量化代理指标来降低复现门槛。
- **对智能体产品设计的迁移价值**：长期使用的 agent（如个人助理、IDE 助手）应把记忆视为与任务执行同等重要的模块，并显式区分“事实性记忆”和“操作性记忆”，前者用于问答，后者用于模仿与习惯对齐。

- **Preference Score**：产出与参与者个人写作风格、格式习惯、内容偏好匹配程度的评分。
- **Win Rate**：有记忆条件下输出被偏好判为优于无记忆条件的比例。
- **Summary-based memory**：仅存储对话/任务摘要的记忆组件。
- **ICL experience memory**：将具体操作经验作为上下文示例注入提示的记忆组件。
- **Trajectory alignment**：将重建轨迹整理为与真实 worklog 最终状态一致的过程，确保下游任务起点可控。
- **Recall-Solvable**：有记忆仍未完成任务中，可由已召回信息直接解决的问题占比。
