## 摘要
GUI代理必须记住早期任务中的有用经验以及当前交互中未完成的进度。潜在记忆通过将多模态轨迹压缩为几个连续令牌提供了一种紧凑的解决方案。然而，现有方法通常将每个轨迹映射到一个固定的记忆块，并主要通过下一动作监督来训练。这产生了三个实际问题：压缩过程中可能丢失重要细节，同一记忆块必须服务不同的决策阶段，以及不相关的检索轨迹仍可能误导代理。我们引入了FocusMem，它在紧凑的潜在记忆接口内分离这些职责。角色感知的内容基础鼓励情景记忆保留可复用的经验，工作记忆保留任务进度。状态条件的读出为相同的存储证据生成特定于决策的视图，而轻量级信任门可以抑制与当前步骤似乎不相关的记忆块。所有组件均在GUI策略冻结时训练。在五个GUI代理基准测试中，FocusMem始终优于完全匹配的仅动作固定记忆基线和先前的潜在记忆适应方法。进一步分析表明，语义和功能监督保留了互补信息，状态条件的读出在周围轨迹上下文增长时更加鲁棒，信任门减少了注入不相关情景证据所造成的损害。这些结果表明，有效的潜在记忆不仅依赖于压缩过去的交互，还依赖于保留什么、暴露什么以及允许什么。

## Abstract
GUI agents must remember both useful experience from earlier tasks and unfinished progress in the current interaction. Latent memory offers a compact solution by compressing multimodal trajectories into a few continuous tokens. Existing methods, however, usually map each trajectory to one fixed memory block and train it mainly through next-action supervision. This creates three practical problems: important details may be lost during compression, the same memory block must serve different decision stages, and irrelevant retrieved trajectories may still mislead the agent. We introduce FocusMem, which separates these responsibilities within a compact latent-memory interface. A role-aware content basis encourages episodic memory to retain reusable experience and working memory to retain task progress. A state-conditioned readout generates a decision-specific view of the same stored evidence, while a lightweight trust gate can suppress memory blocks that appear irrelevant to the current step. All components are trained while the GUI policy remains frozen. Across five GUI-agent benchmarks, FocusMem consistently outperforms a fully matched action-only fixed-memory baseline and prior latent memory adaptations. Further analysis shows that semantic and functional supervision preserve complementary information, state-conditioned readout is more robust as surrounding trajectory context grows, and the trust gate reduces the harm caused by injected irrelevant episodic evidence. These results show that effective latent memory depends not only on compressing past interaction, but also on what is retained, what is exposed, and what is allowed.

# FocusMem 论文详细中文总结

## 1. 核心问题与研究动机

GUI（图形用户界面）智能体在完成任务时需要两种互补的时序记忆：

- **情景记忆（Episodic Memory）**：从已完成任务中提取可复用的经验。
- **工作记忆（Working Memory）**：维护当前会话中的约束、进度与中间状态。

现有方案存在三类瓶颈：
- **文本记忆**紧凑可解释，但丢失视觉/程序性细节；
- **结构化多模态记忆**信息丰富，但重新插入大量截图与文本会消耗过多输入令牌；
- **潜在记忆（Latent Memory）** 将多模态轨迹压缩为连续令牌，是当前最紧凑的接口。

然而，现有潜在记忆方法通常把每条轨迹映射为一个**固定、与状态无关的记忆块**，并仅通过下一动作预测目标训练，导致三个实际缺陷：
1. **内容可恢复性不足**：压缩瓶颈可能丢失关键决策证据；
2. **读出适配性差**：同一固定记忆块难以满足不同决策阶段对同一证据不同部分的需求；
3. **证据信任缺失**：检索到的无关/不匹配轨迹若被强行注入策略，会误导智能体。

作者提出 **FocusMem**，主张有效潜在记忆不仅依赖压缩，更取决于**保留什么（content）、暴露什么（readout）、允许什么（trust）**，并将这三项职责在紧凑的潜在记忆接口内显式解耦。

## 2. 方法论：FocusMem 的核心思想与关键技术

### 2.1 总体框架

- 保留冻结的 GUI 策略（Qwen3-VL-8B），仅训练记忆通路。
- 证据来源：
  - **情景记忆**：检索到的完整已成功轨迹（每条轨迹作为一个证据项）；
  - **工作记忆**：当前会话过期前缀按 W=4 事件切块（每个块作为一个证据项）。
- 每个证据项被压缩为 K=8 个潜在令牌块，注入策略上下文，供冻结策略预测动作。

### 2.2 角色感知内容基（Role-Aware Content Basis）

- 共享编码器 + Q-Former 风格压缩器，但使用**角色专属基础查询**：
  \[
  Z^{\text{fixed}}_i = C_\Phi(s_i; Q^{r_i}_0) + e_{r_i},
  \quad r_i \in \{\text{epi}, \text{work}\}
  \]
- 对每个记忆块施加两类监督：
  - **语义 KL 损失**：用冻结策略在原始证据与压缩块上的下一个 token 分布做 KL 散度，保留可语言化的一般轨迹内容；
  - **功能损失**：按角色生成伪目标——情景记忆强调可复用决策/程序/约束，工作记忆强调状态变化/进度/剩余约束，并要求从压缩块重建这些目标。
- 目标函数：
  \[
  \mathcal{L}_{\text{basis}} = \lambda_{\text{sem}}\mathcal{L}_{\text{sem}} + \lambda_{\text{func}}\mathcal{L}_{\text{func}}
  \]

### 2.3 状态条件读出（State-Conditioned Readout）

- 固定基础查询不随决策状态变化，无法满足不同决策阶段的不同信息需求。
- 引入轻量级状态-证据适配器 \(A_\eta\)，由当前决策状态 \(u_t\)、证据项摘要 \(\text{Pool}(H_i)\) 和角色向量生成**残差查询**：
  \[
  \Delta Q_{t,i} = A_\eta(u_t, \text{Pool}(H_i), e_{r_i}), \quad Q_{t,i} = Q^{r_i}_0 + \Delta Q_{t,i}
  \]
- 再用 \(Q_{t,i}\) 重跑压缩器，得到**动态记忆块**：
  \[
  Z^{\text{dynamic}}_{t,i} = C_\Phi(s_i; Q_{t,i}) + e_{r_i}
  \]
- 适配器输出零初始化，使优化起点与内容基阶段一致。

### 2.4 证据信任门（Evidence Trust Gate）

- 增加轻量级门控模块 \(T_\xi\)，对每个动态记忆块打分：
  \[
  g_{t,i} = T_\xi\left(u_t, \text{Pool}(Z^{\text{dynamic}}_{t,i})\right)
  \]
- 推理时，仅当 \(\sigma(g_{t,i}) > \gamma\)（阈值在验证集上选取）才保留该块；
- 训练时使用直通 HardConcrete 掩码，并注入高置信度无关情景项作为负样本：
  \[
  \mathcal{L}_{\text{gate}} = -\sum_{i \in \mathcal{N}_t} \log(1 - \sigma(g_{t,i}))
  \]
- 门控梯度在记忆块处截断，避免直接重塑内容。

### 2.5 两阶段优化

- **Stage A**：冻结策略下仅优化内容基（固定查询），联合动作模仿损失 + 内容监督损失；
- **Stage B**：从 Stage A 初始化，启用动态读出与信任门，联合动作模仿损失 + 门控损失；
- 整个 GUI 策略保持冻结。

## 6. 主要结论与发现

1. **FocusMem 全面领先**：Overall 成功率 48.3%，比 Action-only Fixed 基线提升 +10.8~+18.0 点，比 Mem-W-style 提升 +4.5~+8.0 点，比无记忆 Qwen3-VL-8B 平均提升约 20 点。
2. **三个解耦组件均有价值**：内容基 +5.0、动态读出 +4.0、信任门 +4.5 点（MMInA-Shopping 累积消融）；总收益不是由单一机制主导。
3. **语义与功能监督互补**：仅语义监督提升通用轨迹重构，仅功能监督提升角色对齐信息；两者联合在每个指标上最优。
4. **状态条件读出随上下文增长更鲁棒**：固定读出在 Oracle Core 到 Full trajectory 之间准确率下降 22–25 点，而动态读出仅下降 6–12 点；潜在预算增大时动态读出的优势进一步扩大。
5. **动态读出确实依赖检索值**：破坏查询与值对应关系后增益几乎消失，表明不是“只靠状态也能成功”。
6. **信任门有效抑制无关证据**：最大污染下（3/3 情景轨迹被替换），FocusMem 仍比无门变体强 9–11 点，门控放行率从 86% 降至 35%。

## 7. 优点与亮点

- **问题刻画清晰**：将潜在记忆的缺陷提炼为“内容可恢复性—读出适配性—证据信任”三个正交维度，并分别设计对应模块。
- **方法设计简洁有效**：在冻结策略的前提下，仅通过角色查询、动态查询残差和块级门控实现三项分工，训练稳定（零初始化、两阶段）。
- **实验匹配度高**：专门的“Action-only Fixed”基线完全匹配除分解组件外的所有设置，能够干净地归因增益。
- **诊断设计有深度**：内容探测（Semantic/Aligned/Transfer）、Oracle 证据扩展、证据依赖干预、污染分析等多角度验证组件功能，不止于端到端得分。
- **推理效率较好**：尽管单步耗时增加 1.70×，但更少执行步骤使总耗时仅增加 1.51×，且内存仅最多 48 个潜在令牌。

## 8. 不足与局限

- **主干与场景覆盖有限**：仅用冻结 Qwen3-VL-8B 策略在网页基准评估，未覆盖移动端、桌面端或其他策略主干；
- **信任诊断较理想化**：仅使用人工确认的“明显无关”情景轨迹作为污染，未覆盖更微妙的不匹配、过期工作记忆或部分相关证据的情形；
- **评测者偏差**：所有成功判断依赖 Gemini-3.1-Pro，尽管固定提示且方法盲评，仍无法完全消除 LLM 裁判偏差；
- **统计显著性缺失**：多数结果来自单次运行，没有报告多次运行的均值/方差或显著性检验；
- **情景记忆库为域内演示**：No Memory 基线只作为“系统级参考”，而非严格对照，若记忆库与评测任务分布差异更大时性能如何未知；
- **人工标注环节**（Oracle Core 定位、污染轨迹选择）可能引入标注者主观性，未见标注一致性报告。
