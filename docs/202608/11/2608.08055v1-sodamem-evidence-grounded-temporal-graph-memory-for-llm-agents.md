## 摘要
在数周对话中协助用户的大型语言模型（LLM）智能体必须记住当前真实的情况，而不仅仅是曾经说过的话。扁平化的RAG日记和Markdown日志优化了针式检索，但在时效性、来源追溯和有序时序推理方面表现不足（Maharana等，2024；Wu等，2024；Packer等，2023；Chhikara等，2025）。我们提出SodaMem，一种证据基础的时序图记忆，它（i）提取带有强制来源片段的有类型事实事件，（ii）在混合词汇-稠密索引下持久化提及时间、发生时间和有效性，并建立SUPERSEDES/CONTRADICTS/UPDATES边，（iii）通过规划器-阅读器循环进行回答，在生成最终响应前收集可引用证据。在LongMemEval-S上，我们的记录存储配置在平均每次查询0.00161美元（约18.3k个标记；中位数0.00111美元/约14.6k个标记）的成本下达到92.8%的准确率（464/500；N=3中最佳），使用deepseek-v4-flash。我们将具有可估算API成本的公开系统汇编成成本表和成本-准确率图；在这些估算下，SodaMem在Flash级支出下接近准确率前沿，并严格支配多个高成本、低准确率的点。准确率使用与读者和评判者相同的Flash模型（自评分）；成本不包括摄取/评判，跨系统比较是基于汇编估算，而非单一测试框架的对比实验。我们的代码可在https://github.com/SodaMem/SodaMem获取。

## Abstract
Large language model (LLM) agents that assist users over weeks of conversation must remember what is currently true, not merely what was once said. Flat RAG diaries and Markdown logs optimize needle retrieval but under-serve currency, provenance, and ordered temporal reasoning (Maharana et al. 2024; Wu et al. 2024; Packer et al. 2023; Chhikara et al. 2025). We present SodaMem, an evidence-grounded temporal graph memory that (i) extracts typed FactEvents with mandatory provenance spans, (ii) persists mention time, occurrence time, and validity with SUPERSEDES/CONTRADICTS/UPDATES edges under hybrid lexical-dense indexing, and (iii) answers via a planner-reader loop that gathers citable evidence before composing a final response. On LongMemEval-S, our store-of-record configuration reaches 92.8% accuracy (464/500; best of N=3) at mean $0.00161/question (approximately 18.3k tokens; median $0.00111 / approximately 14.6k) with deepseek-v4-flash. We compile public systems with estimable API cost into a cost table and cost-accuracy map; under these estimates SodaMem sits near the accuracy frontier at Flash-tier spend and strictly dominates several higher-cost, lower-accuracy points. Accuracy uses the same Flash model as reader and judge (self-grading); costs exclude ingest/judge and cross-system comparisons are compiled estimates rather than a single-harness bake-off.Our code is available at https://github.com/SodaMem/SodaMem

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：LLM 智能体在长期（数周甚至更久）的对话陪伴场景中，必须记住**“当前真实的状态”**，而不仅仅是“曾经说过的话”。传统方案（扁平 RAG、Markdown 日志、向量库）擅长“从文本中找一个事实”（needle retrieval），但在**时效性（currency）**、**来源追溯（provenance）**和**有序时间推理（ordered temporal reasoning）**上存在系统性缺陷。
- **四个具体失败模式**：
  - **(P1) 时效性/冲突**：偏好或事实会反转（如“我爱吃辣”→“我在戒辣”），追加式日志不维护“哪个值才是当前值”，导致过时信息被错误召回。
  - **(P2) 时间结构**：“最近”“几个月前”等相对时间短语缺乏可比的时间线，导致排序类（“most recently”）和时间推断类问题难以回答。
  - **(P3) 来源追溯**：无引用的压缩摘要和不透明的向量命中破坏了可信度与审计能力。
  - **(P4) 关联性**：多跳综合需要实体/主张级别的关联（beyond cosine neighbors），而仅靠向量相似度容易召回到“场景错误但表面相似”的记忆，造成上下文坍塌。
- **论文立场**：将记忆视为**证据基础的时序知识图谱（evidence-grounded temporal knowledge graph）**——即带来源片段、时间轴（提及/发生/有效性）和 SUPERSEDES/CONTRADICTS/UPDATES 边的类型化事实事件，配合规划器-阅读器（planner-reader）循环，在生成最终回答前先收集可引用证据。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **总体架构**：SodaMem 是一个三段式流水线：**Ingest（摄取）→ Store（存储与检索）→ Answer（回答）**，将系统分解为公式（1）–（3）：
  - Mut = Ingest(Hu)
  - E = Retrieve(q, Mut)
  - a = Read(q, E)

### 2.1 Ingest：从对话到 FactEvents

- **FactEvent 定义**：f = (κ, π, m, τ, ρ, S, σ)，分别表示：类型 kind、谓词 predicate、模态 modality、时间字段 τ、实体角色 ρ、来源片段 S（MessagePieces）和状态 σ（active / superseded / invalid）。
- **提取约束**：LLM 提取候选 FactEvent 时，必须引用源对话 turn 中**字面出现的片段（spans）**；凡是不落在源 turn 内的候选直接拒绝——这是**来源硬约束**。
- **确定性后处理**：模态归一化、日期绝对化，并以会话时间 ts 作为提及时间锚点。可选实体主体提示以减少“star-graph collapse”（所有事实都挂到 user 实体上）。
- **时间线解析层（可选）**：对相对时间短语（“two months ago”）通过公式（4）τ̂(f) = T(τraw(f), ts(f), context(f)) 解析为可比时间戳；不能解析的标记为 unresolved。查询时单独解析时间意图（W, δ）。

### 2.2 Store：混合索引与图关系

- **持久化**：SQLite 存储事实，配稠密向量（MiniLM/GTE 类）和 BM25 索引，覆盖事实文本、片段和原始 turn。
- **边类型**：
  - 提及/来源边（mention / DERIVED FROM）；
  - 语义关系边：SUPERSEDES（取代）、CONTRADICTS（矛盾）、UPDATES（更新）；
  - 检索用扩展边：语义边（内容驱动的邻居链接）和关系类型边（实体间的类型化谓词）。
- **写入语义**：默认产品模式下写入时自动写入 supersession（取代关系）；只读冻结存储作为实验轴。

### 2.3 Retrieve：多通道召回 + 连接密度融合

- **查询分析**：将 q 解析为实体提及、词法键、嵌入查询和时间意图 (W, δ)。模糊时间线索映射为宽窗口（宁可召回多也不要漏），缺失时间线索则禁用时间奖励。
- **三条检索通道**：
  1. **图/实体通道（强）**：以实体或事实为搜索头，沿语义/关系边扩展 1 跳或多跳，应用有效性过滤和软时间评分；
  2. **BM25 通道（强）**：词法命中事实/片段/原始 turn，片段命中的相邻片段和父 turn 一并带回，turn 命中扩展相邻 ±2 turns；
  3. **嵌入通道（弱）**：稠密近邻，扩展模式同 BM25，但基础权重更低（因为相似度可能召回“相关但场景错误”的片段）。
- **有效性硬门控**：状态为 invalid/superseded-as-inactive 的内容，或与查询窗口 W 明确不兼容的已知有效性区间，被硬性排除——这是唯一的硬时间/状态过滤；发生时间不匹配不会丢弃高密度候选。
- **连接密度与排序信心**：每个 (通道, 搜索头, 命中) 赋予一个质量权 w（默认：强直接 0.4，弱直接 0.2，强派生 0.1，弱派生 0.05）；多个头命中同一证据 ID 或嵌入相似度 ≥ θ（默认 0.8）时质量累加。公式（5）–（6）：
  - density(i) = Σ_{h∈H(i)} wh
  - conf(i) = density(i) + β·1[i ∩ W ≠ ∅]（β 默认 0.3，同一合并项最多奖励一次）
- **融合**：按 ID/相似度合并各通道列表，重算 conf，按 δ 排序输出唯一化证据池。

### 2.4 Answer：规划器–阅读器循环

- **规划器（Planner）**：在步骤预算内可调用工具（search、inspect、session expand、timeline、count、compute），针对密度排序不足的场景（如显式枚举）扩展证据池（Algorithm 3）。
- **阅读器（Reader）**：用独立提示从选定证据 ID 编排出面向用户的回答，**强制附带引用**——将引用纪律与工具策略解耦。

- **SodaMem 配置**：实体主体（entity-subject）store-of-record 设置，500 个用户、235,840 个事实；规划器、阅读器和评判者均为 deepseek-v4-flash；使用 LongMemEval 官方 yes/no 模板。
- **对比方法**（约 20 个公开系统，按准确率排序）：

  - 同档/低分阵营：Cersei Full-context（87.6%）、Cersei Embed（86.6%）、Cersei Hybrid（86.3%）、AgentOS（85.6%）、LC GPT-5-mini（82.4%）、EmergenceMem Simple Fast（79.0%）、MemOS、TiMem、Memobase、Zep、Supermemory、MemoryOS、A-MEM、Fact-Mem0、MemU、MemoryBank 等（58%～78% 区间）。
- **评估指标**：准确率（accuracy）和每次查询 API 成本（$/10³ questions）。成本来源包括作者报告的 USD、披露 token 数按 2026 年列表价估算、以及 recalled context length 加输出 token 的下界估算。

## 6. 主要结论与发现

1. **成本-准确率前沿位置**：SodaMem 以 Flash 级成本（约 $0.0016/问题）达到 92.8% 准确率，接近 Opus/GPT-4o 级高成本系统的精度，成本低约 **10–40 倍**。
2. **严格支配区域**：Cersei（三个变体）、AgentOS、long-context GPT-5-mini、EmergenceMem Simple Fast、MemoryBank 等系统处于“更高成本 + 更低准确率”的被支配象限；若按中位数成本计算，MemoryOS 和 Fact-Mem0 read 也进入被支配区。
3. **中位数与平均数的差异**：平均成本被长尾拉高，中位数成本（$0.00111）比平均数低约 25%，说明“典型查询”实际比平均账单更便宜。
4. **准确性提升往往来自读取器升级**：公开数据表明一些系统的精度跃升（如 Mastra 从 84.23% 到 94.87%）主要源于读取模型更换，而非记忆架构本身——SodaMem 主张在同等（低）模型规格下通过记忆结构取胜。
5. **剩余失败**：主要 miss 集中在时间推理任务（self-grading 下），驱动了 ingest 端会话锚定时间线解析的动机。

## 7. 优点

- **问题框架清晰**：将长期记忆挑战提炼为 P1–P4 四个可测试的失败模式，并逐一给出机制对应。
- **证据硬约束**：强制来源片段 + 阅读器强制引用，使回答可审计、可追踪，显著增强信任度。
- **三维时间轴设计**：mention / occurrence / validity 分离，配合软时间评分（时间作为排序特征而非硬过滤器），兼顾

兼顾“软性过滤”（不因时间戳不匹配而丢弃高密度记忆）与“硬性约束”（已知无效区间硬排除），在召回完整性与时效准确性之间取得平衡。
4. **多通道融合的设计务实**：图/实体、BM25、嵌入三通道各司其职，以连接密度（density）和置信度（confidence）公式进行可解释的融合，且每个通道的权重可调节，便于工程部署时的调优。
5. **成本意识明确**：主动将价格作为一等评估维度，并以中位数/平均数双报告方式呈现成本分布，体现了对实际落地经济性的重视。
6. **规划器–阅读器解耦**：将“找什么证据”（工具调用策略）与“怎么回答”（引用编排）分离，既降低了对单一模型能力的耦合，也使得引用纪律（citation discipline）可以被独立评估和优化。

## 8. 缺陷与局限

1. **自评分偏差风险**：用与阅读器相同的 Flash 级模型做 yes/no 评判，缺乏独立人工或更强模型（如 GPT-4o/Opus）的对照验证。论文虽承认绝对准确率可能漂移，但未提供修正后的数字，导致“92.8%”这一核心数字的可信度打折。
2. **尚无真正消融实验**：摄取成本、时间线解析、扩展边权重、密度阈值（θ=0.8）、时间奖励 β=0.3 等关键超参数均未做敏感性分析；读者无法判断性能来自架构本身还是特定取值。
3. **单基准、单配置**：仅在 LongMemEval-S 上测试一种 store-of-record 配置，缺少跨数据集（如 LOCOMO、MemBench）泛化证据，也缺少对不同用户规模、对话时长的压力测试。
4. **摄取阶段质量未评价**：FactEvent 的提取准确率、supersession 判定的误报率、时间线解析的失败率均未报告；如果摄取阶段注入错误事实或错误取代关系，下游检索质量会系统性受损（garbage-in-garbage-out）。
5. **对比基准不统一**：基线分数与成本来自不同论文、不同协议、不同评判模型，甚至不同时间点的系统版本（如 Mem0 2026 research 引用的是其官方博客数据），跨系统比较的公平性存疑，作者也未提供统一的复测 harness。
6. **成本口径不含摄取与评判**：真实端到端成本（含每日摄取和评测）被排除在外，可能低估系统整体开销；规划器的多轮工具调用 token 也被“下界估算”掩盖。
7. **时间语义仍有未解问题**：对 unresolved 的提及时间、跨时区会话、用户主动纠正旧记忆等边角情况处理策略阐述不足；P2 时间结构问题在 ingest 端解析失败时的兜底机制不清晰。

- **对读者的启示**：
  1. 记忆系统的瓶颈正从“召回什么”转向“如何证明召回的是当下正确的”，证据引用与时间有效性将成为标配；
  2. 低成本记忆架构（Flash 级模型 + 结构化索引）可以逼近高成本长上下文或强模型方案，说明“记忆管理”比“模型能力”在长对话场景中更具杠杆效应；
  3. 评估上应警惕自评分幻觉，建议引入独立评判者与统一成本计价管线，否则“高准确率 + 低成本”的结论容易被放大。

## 10. 总体评价

SodaMem 是一篇工程风格鲜明的预印本：它把 LLM 智能体的长期记忆明确定义为“证据可追溯的时序知识图谱”，并给出了一套实现完整、机制对应清晰的三段式流水线（摄取→存储→回答）。在方法论层面，其对四类失败模式（P1–P4）的诊断和逐条机制回应具有较强说服力；在实验层面，虽然规模偏小、对比公平性存在瑕疵，但 92.8% 准确率与约 $0.0016/问题的成本组合仍足以证明其核心主张：**通过结构化记忆和证据纪律，Flash 级模型可以在长期对话记忆任务上逼近乃至追平昂贵模型的水平**。作为预印本，其结论在独立复测前应被视为“强参考”而非“定论”；其最大价值在于提供了一个清晰的可复现架构与量化成本框架，有望推动记忆系统评估从“只看准确率”走向“准确率 + 可审计性 + 成本”的多维标准。
