## 摘要
基于LLM的智能体越来越依赖外部记忆来支持长时推理和交互。然而，主要瓶颈不仅仅是存储过往经验，而是在相关信息分散于多次交互中时，恢复正确的证据集。现有方法难以应对这一访问问题。全上下文方法需要嘈杂的长上下文检索，扁平检索往往返回孤立且不完整的记录，而基于图的记忆系统构建成本高昂且压缩了丰富的事件上下文。我们提出RippleMem，一种长期记忆系统，用自适应联想回忆替代一次性检索。受线索依赖的情景回忆和联想完成的启发，RippleMem将交互历史存储为富含线索的情景记忆单元，并将其组织在事件中心的记忆图中。给定查询时，它首先通过混合线索回忆相关记忆锚点，然后沿着语义和结构关联从这些锚点扩展，以恢复缺失的支持证据。这样，最初回忆的记忆不仅作为答案上下文，还作为完成回答所需证据的线索。在LoCoMo和LongMemEval-S上的实验表明，RippleMem在所评估的设置中取得了最佳整体性能，在LoCoMo上将LLM-as-a-Judge准确率提高了3.95%，在LongMemEval-S上提高了11.87%，同时将图构建成本降低了约30倍。

## Abstract
LLM-based agents increasingly rely on external memory to support long-horizon reasoning and interaction. However, the main bottleneck is not simply storing past experience, but recovering the right set of evidence when relevant information is distributed across many interactions. Existing approaches struggle with this access problem. Full-context methods require noisy long-context search, flat retrieval often returns isolated and incomplete records, and graph-based memory systems can be expensive to construct while compressing rich event context. We introduce RippleMem, a long-term memory system that replaces one-shot retrieval with adaptive associative recollection. Inspired by cue-dependent episodic retrieval and associative completion, RippleMem stores interaction history as cue-rich episodic memory units and organizes them in an event-centric memory graph. Given a query, it first recalls relevant memory anchors through hybrid cues, then expands from these anchors along semantic and structural associations to recover missing supporting evidence. In this way, initially recalled memories serve not only as answer context, but also as cues for completing the evidence needed to answer. Experiments on LoCoMo and LongMemEval-S show that RippleMem achieves the best overall performance across evaluated settings, improving LLM-as-a-Judge accuracy by 3.95% on LoCoMo and up to 11.87% on LongMemEval-S, while reducing graph construction cost by about 30x.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想
RippleMem将记忆访问从一次性匹配转向**自适应联想回忆（adaptive associative recollection）**。其名称寓意“涟漪扩散”——从初始接触点出发，沿局部关联逐层扩散，恢复缺失证据。设计受认知科学中事件分段（event segmentation）、线索依赖回忆（cue-dependent retrieval）和模式完成（pattern completion）等理论的启发。

### 2.2 写阶段（Write Phase）

**（1）线索丰富的情景记忆构建（Cue-Rich Episodic Memory Construction）**

- 将对话历史按滑动窗口切分，窗口间保留局部重叠以维持连续性；
- 通过架构引导的LLM提取器，从每个窗口提取JSON格式的记忆单元，每个单元遵循固定架构：
  \[
  m_i = (r_i,\ v_i,\ P_i,\ L_i,\ T_i)
  \]
  - \(r_i\)：规范化的事件重述（可独立于原对话窗口理解）；
  - \(v_i\)：\(r_i\)的稠密向量表示；
  - \(P_i, L_i, T_i\)：参与者、地点、时间线索或时间区间。
- 提取器被要求消除代词指代、锚定相对时间、拆分多事件窗口；无法可靠接地时字段留空而非臆造。

**（2）事件中心记忆图（Event-Centric Memory Graph）**

- 构建稀疏加权事件图 \(G = (M, E)\)，其中节点为记忆单元，边为语义关联与结构关联两类带权边。
- **语义关联**：计算重述向量间的余弦相似度：
  \[
  s_{\text{sem}}(i,j) = \cos(v_i, v_j)
  \]
- **结构关联**：计算参与者、地点、时间三类线索的兼容度：
  - 参与者与地点使用Jaccard重叠；
  - 时间线索：重叠区间得1分，非重叠时按指数衰减：
  \[
  u_{T}^{ij} = \begin{cases} 1, & T_i \cap T_j \neq \emptyset \\ \exp(-\Delta(T_i,T_j)/\tau), & \text{otherwise} \end{cases}
  \]
  - 聚合为：
  \[
  s_{\text{str}}(i,j) = \frac{\sum_{x \in \{P,L,T\}} \beta_x I_x u_x^{ij}}{\sum_{x \in \{P,L,T\}} \beta_x I_x}
  \]
- **稀疏增量构建**：新记忆插入时，从语义近邻和线索索引中获得受限候选池，按阈值和度数上限（K_sem、K_str）保留边，避免全图两两计算，控制成本。

### 2.3 读阶段（Read Phase）

**（1）混合初始召回（Hybrid Initial Recall）**

- 从查询中提取语义、词汇、结构化线索，实施三种互补召回视图：
  \[
  C_0 = C_{\text{sem}} \cup C_{\text{lex}} \cup C_{\text{cue}}
  \]
- 当前证据状态初始化为 \(C \leftarrow C_0\)。

**（2）记忆锚规划（Memory-Anchor Planning）**

- 调用架构约束的回忆控制器 \(\Pi_{\text{rec}}\)：
  \[
  (d_r,\ A_r,\ g_r,\ s_r) = \Pi_{\text{rec}}(q,\ c_q,\ C)
  \]
  - 输出：是否继续（\(d_r\)）、所选锚点（\(A_r \subseteq C\)）、缺失支持目标（\(g_r\)）、停止原因（\(s_r\)）。
  - 控制器只从当前证据中选取**少量最佳锚点**（而非所有相关记忆），并生成一个**缺失证据描述目标**（而非最终答案）。

**（3）锚定局部扩展（Anchor-Local Expansion）**

- 仅从所选锚点在受限图邻域内扩展：
  \[
  U_r = \{ m \in M \setminus C \mid d_G(m, A_r) \leq h \}
  \]
- 分别沿语义边和结构边收集候选，按缺失目标进行语义匹配和结构匹配，两通道结果按记忆身份合并，更新 \(C \leftarrow C \cup S_r\)。
- 候选得分相近时，偏好离锚点更近、路径权重更高的记忆。
- 循环持续直到证据充分、无新增支持或达到轮次预算（默认 \(R=1\)）。完整流程见Algorithm 1。

### 2.4 证据整合（Evidence Assembly）

- 按记忆单元身份去重并合并来源信息；
- 对记忆进行确定性排序，得分函数：
  \[
  \rho(m) = \lambda_q a(q,m) + \lambda_p \pi(m) + \lambda_a I_{\text{anc}}(m)
  \]
  - 融合查询-记忆语义对齐、检索来源排名/分数/扩展路径支持和锚点状态；
- 取Top-K（固定预算）构成最终证据上下文，交由答案生成器作答。

## 6. 主要结论与发现

1. **一致性整体增益**：RippleMem在LoCoMo和LongMemEval-S上均取得最佳综合性能。LoCoMo上F1相对提升3.98%，BLEU-1相对提升3.62%，评判准确率相对提升3.95%；LongMemEval-S上达到84.80%和86.60%的准确率。
2. **证据分布型问题增益更大**：多跳与时序类问题提升最明显（时序问题在SimpleMem基础上提升了5.45个F1点和9.66个评判准确率点），符合联想回忆的设计意图。
3. **有根据的回忆（grounded recollection）比单纯增加关联或迭代更有效**：在匹配记忆单元和证据预算的条件下，RippleMem仍优于RF-Mem等关联式基线。
4. **图扩展贡献最大**：消融显示移除图扩展导致最大的准确率下降（87.14→83.12），说明首跳召回常遗漏关键支持证据。
5. **高效的阶段权衡**：在构建成本降低约30倍的前提下取得最优效果，展示了持久记忆构建、答案时间上下文大小和下游有效性之间的有利平衡。

## 7. 优点

- **问题定义深刻**：将长期记忆瓶颈从“存储”转向“证据恢复”，并明确刻画了两类失败模式（直接查找过早停止、未定向关联遗漏安全约束），具有较强的洞察力和通用价值。
- **认知启发与工程实用的平衡**：借鉴事件分段、线索依赖回忆、模式完成等认知理论，但明确声明作为“设计直觉”而非机制性模仿，保持了系统的实用性。
- **双通道图关联**：语义关联与结构关联互补，能召回“措辞不同但共享参与者/地点/时间”的相关记忆，增强了访问鲁棒性。
- **有规划的锚定扩展**：回忆控制器明确规划“锚点”和“缺失目标”，使扩展有导向性而非盲目遍历，避免了无向图传播常见的“相关但不支持”问题。
- **成本控制出色**：稀疏图构建 + 受限邻域扩展 + 固定轮次预算，在性能最优的同时大幅降低构建成本。
- **公平性实验设计**：对RF-Mem采用匹配记忆单元和预算的控制设置，能有效隔离访问策略本身的贡献；对MemPalace采用对齐配置对比，增加了结论可信度。
- **对抗性分析完备**：专门针对无支持问题分析回忆控制器的行为，展示了系统在证据不足时能保守验证而非强行作答。

## 8. 不足与局限

- **模态覆盖有限**：仅评估文本对话记忆；不涉及多模态交互、具身智能体或工具使用场景，记忆可能包含视觉观察、动作状态等，这些场景下的联想回忆有效性尚未验证。
- **LLM调用的延迟与成本**：记忆提取、查询分析、回忆规划等均依赖LLM操作，相比单次检索增加延迟和API成本；虽然部分组件可缓存/批处理，但端到端效率仍有提升空间。
- **长期增长场景压力测试不足**：现有benchmark对持续增长的个人记忆（更长的时间线、用户状态演化、记忆老化、隐私删除）缺乏充分压力测试。
- **图结构依赖固定超参**：语义/结构边阈值、度数上限、候选池大小等均需预设，不同对话分布可能影响最优设置，泛化性有待进一步验证。
- **回忆控制器质量依赖LLM**：控制器输出的锚点与缺失目标质量直接决定扩展效果，而论文未深入分析规划错误造成的级联失败案例。
- **评估基准的数据量有限**：LongMemEval-S仅500问题，EverMemBench在附录中，主benchmark规模与多样性相对有限。
