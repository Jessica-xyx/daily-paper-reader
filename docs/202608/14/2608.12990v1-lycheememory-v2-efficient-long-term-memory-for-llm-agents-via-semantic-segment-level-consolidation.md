## 摘要
长时程LLM智能体必须保留过去交互的信息以支持未来任务。现有记忆系统通常依赖急切整合，即在每次交互后调用LLM提取、总结或更新记忆。这种设计使得随着对话增长，记忆构建成本越来越高。粗略总结可以降低构建成本，但可能丢失细粒度的上下文证据，而更大的检索上下文或多跳LLM推理则将开销转移到查询时间。我们提出LycheeMemory V2，一个高效的长期记忆框架，用语义片段级整合取代轮次级整合。LycheeMemory不是整合每次交互，而是将多次交换分批成片段，并将每个已完成的片段编码为上下文无关的类型化记忆记录。片段级批处理降低了LLM编码频率，而语义边界检测相比固定窗口批处理有助于保留连贯的事件级和时间证据。生成的记录通过轻量级结构化索引组织，用于查询计划的证据检索。使用GPT-4.1-Mini的实验表明，LycheeMemory达到了最先进的性能，在LoCoMo上达到89.22%，在LongMemEval-S上达到92.20%。与A-Mem相比，它在LoCoMo上将构建令牌减少了86.0%，在LongMemEval-S上减少了75.9%，且没有增加查询时间的令牌使用。更广泛地说，我们的结果表明，长期智能体记忆的准确性-成本权衡不仅取决于保留了什么信息，还取决于整合的粒度。

## Abstract
Long-horizon LLM agents must preserve information from past interactions to support future tasks. Existing memory systems typically rely on eager consolidation, invoking LLMs after each interaction to extract, summarize, or update memories. This design makes memory construction increasingly costly as conversations grow. Coarse summarization can reduce construction cost but risks discarding fine-grained contextual evidence, whereas larger retrieval contexts or multi-hop LLM reasoning shift the overhead to query time. We present LycheeMemory V2, an efficient long-term memory framework that replaces turn-level consolidation with semantic segment-level consolidation. Instead of consolidating every interaction, LycheeMemory batches multiple exchanges into segments and encodes each finalized segment into context-independent typed memory records. Segment-level batching lowers LLM encoding frequency, while semantic boundary detection helps preserve coherent event-level and temporal evidence compared with fixed-window batching. The resulting records are organized with lightweight structured indexes for query-planned evidence retrieval. Experiments using GPT-4.1-Mini show that LycheeMemory achieves state-of-the-art performance, reaching 89.22% on LoCoMo and 92.20% on LongMemEval-S. Compared with A-Mem, it reduces construction tokens by 86.0% on LoCoMo and 75.9% on LongMemEval-S without increasing query-time token usage. More broadly, our results suggest that the accuracy--cost trade-off of long-term agent memory depends not only on what information is retained, but also on the granularity at which it is consolidated.

## 1. 核心问题与整体含义（研究动机与背景）

长期运行的 LLM 智能体（如个人助理、客服系统、任务型对话代理）必须在跨会话、长时程的交互中持续保留用户偏好、历史事件、动态变化的事实与约束。然而，现有主流记忆系统大多采用**急切整合（eager consolidation）**策略：每经过一轮或一小段对话，就调用一次 LLM 对交互进行总结、抽取事实或更新已有的记忆。

这种设计存在一个核心矛盾：
- **逐轮急切整合**虽然语义丰富，但记忆构建成本随对话量线性增长，token 开销急剧膨胀；
- **粗略摘要**可以降低构建成本，但会丢弃细粒度上下文证据（实体、时间表达、指代关系、小细节），导致多跳推理、时间推理等问题上的精度下降；
- **查询时补偿**（如扩大检索上下文、LLM 多跳搜索）虽然能改善召回，却将成本转移到了查询侧。

因此，论文提出的核心问题是：**如何在保留足够细粒度证据的同时，将记忆构建与检索两端的成本都控制在合理范围？** 论文的总体立场是：长期记忆的准确率–成本权衡不仅取决于"保留什么信息"，还取决于"以什么粒度进行整合"（consolidation granularity）。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想
LycheeMemory V2 将记忆构建从**轮次级（turn-level）急切整合**改为**语义片段级（semantic segment-level）整合**：将多条对话批量聚合成语义连贯的片段，仅对"定稿"的片段调用一次 LLM 编码，从而显著降低写入侧 LLM 调用频率，同时通过语义边界检测避免固定窗口切分造成的证据割裂。

### 关键技术细节

**（1）在线语义分段（Online Semantic Segmentation）**
- 每个对话交换（exchange）用 embedding 模型编码；
- 维护当前活动片段的质心向量、最近交换向量、语义新奇度历史、token 长度与交换数；
- 边界分数 \(p_t\) 由以下信号组合并经 sigmoid 归一化得到：
  - **语义惊奇度** \( s_t = 1 - \max(\text{sim}(e_t, c_k), \text{sim}(e_t, h_k)) \)——新交换与片段质心/局部轨迹的偏离程度；
  - **凝聚度下降** \( d_t = \max(0, \text{Coh}(S_k) - \text{Coh}(S_k \cup \{x_t\})) \)——加入新交换后片段内部主题一致性的削弱程度；
  - **token 长度压力**与**交换数压力**——防止片段过长或过短；
- 当 \(p_t\) 超过阈值 \(\delta\)（默认 0.50）或达到硬上限时定稿片段。边界决策完全基于 embedding 与确定性计算，**不消耗 LLM token**。

**（2）片段级记忆编码（Segment-Level Memory Encoding）**
- 对每个定稿片段 \(S_k\)，编码器接收片段文本 + 紧凑的参考上下文 \(\rho_k\)（来自近期片段的消歧状态与记录摘要），输出一组类型化记忆记录 \(R_k\) 与更新后的消歧状态 \(d_k\)；
- 每条记录 \(r_i\) 为 7 元组：(id, 记忆类型, 自包含文本, 实体集, 话题标签集, 时间作用域, 来源溯源链接)；
- 记忆类型覆盖：事实、偏好、事件、约束、流程、失败模式、工具能力；
- 编码提示要求 LLM 在单次调用中同时完成：抽取原子信息、解析指代与省略表达、将相对时间按会话时间戳归一化；
- 跨片段连续性通过有界预算的参考上下文维护，防止提示规模随历史增长。

**（3）结构化证据组织（Structured Evidence Organization）**
- 向量存储（LanceDB）存记录 embedding 用于语义检索；
- 结构化存储（SQLite + FTS5）构建五类证据节点：
  - 实体节点、话题节点、实体-话题联合节点、时间节点（日/月粒度）、事件框架节点（同一语义片段内记录的分组）；
- 此阶段仅需 embedding 与确定性索引操作，无额外 LLM 调用。

**（4）计划引导的多路检索（Plan-Guided Multi-Route Retrieval）**
- 查询时**仅调用一次 LLM 规划器**，将用户问题分解为多个带目标的检索路径（每条路径含检索查询、结构化约束、时间约束）；
- 每条路径并行执行四类召回通道：直接记录召回、证据节点召回、时间过滤召回、原始对话轮次召回；
- 候选经倒数秩融合（RRF）、轻量级 cross-encoder 重排（非生成式）、多样性感知选择后，序列化为最终证据上下文；
- 除规划调用外，所有检索与排序均为 embedding 查询和算术运算，**不产生额外生成式 token**。

## 6. 主要结论与发现

1. **SOTA 准确率**：LycheeMemory 在 GPT-4.1-Mini 下于 LoCoMo 达 89.22%（超过 Full Context 84.80% 与最强基线 TiMem 83.77%），于 LongMemEval-S 达 92.20%（超过最强的 TiMem 75.80%）；GPT-4o-Mini 下同样取得最佳总体成绩（78.90% / 78.80%）。
2. **显著降低构建成本**：与 A-Mem 相比，构建 token 在 LoCoMo 上减少 86.0%（204.1K vs. 1459.9K），在 LongMemEval-S 上减少 75.9%（304.7K vs. 1264.3K）。
3. **不增加查询成本**：LycheeMemory 的查询 token 反而低于 A-Mem（LoCoMo 4.01K vs. 5.56K，-27.9%；LongMemEval-S 8.88K vs. 15.46K，-42.6%）。
4. **消融验证了核心假设**：
   - 段级批处理降低构建成本，但语义边界检测决定准确率提升（固定窗口使准确率掉 6.8 pp）；
   - 类型化结构化记录优于摘要级记录（+8.4 pp）；
   - 多路检索与证据选择栈贡献显著（去掉融合/重排/多样性选择，准确率降 22.6 pp）；
5. **核心启示**：长期记忆的准确率–成本权衡由**整合粒度**这一关键杠杆决定——语义段级整合可在不牺牲证据保真度的情况下大幅降低写入频率，是大型智能体记忆系统的高效设计方向。

## 7. 优点

- **问题定位精准**：明确指出现有记忆系统"让 LLM 做太多事"的根源在于轮次级整合粒度，而不是单纯地压缩存储或简化检索，视角有启发性。
- **成本-质量解耦设计**：将"何时整合"（语义分段，确定性计算）与"如何编码"（一次 LLM 调用）分离，从架构层面同时优化两侧成本。
- **充分的消融体系**：构建侧、表征侧、检索侧三组消融分别隔离了各组件对成本和准确率的独立贡献，论证严密，清晰区分了"批处理省成本"与"语义边界提准确率"。
- **广泛的基线覆盖**：对比了 Full Context、Naive RAG、Mem0、A-Mem、MemoryOS、TiMem、MemOS、Nemori、LightMem、MemU 等十余种方法，涵盖不同设计路线，且两个 backbone 交叉验证。
- **透明度高**：附录提供了完整的 prompt 模板、token 计算规则、参数设置与实现细节，可复现性强。

## 8. 不足与局限

- **仅限文本模态**：论文明确不涉及多模态记忆，无法评估图文、音视频等场景的适用性。
- **偏好追踪仍是短板**：在 LongMemEval-S 的偏好类问题上，GPT-4.1-Mini 下 LycheeMemory 为 90.00%，不如 MemoryOS 的 100.00%；GPT-4o-Mini 下为 70.00%，不如 MemOS 的 96.67%。论文承认专用用户画像/profile 模块可能更具优势。
- **未报告运行延迟、存储占用与工程开销**：虽然 token 成本大幅下降，但数据库延迟、embedding 索引存储、生产环境监控等未评估。
- **依赖托管 API**：实验使用 GPT-4.1-Mini / GPT-4o-Mini 等闭源模型，换成开源模型后能力与 token 统计可能变化，需要在新的评估下重新报告精度与成本。
- **潜在评估偏差**：LLM 法官（GPT-4o-Mini）的偏好与稳定性可能影响结论；未报告多次运行的方差。
- **无增量/在线学习机制**：记录为 append-only 存储，不做近似语义合并或自动过期推断（有意保留历史证据），但这也意味着冲突解决完全依赖查询侧，在长期部署中可能带来额外的推理负担。
- **基准规模有限**：LoCoMo 仅有 10 个对话，结果方差大；LongMemEval-S 虽长但每对话仅一个问题，覆盖的真实应用模式有限。
