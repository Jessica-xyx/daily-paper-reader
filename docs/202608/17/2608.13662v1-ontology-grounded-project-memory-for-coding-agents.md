## 摘要
编码智能体已成为许多软件项目中生成新代码的主要方式，由此产生的变更速度使得追踪这些变更背后的原因变得具有挑战性。本文介绍了 MOOSEDev，一个旨在为编码智能体提供结构化、基于本体的项目记忆的系统。该系统将架构决策、经验教训、约束条件和理由捕获在知识图谱中，并通过模型上下文协议（MCP）接口向智能体暴露。记录带有生命周期状态、来源和替代链接，可通过 MOOSE 查询，MOOSE 是一种专有的神经符号引擎，将符号层作为主要推理基础。我们在包含 835 条类型化记录的中立公开语料库上，将 MOOSEDev 与生产级向量记忆工具进行了比较。MOOSEDev 在替代、集合完整性和否定问题上几乎完整地返回了预期答案集（0.98-1.00），而基线模型的 top-k 检索仅返回了 6% 到 27%。相反，相关召回的准确性和 token 成本在两个系统之间大致相当。我们还描述了自身代码库的时间性提交历史引导、预注册的现场试验以及经验教训。

## Abstract
Coding agents have become the primary means of generating new code in many software projects, and the resulting velocity of changes makes keeping track of the reasons behind those changes challenging. This paper introduces MOOSEDev, a system designed to give coding agents structured, ontology-grounded project memory. The system captures architectural decisions, lessons, constraints, and rationales in a knowledge graph exposed to agents via a Model Context Protocol (MCP) interface. Records carry lifecycle status, provenance, and supersession links, queryable via MOOSE, a proprietary neurosymbolic engine that treats the symbolic layer as the primary reasoning substrate. We compared MOOSEDev against a production vector-memory tool on a neutral public corpus of 835 typed records. MOOSEDev returned the expected answer set essentially in full (0.98-1.00) on supersession, set-completeness, and negation questions, whereas the baseline's top-k retrieval surfaced between 6% and 27%. Conversely, relevance recall and token cost were largely equivalent between the two systems. We also describe a temporal commit-history bootstrap of our own codebase, a pre-registered live trial, and lessons learned.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：编码智能体（coding agents）已成为许多软件项目中生成新代码的主要方式，由此产生的变更速度使得追踪这些变更背后的原因变得极具挑战性。
- **核心问题**：作者提出“理解债务”（comprehension debt）这一概念，指代码库之所以是当前样子的原因（架构决策、约束、理由、经验教训等）逐渐流失的过程。源代码只是“做了什么”的体现，而“为什么这样做”的推理和理论则存在于代码之外（引用了 Naur 1985 的“编程即理论构建”观点）。
- **现有解决方案的不足**：笔记文件、Markdown 规范、检索增强生成（RAG）和向量记忆工具（如 mem0）虽有所帮助，但存在根本性缺陷——智能体需要知道一条记录代表什么**类型**的知识（决策、约束、理由、教训、反模式），它是当前有效还是过时历史，以及记录之间的**关系**（如“这个决策取代了那个决策”）。这些区别本质上是**本体论**的。向量搜索能找到相近的词语，但不知道一条记录是什么、在生命周期中扮演什么角色。
- **核心论断**：项目记忆从“记笔记问题”变成了“建模问题”（modeling problem）。虽然已有大量关于源代码本身的知识图谱研究（如类图、API 演化图），但 MOOSEDev 建模的是关于代码的**知识**，而非代码本身——这是现有工作所隐含但未显式处理的层次。

## 2. 方法论

### 核心思想
MOOSEDev 是一个已部署的神经符号记忆系统，将架构决策（ADRs）、经验教训、约束、理由和反模式捕获到项目知识图谱中，通过 MCP（模型上下文协议）暴露给编码智能体，并使用专有的神经符号引擎 MOOSE 进行查询。

### 关键技术细节
- **本体层**：基于两个小型 OWL 本体——software-engineering（代码库的结构词汇，9 个类）和 software-architecture（关于结构的知识，11 个类），共 51 个属性，配有 SHACL 形状用于验证。本体通过 Trivyn 本体工程工作台交互式生成并手动精炼。
- **关系类型**：一条记录可以携带理由（rationale）、取代（supersede）另一条记录、影响（affect）某个组件、带有生命周期状态、作者和时间戳。这些边构成了可遍历的网络。
- **神经符号引擎（MOOSE）**：
  - 将 LLM 视为“不可靠但有用的传感器”。
  - 符号层（关键词与结构匹配、本体遍历、确定性证据融合、验证、执行轨迹）作为主要推理基础。
  - LLM 仅在窄而明确的点上被调用：解释问题和综合答案，可采用较小的模型（8–32B 参数）。
  - 每次推理的每一步都记录在执行轨迹中（可审计性）。
- **对外接口**：通过 MCP 提供四组工具——类型化捕获（typed capture）、读取（上下文检索、自然语言查询、SPARQL）、生命周期管理和完整性检查。
- **引导流程（Bootstrap）**：通过逐提交（commit-by-commit）走查仓库历史来提取带历史时间戳的类型化记录，从而恢复替代链等历史关系。本体是领域级的而非项目特定的，因此新代码库无需定制 schema。
- **运行时行为**：当智能体请求当前指引时，引擎遍历图谱找到相关记录，沿类型化关系跳转，过滤已取代记录，将剩余证据确定性排序后放入上下文；LLM 只负责解释问题并综合答案。

## 3. 实验设计

### 基准（Benchmark）与数据
- **测试语料**：CodeGraph（第三方开源开发者工具）的文档，捕获为 **835 条类型化记录**存入图谱，以及 **553 条 mem0 记忆**，已验证保真。
- **评估条件**（五个记忆与检索条件）：
  - **B0**：无记忆的编码智能体（“vibe coding mode”），作为地板。
  - **B1-notes**：将真实文档作为平面文件提供给智能体。
  - **B1-mem0**：使用生产级向量记忆工具 mem0 摄取相同文档。
  - **B1-rag**：BM25 检索工具，作用于图谱内容展平后的文本——测试仅凭内容而无结构是否足以得到结果。
  - **B2**：结构化项目记忆图谱（MOOSEDev）。
- **模型配置**：所有运行使用同一 CLI 代理配置和模型（GPT-5.x 家族）。
- **评估方法**：预先注册了裁决标准；金标准答案来自原始资料或 SPARQL 推导集合；使用严格 LLM 评判器（GPT-5.4-mini）评分，允许同义改写但拒绝“主题正确但事实错误”的答案。评判器通过复现图谱条件（B2）的严格匹配分数进行验证。每次运行都是不可变转录，无需重新运行代理即可重新评分。

### 主要实验任务
1. **集合完整性（Set completeness）**：能否枚举出完整答案集。
2. **否定/缺失（Negation/absence）**：能否确认某事物不存在。
3. **替代遍历（Supersession traversal）**：能否沿“取代”关系追踪记录的新旧更替。
4. **简单相关性检索**：常规相关性召回测试（向量记忆预期的优势领域）。
5. **规模研究**：从 50 到 634 条记录，检验优势是否随存储增长而复合。
6. **反转对研究（Reversal pairs）**：4 组真实反转对 × 4 个模型 × 2 种交付模式，共 40 次试验，检验“当前性”（currency）。
7. **预注册现场试验**：在公司的两个生产代码库上持续 21 天（截至报告时）的日常使用测试，16 个固定参考点，评估每月图谱 vs 冷启动的差距，并预设失败条件（每个项目每月少于 4 次引用记录的辅助即触发系统退役）。

## 6. 主要结论与发现

- **结构推理任务上的绝对优势**：在集合完整性（1.00 vs 0.18 vs 0.08）、否定/缺失（0.98 vs 0.06 vs 0.00）、替代遍历（0.98 vs 0.27 vs 0.12）上，结构化图谱远超向量记忆（mem0）和纯文档搜索。基线并非缺少相关信息（mem0 中有这些事实），而是检索只能返回有限的排序切片，无法枚举完整集合、确认缺失或遍历关系。
- **与 BM25 对比**：集合重叠 F1 为 0.94 vs 0.25（私有语料）、0.90 vs 0.34（公共语料），说明优势来自结构而非内容本身。
- **相关性检索持平**：在向量记忆预期擅长的简单相关性检索上，图谱与 mem0 基本打平（图谱覆盖率 0.82 @约 35k token；mem0 为 0.67–0.90 @约 40k token）。检索精度本身不是核心差异点。
- **规模无复合优势**：规模研究显示图谱在每个规模点上领先（最大规模 hit@5 为 0.84 vs 0.60），但斜率的置信区间包含零，即优势没有随规模增加而扩大。
- **当前性（Currency）通过构造保证**：40 次反转对试验中图谱 100% 提供当前答案，因为被取代的记录从当前指引检索中被构造性排除。冷启动智能体得 0 分；在替代记录排序高于当前记录的反转对上，B1-rag 仅有 1/13（8%）的当前率。
- **成本权衡**：结构性完整查询消耗更多 token（78k–167k vs 约 35k），但这是“能力是否会失败”的差异——基线在任意成本下都无法产出完整答案。
- **部署可行性**：引导流程在自身上恢复出 7 条真实的替代链；预注册试验中前 21 天记录了 71 次引用记录的主动辅助和 38 次漏报（其中 35 次来自提交历史较薄弱的项目），说明实际部署基本可行。
- **记忆是建模问题**：核心结论是——当问题是结构性的（完整性、缺失、遍历）时，结构化方法带来了类别性的（categorical）优势，而非渐进式改善。

## 7. 优点

- **清晰的定位与诊断**：准确指出向量记忆的根本局限在于无视本体论区分（记录类型、生命周期角色、关系），并据此设计解决方案。
- **符号层优先的神经符号架构**：将 LLM 降级为“窄点传感器”，由符号层承载确定性推理，设计上支持小模型，可审计、可复现，执行轨迹完整记录——代表了神经符号 AI 的实用落地。
- **评估严谨性极高**：预注册裁决、不可变转录、免费重新评分、判定器按已知分数条件验证、金标准来自一手资料、确认记忆工具真实触发——这些规则有效拦截了三个近似的错误结论，本身就是对“自信、流畅但错误”这一失效模式的有力回应。
- **全面的实验架构**：涵盖效果（能否答对）、效率（token 成本）、可扩展性（规模研究）、当前性（反转对）和长期生态效度（现场试验），并特意加入对称测试避免稻草人。
- **知识贡献超越工具本身**：分享的测量陷阱（近似的三个错误结论）和部署障碍（捕获纪律摩擦、MCP 被动性、模型层级依赖）对社区有普适参考价值。

## 8. 不足与局限

- **对捕获质量的高度依赖**：作者明确承认“平面捕获会将图谱贬低为自由文本平局”（flat capture degrades the graph to free-text parity）。类型化捕获的纪律性摩擦高于向量存储，这在实际采用中是一个显著障碍，且文中对此摩擦的量化有限。
- **评估语料与模型范围的局限**：公共语料只有一个（CodeGraph）；评估的代理家族只有 GPT-5.x 一个系列；模型均为闭源 API 模型，未验证开源或更小模型上的表现（虽然架构设计声称支持 8–32B 本地模型）。
- **规模研究的上限有限**：最大仅到 634 条记录，对于真实大型项目的记忆库规模（数千到数万条）外推性有限；且斜率置信区间跨零，说明“结构性优势随规模增长”这一假设未被证实。
- **部署模式的被动性**：MCP 是主动拉取模式，代理自行决定何时调用记忆工具，这天然偏向更高级的模型——低能力模型可能不知道何时该查询记忆，从而降低效用。
- **长期主张尚未验证**：关于“减少理解债务”的核心动机声明，21 天的现场试验时间尚短，预注册报告虽然在按计划进行，但长期结论仍未落地。现场试验仅覆盖自家公司两个代码库，存在选择偏差。
