## 摘要
大型语言模型代理越来越多地在动态环境中运行，其中工具接口、API和用户需求在部署后发生变化。现有的自我进化方法主要遵循两种范式：基于外部记忆的方法，将反馈外部化为可编辑的记忆或技能以实现快速适应；以及基于参数的方法，将经验内化为模型参数以实现更深层次的能力提升。然而，单独使用任一机制都会在灵活性和性能之间产生权衡。本文探讨代理如何协调这两种渠道以实现稳健的自我进化。我们提出了COVE，一个统一的代理自我进化框架，通过任务感知路由、阶段感知调度和知识优化，结合了基于记忆和基于参数的学习。通过这种设计，COVE将自我进化视为一种协调过程，而非无差别地积累经验，该过程将任务和知识类型匹配到适当的学习机制。跨多个任务类别的实验表明，COVE优于单通道进化策略，在变化环境下展现出更稳健和高效的改进。

## Abstract
Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.

## 2. 方法论：COVE 框架

### 整体思想

COVE（**C**hannel **O**rchestrated **V**olatility-aware **E**volution）将自我进化从“无差别经验积累”重构为“按任务类型和知识稳定性匹配学习机制的协调过程”，整合两条通道形成闭环：外部记忆提升训练数据质量，训练后的参数降低对记忆的依赖。

### 三大核心机制

**① 任务感知路由（Task-aware Routing）**

- 使用反馈条件化的决策策略（而非手工评分函数），以受约束的 judge 为路由器。
- 输入：任务描述 τᵢ + 执行反馈 fᵢ（结果状态、标量分数、诊断消息）→ 输出结构化决策记录 dᵢ = (mᵢ, sᵢ, rᵢ)，其中 mᵢ 为通道选择，sᵢ 为任务特征描述符，rᵢ 为一句解释。
- 三通道选择：`harness_only`（任务失败源于易变/上下文知识）、`parametric_candidate`（需要可内化的深层能力）、`hybrid`（两者兼有）。
- 路由结果具有可解释性（附带信号描述和理由）。

**② 阶段感知调度（Stage-aware Scheduling）**

- 核心：**Stage-aware Evolution Trigger**，基于三种可测条件动态决定何时切换通道：
  - **性能平台期（Plateau）**：最近 w 个 episode 的成功率/平均奖励提升低于阈值 ε；
  - **数据充分性（DataSufficient）**：高质量轨迹数 |D_q| ≥ N；
  - **冷启动失败（ColdStartFailure）**：前 k 个任务的成功率低于阈值 τ_c（用于反转路径：先参数训练建立基础能力，再记忆探索）。
- 触发条件为三者析取：`Trigger = Plateau ∨ DataSufficient ∨ ColdStartFailure`。
- 这既支持常见的“先记忆探索，后参数内化”路径，也支持 Lean 定理证明等领域的“先参数训练建立最小能力，再记忆进化”的反向路径。

**③ 双模态知识优化（KnowledgePO）**

- **知识波动性分类**：每条记忆被标记为 `volatile`（易变，如 API 名称、表结构）、`stable`（稳定，如算法模式、领域推理习惯）、`strategic`（策略性，如调试计划），反复修订的条目会升级为 volatile。
- **Memory-aware Rollout（记忆辅助参数化）**：训练前将 volatile 条目用 `<volatile>...</volatile>` 显式标记，rollout 时检索 top-k 记忆注入消息列表，提高训练数据的信号密度。
- **抗背诵奖励（Anti-recitation Reward）**：训练前对 volatile 条目中的名称随机重命名。若模型调用过时/未观察到的易变名称，则施加惩罚：`R = R_task − λ·I[uses stale or unobserved volatile name]`，强制模型“读当前条目并据此行动”而非“记忆—重复”。
- **Memory Release（记忆释放）**：训练后对稳定记忆进行 A/B 评估，若去除后性能下降低于阈值（Δⱼ < 阈值），则标记为已内化并从在线检索集释放（但保留在归档存储中）；volatile 记忆永远不释放。

### 公式与算法

- 优化目标：最大化累计任务效用 `ΣRᵢ − α·ΣC_tokenᵢ − β·ΣC_trainₘ`，在推理 token 成本和训练计算成本约束下权衡。
- 完整流程见 Algorithm 1（COVE Workflow）：任务流循环中依次执行记忆检索 → harness 推理 → 反馈收集 → 候选知识提取与标注 → 路由决策 → 触发条件检查 → 参数训练（含抗背诵惩罚）→ 稳定记忆评估与释放。

## 6. 主要结论与发现

1. **单一通道进化存在互补瓶颈**：Harness 侧记忆无法提升需要操作性能力的任务（Lean 证明成功率提升 <3%），参数侧学习使模型在表面接口变化时崩溃（API 正确率下降 59.3%）。
2. **通道选择需依赖任务特征**：任务类别（如逻辑严谨性 vs 动态工具依赖）、知识类型（易变 vs 稳定 vs 策略性）、学习阶段（冷启动 vs 平台期）共同决定最优通道。
3. **知识波动性是决定存储位置的关键标准**：易变表面形式（API 名称、schema）应留在 harness，稳定原则（可复用证明策略）适合参数内化，策略性启发则需反复验证稳定性后才可内化。
4. **协调进化显著优于单通道**：COVE 在 Hybrid 测试子集上达到 24.1% 成功率，超过 Base（15.6%）、Harness-only（20.8%）和 Parametric-only（21.3%）；在 Lean4、APPS、HotpotQA、MATH 上均取得最佳结果。
5. **有选择的参数化大幅提升效率**：路由器仅对真正需要参数化学习的实例分配训练，保持 65.0 的平均性能的同时将训练成本降至 Always-Both 的 16%。
6. **阶段感知调度优于固定调度**：平台期触发的参数化更新胜过持续参数训练和纯 harness 进化，说明训练时机是独立的决策维度。
7. **抗背诵奖励有效防止易变知识内化**：在 API 重命名条件下将 API 正确率从 54.0% 提升到 92.5%，且不损害分布内性能（96.5%→近似）。注意力分析表明该机制使模型更关注当前指令而非记忆中的旧接口。

## 8. 不足与局限

### 实验层面

- **未见方差与显著性检验**：未报告多次运行的标准差或置信区间，统计显著性未知。
- **基准覆盖有限**：未与更多主流自我进化方法（如 Voyager、AgentGen、Seagent）对比；Evo-Memory 和 Self-Challenging 的复现质量可能影响公平性。
- **Hybrid 评估的选择偏差**：Hybrid 子集由路由器自身判定，可能高估协调进化的实际增益。

### 方法层面

- **依赖 Router/Judge 的约束生成质量**：面对未见任务类别时路由决策可能退化为随机；论文仅验证了跨 LLM 的一致性而非路由正确性本身。
- **阈值选择未充分讨论**：Plateau（ε）、数据量（N）、冷启动（τ_c）等阈值缺乏敏感性分析。
- **知识分类成本**：波动性标注依赖模型判断和迭代修订，其与人工标注的一致性未验证。
- **Memory Release 的 A/B 评估**：对每次训练后的每个稳定记忆都做 A/B 测试，计算成本在大型记忆库下可能显著。

- **训练只用一个 FRPO/GRPO 风格**的强化更新，未与更复杂的多轮训练或持续学习策略（如经验回放、正则化防遗忘）结合。
- **动态环境的模拟程度有限**：API 重命名只是其中一种扰动；更复杂的持续漂移（如 schema 渐进演变、用户偏好翻转）未覆盖。
- **未涉及安全性和分布外泛化**：自我进化可能放大模型偏见或导致参数灾难性遗忘，论文对此未做讨论。
