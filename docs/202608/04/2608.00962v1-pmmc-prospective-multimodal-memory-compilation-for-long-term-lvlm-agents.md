## 摘要
长期记忆对于LVLM智能体在扩展的多模态交互中保持一致性和整合信息至关重要。然而，现有的智能体记忆系统通常将视觉体验简化为文本摘要，或依赖静态的检索-然后-推理流水线，这在查询时效率低下，并且在问题需要图像-文本绑定、时间更新或视觉细节时显得脆弱。我们提出了前瞻性多模态记忆编译，这是一个将部分记忆推理过程从查询时间转移到记忆整合时间的框架。给定累积的多模态交互，一个提问者预测未来的候选问题，一个规划者编译基于问题的多模态记忆程序，一个怀疑者验证计划的证据路径是否能支持预测的答案。经过验证的问题-程序对构成了一个结构化题库，用于高效的查询时路由和证据检索。在多模态长期记忆基准上的实验表明，我们的方法提高了答案质量和视觉证据召回率，同时降低了查询时的令牌和延迟成本。广泛的消融实验分析了自我反馈、动态规划、原始图像访问和题库覆盖率的影响。

## Abstract
Long-term memory is essential for LVLM agents to maintain consistency and integrate information across extended multimodal interactions. Existing agent memory systems, however, often reduce visual experiences into textual summaries or rely on static retrieve-then-reason pipelines, which are inefficient at query time and brittle when questions require image-text binding, temporal updates, or visual details. We propose Prospective Multimodal Memory Compilation, a framework that shifts part of the memory reasoning process from query time to memory consolidation time. Given accumulated multimodal interactions, a Questioner predicts future question candidates, a Planner compiles question-conditioned multimodal memory programs, and a Doubter verifies whether the planned evidence path can support the predicted answer. The verified question-program pairs form a structured question bank for efficient query-time routing and evidence retrieval. Experiments on multimodal long-term memory benchmarks show that our method improves answer quality and visual evidence recall while reducing query-time token and latency costs. Extensive ablations analyze the effects of self-feedback, dynamic planning, raw-image access, and question bank coverage.

- **问题背景**：长期记忆对大型视觉-语言模型（LVLM）智能体在多模态交互中保持一致性和信息整合至关重要。但智能体的经验是跨会话增量到达的，未来查询的证据可能分散在多个时间轮次、图像和后续修正中。
- **现有方法缺陷**：
  - **长上下文模型**：直接消费交错历史，但计算成本随上下文长度增长，且历史扩展后定位相关证据的能力退化。
  - **记忆增强智能体**：依赖摘要、结构化笔记、层次存储或图结构，在未知未来查询前就固定了记忆表征和访问策略。
  - **多模态记忆系统的特有难题**：基于字幕的存储会永久丢失字幕生成时未提及的视觉属性；对比编码器（如CLIP、SigLIP）不能显式保留交互特定的绑定关系（如后续分配给早期图像的名字）；单一表征粒度难以满足所有信息需求（事实问题可能需要文本、实体问题需要图文关联、视觉细节问题需要原始像素、时间或多跳问题需要多个关联记忆）。
  - **传统RAG与智能体检索**：传统RAG在查询到达后才做检索；智能体检索更灵活但需要额外在线模型调用和检索轮次；索引时间的问题生成主要用于检索键而非编译和验证可执行的多模态访问程序。
- **核心研究问题**：智能体能否在记忆整合期间预测合理的未来信息需求，并提前准备证据应如何被访问？

## 二、方法论：PMMC框架

### 2.1 核心思想

**将部分记忆推理过程从查询时间转移到记忆整合（consolidation）时间**，即将"查询时才规划如何检索"改为"提前编译并验证问题条件化的访问策略"。PMMC构建的是**路由和程序索引（Question Bank），而非答案缓存**。

### 2.2 三个核心组件

- **Questioner（提问者）**：基于新整合的锚点（anchor）与更早的支撑记忆，生成有界数量的典型前瞻性问题、改写变体和源支撑声明。
- **Planner（规划者）**：将每个问题编译为类型化多模态记忆程序，程序由冻结的算子内核组成，包括：词法和稠密文本检索、跨模态图像检索、图像-文本与局部上下文扩展、时间扩展、原始图像物化、证据控制算子。程序有类型化无环数据流、有界长度限制，禁止任意代码、SQL、路径和不受限工具调用。
- **Doubter（怀疑者）**：通过实际执行程序来验证证据路径能否支撑预测答案，执行结果通过准备度检查（Eq. 5：执行成功、非空证据、覆盖所需模态与能力、满足证据多重性要求），返回`pass / revise / reject`，可修正失败被翻译为类型化修订指令（如增加视觉检索、扩展时间上下文、物化原始图像、增加检索深度），最多rmax轮。

### 2.3 关键公式与流程

- **问题形式化**（Eq. 1）：多模态交互历史 H = {m1, …, mN}，每个交互单元 mi = (xi, Ii, ci, si, ℓi, bi, μi)，其中 xi为对话文本、Ii为关联源图像、ci为可选字幕、si与ℓi为会话与时间顺序、bi为可见边界、μi为元数据。字幕和嵌入仅作为辅助索引，原始话语和图像是规范证据。
- **程序编译**（Eq. 2-3）：Questioner生成前瞻性问题集 eQt = Qθ(Ut, Ωt)；Planner在每轮修正中基于（问题、需求契约、上一轮反馈）选择受约束策略，经确定性下沉（Lower）生成类型化程序 π = [o1, …, oL]。编译器会构造仅私有化的临时答案和源支撑，不会从基准标注获取。
- **执行验证**（Eq. 4-5）：Exec(π, H≤t; q) 产生执行轨迹和类型化证据；Ready(E, T; R) 检查执行成功、非空证据、模态覆盖、能力覆盖和证据数量满足。
- **在线路由与回答**（Eq. 6）：查询时通过词汇、稠密文本和（如有查询图像时）多模态匹配筛选题库候选，加权倒数排名融合（RRF）排序，置信度和前二名间隔过阈值则接受编译路由；所选程序在当前可见记忆上重新执行（程序冻结的是访问策略和检索表征，而非固定证据标识符，因此能检索编译后新出现的有效记忆）；准备度检查通过则物化检索到的原始对话文本、字幕、上下文和源图像，交给答案LVLM。不通过则回退到原生多模态RAG。**在线绝不调用Questioner、Planner、Doubter**。
- **成本模型**（Eq. 7）：CPMMC(n) = Ccompile/n + Conline，编译态服务n个未来查询的分摊成本。

## 六、主要结论与发现

1. **主结果**：PMMC在8个骨干-基准配置中**6个排名第一**，其余2个第二；整体宏平均HJ从最强基线的46.7提升至**49.9**，MEMLENS上50.4 vs 最强基线48.1（+2.3），Mem-Gallery上49.4 vs 45.4（+4.0）。在Mem-Gallery上对每个骨干均第一。
2. **Caption vs Raw的长上下文**：Full-Ctx-Caption一致优于Full-Ctx-Raw，说明在固定上下文预算下，直接提供历史图像并不能确保有效使用多模态证据。
3. **动态规划最重要**：移除动态Planner导致证据召回-8.3、原始图像命中-10.6、程序成功率-15.2，消融实验中降幅最大。
4. **执行验证（Doubter）价值**：移除后HJ降约2.8-3.2分，程序成功率从92.1%降至82.7%，虽然节省约41%写入token，但线上计算量上升。
5. **原始图像不可替代**：移除后Mem-Gallery（视觉密集）HJ降4.9分，说明字幕和文本索引不能完全替代原始视觉证据访问。
6. **受控自反馈的价值**：从r=0到r=2，HJ从54.0升至57.0，程序成功率82.7%→92.1%，回退率降9.8个点，查询token降15.8%；r=3边际收益极小（+0.2 HJ），故部署r=2。
7. **摊销成本优势**：PMMC初始整合成本最高，但在约2次查询后就相对M3-Agent/M2A回本，约12次相对Native MM-RAG、18次相对Caption-Text RAG回本。
8. **题库覆盖与瓶颈**：宏观平均证据覆盖@5为82.1%，语义匹配@5为75.2%，缺口（6.9点）主要来自路由而非问题生成；Oracle题库HJ达65.4，比部署的57.0高8.4点，说明候选排序与程序选择仍有余量；12.6%查询触发回退。

## 七、优点与亮点

- **问题重构有创新性**：将记忆访问规划从查询时前移到整合时，提出"前瞻性记忆编译"的新范式，而非复用传统的静态索引或在线智能体检索。
- **Questioner-Planner-Doubter三组件分工清晰**：每个组件职责明确，且信息隔离严谨——Planner和Doubter看不到私有答案和源标识符，防止标注泄露。
- **执行验证而非文本验证**：每次修订都绑定到已观察的执行失败和不可覆盖的准备度检查（对比无约束自修正），避免看似合理但实际无效的证据路径。
- **题库是程序索引而非答案缓存**：运行时可检索编译后新出现的有效记忆，避免陈旧性；在线路径零编译模型调用，理论延迟可控。
- **多模态算子内核设计**：覆盖文本、图像、跨模态、时间、原始像素等多种证据来源，且禁止任意代码/SQL，安全性高。
- **成本-质量权衡的详细刻画**：给出r轮数、写入开销、摊销成本的清晰分析，对实际部署有指导价值。

## 八、不足与局限

- **前瞻覆盖有限**：Cover@5仅82.1%，仍有约18%查询的证据组无法被题库完全覆盖，高度依赖回退机制。
- **写入时开销较大**：编译需要多轮（Questioner + Planner + Doubter数轮）模型调用，写入token最多约3.2万/编译单元；只有当记忆被反复访问时摊销优势才明显。
- **骨干差异明显**：在GPT-5-mini/MEMLENS和Qwen3.5-9B/MEMLENS上弱于Caption-Text RAG，说明方法对模型能力存在敏感性（尤其生成高质量前瞻问题需要较强模型）。
- **题库缺少持续维护机制**：当前题库构建基于整合时快照，未涉及跨时间的问题库更新、过期条目淘汰和合并策略，这点论文也在展望中承认。
- **路由仍是瓶颈**：Match@5与Cover@5之间有6.9点差距，说明已有正确程序但排序未命中，路由质量有待提升。
- **Oracle-Gap**：Oracle HJ（65.4）与部署HJ（57.0）间存在8.4点鸿沟，仅靠更好排序有望进一步提升，但排序策略本身可能依赖查询-问题语义对齐，语义鸿沟难以完全弥合。
- **未报告多轮运行方差与统计显著性**，对评估噪声的解释力有限；GPU数量与能耗细节缺失，影响成本完全评估。
