## 摘要
自进化大型语言模型（LLM）代理的内存通常被配置为仿佛其字节预算只会增长。然而，云平台会根据负载和成本调整配额，并且我们表明能力并不会随预算恢复而回升：在经历压缩-恢复循环后，代理会稳定在压缩前水平之下，我们将这一差距称为内存滞后。其原因在于结构性。删除和单向压缩会丢弃后续重建所需的材料，并且我们证明，任何仅保留或丢弃条目的策略都存在残差赤字下限。我们提出CrystalMem（结晶化内存），一种弹性内存辅助组件，在结晶能量调度下将条目降级到四种保真状态，通过优势加权影响力与依赖耦合排序降级操作，并在显式计算和字节上限约束下通过验证的再结晶恢复能力。在七个环境、十七种方法和六个主干网络上，结合多租户服务和物理边缘-云部署，CrystalMem在每种设置下均实现了最高的恢复能力，并闭环了所有基线未解决的问题。在50%字节预算下，CrystalMem在每种环境上的完整配置下都能匹配最强的有预算基线；在相同预算下，它平均领先+4.6个百分点。

## Abstract
Memory for self-evolving large language model (LLM) agents is often provisioned as if its byte budget only grows. Cloud platforms, however, adjust quotas with load and cost, and we show that capability does not follow the budget back up: after a squeeze-and-recover cycle, the agent settles below its pre-squeeze level, a gap we call memory hysteresis. The cause is structural. Deletion and one-way compression discard the material needed for later rebuilding, and we prove that any policy that only keeps or drops entries carries a residual-deficit floor. We propose CrystalMem (Crystallized Memory), an elastic memory sidecar that demotes entries across four fidelity states under a crystallization-energy schedule, orders demotions by advantage-weighted influence with dependency coupling, and recovers capability through verified recrystallization under explicit compute and byte caps. Across seven environments, seventeen methods, and six backbones, with multi-tenant serving and a physical edge-cloud deployment, CrystalMem achieves the highest restored capability in every setting and closes the loop left open by every baseline. From a 50% byte budget, CrystalMem matches the strongest budgeted baseline at full provision on every environment; at equal budgets, it leads by +4.6 pp on average.

- **研究背景**：自进化LLM代理通过将轨迹、技能和事实写入外部记忆并在推理时检索来持续改进。生产系统中，这一存储层已被当作"管理内存平面"进行治理。然而，云服务栈中计算、KV缓存等资源都具备弹性，**唯独代理记忆的字节预算被默认视为只增不减**——这种假设在共享云环境中并不成立。
- **核心发现（内存滞后现象）**：论文通过实验测得当云配额经历"压缩→恢复"循环后，**代理能力并不会随字节预算回升而恢复到压缩前水平**（见图1、图2），即 `能力不仅取决于当前预算，还取决于预算走过的路径`。作者将这一不可逆差距命名为 **memory hysteresis（内存滞后）**。
- **结构性根因**：现有策略分为两类——二元保留（删除或保留原文）和单向不可逆压缩阶梯。二者的共同缺陷是：**在压缩阶段丢弃了后续重建所需的"材料"**，导致恢复阶段无法重建条目。

- **论文定位**：提出 CrystalMem 作为首个打通"能力闭环"的弹性内存侧车，将记忆保留从"二元选择"转变为**可逆的状态分配**。作者明确区分了贡献归属：滞后现象与下界为发现，结晶机制为设计，serving 栈与 benchmark 环境采用自前人工作。

### 2. 方法论：核心思想、关键技术细节与算法流程

- **整体框架**：CrystalMem 是一个运行在 serving 路径旁的 sidecar，每个阶段（stage）执行一次控制循环，包含三个相位：**Monitor（监控）→ Crystallize（结晶）→ Recrystallize（再结晶）**。阶段转移因式分解为结晶分配核 φ 与再结晶生成-验证算子对的乘积（公式 5），删除仅作为最后一层兜底而不再默认发生。

- **核心机制一：四档保真度阶梯（Fidelity Ladder）**
  - 每个条目占据四种状态之一：`FULL → COMPRESSED → SKELETAL → TRACE`，状态越低字节开销越小、效用占比越低、未来重建所需 token 越多。
  - 从 COMPRESSED 往下，每个条目保留 **residue（残差）** 与 **invariants（不变量）**（关键跨度、实体元组、结果事实），供后续验证重建使用。

- **核心机制二：结晶能量调度（Crystallization Energy Schedule）**
  - 降级决策同时定价"当前效用损失"与"未来重建计算成本"：**ηe(k) = ṽe(1 − rk) + τ·ck**（公式 6）。
  - 在给定入站预算下，求解约束分配问题（公式 7）：目标为最小化总能量，约束为字节预算。
  - 实现为**水填充降级**：按边际价格 Δηe/Δμe 升序逐级降级，直到满足预算约束；移动的边界称为"结晶前沿"。
  - 复杂度仅为 O(|M| log |M|) 每阶段，无需训练、无需外部求解器，适合在 serving 路径内运行。

- **核心机制三：影响力驱动的价值估计（Advantage-Weighted Influence）**
  - 在线估计每条条目的价值（公式 8）：基于检索权重与查询结果相对滑动批次的**优势**（均值/标准差归一化），指数滑动平均更新。
  - 依赖耦合（公式 9）：通过共检索与引用边构成的**依赖图**传导价值，锚定其他条目的"枢纽条目"最后沉没；硬性保护为：当 FULL 邻居仍引用某条目不变量时，该条目不得降级到 SKELETAL 以下。
  - 价值估计为白盒方法，仅使用检索日志与分级结果。

- **核心机制四：验证再结晶（Verified Recrystallization）**
  - 预算恢复时，在显式**计算上限（ρ·ns，默认10%的 serving token）**与**字节上限**下选择提升集合（公式 10），使用贪心背包近似（密度 ṽeΔe/ce）。
  - 从残差与图邻域条件重建，重建草案必须通过**不变量验证门控**（V(e′, he)=1）才被准入；失败的提升留在当前档位，不污染存储。
  - 因此将 serving token 转化为恢复的能力，实现"存储换计算"的交换。

- **理论保证**（三条命题）：
  - **Proposition 4（可行性）**：每一阶段的存储字节始终不超预算。
  - **Proposition 5（近最优性）**：当边际价格沿阶梯非递减时，水填充调度对分数松弛是最优的，能量损失最多为一个条目的跨度（分数背包经典论证）。
  - **Proposition 6（闭环）**：在无底层删除、完美重建、无虚假拒绝且资源充足时，期望赤字趋于 0、闭环成立——论文主动标注此为理想化情形。

### 6. 主要结论与发现

- **滞后现象定量化**：在压缩低谷（预算 25%），按策略家族分类的中位能力保持率排序为 LRU (0.585) < Mem0 (0.703) < 不可逆阶梯 (0.755) < CURATOR (0.790) < CrystalMem (0.841)。
- **恢复不恢复**：预算回到 100% 后，四个基线停留在压缩前能力的 0.71-0.89，滞后面积 0.086-0.207；CrystalMem 恢复到 0.984，滞后面积仅 0.010。
- **双杠杆分离**：四档阶梯 vs 单档换取 2.3 pp，而可逆栈额外换取 9.0 pp——**可逆性是第一阶杠杆，档位数量是第二阶**。
- **主表结果**：CrystalMem 在全部 7 个环境上恢复能力最高（平均 57.4），比最强基线 R3Mem（52.8）领先 +4.6 pp，比最强二元基线 CURATOR（51.3）领先 +6.1 pp；平均滞后面积 0.013（基线范围 0.044-0.216），平均残余赤字 0.5 pp（基线范围 5.2-17.6）；与无预算 keep-all（58.8）仅差 1.3 pp。
- **半预算等价**：中位 b⋆=50% 时即匹配最强预算基线在 100%

- **理论-实验交叉验证**：实测残余赤字与 Proposition 3 的理论下界之间的相关系数为 0.76，散点显示所有基线均位于下界之上、CrystalMem 贴合下界运行，证实了理论分析对真实行为的预测力。

### 7. 局限性与潜在不足

- **理想化闭环假设的脆弱性**：Proposition 6 的闭环保证依赖“无底层删除、完美重建、无虚假拒绝”三个条件，论文明确承认这是理想化情形。现实中的生成模型会产生重建偏差，验证门控的拒真率（false rejection）会牺牲一部分本可恢复的能力；论文未给出拒真率的上界估计，也未分析其在不同 backbone 间的变异性。
- **白盒与开源模型依赖**：CrystalMem 的价值估计、不变量提取与验证全部依赖可访问的隐藏状态与可控解码（温度 0），对闭源 API 模型（GPT-4 等）不直接适用；这不只是实现细节问题，而是方法论层面的适用范围限制——若将三者迁移到纯黑盒设置，需要重新设计代理信号。
- **价值估计的冷启动问题**：优势加权影响力（公式 8）依赖滑动批次内的查询相对表现，在系统冷启动、查询模式剧烈变化、或新条目尚未被检索到时，会产生有偏估计；论文虽然用指数滑动平均缓解，但未给出收敛时间或对突发流量鲁棒性的量化分析。
- **超参数的敏感性未完全披露**：ρ（再结晶计算上限，默认 10%）、滑动窗口宽度、优势归一化的温标常数等均未做敏感性扫描；Table 4 仅报告了 ρ 的 0%/5%/10%/20% 四个点，其余超参缺乏系统探讨。
- **泛化与外部效度证据不足**：跨骨干测试虽覆盖 6 个模型规模，但仅限 Qwen 与 Llama 两个家族；额外泛化验证仅一个环境（BabyAI）。阶梯深度、依赖图、验证门控等机制是否在其他任务形态（如多模态、代码生成、科学推理）下依然有效，仍属未知。
- **多租户实验规模有限**：N 最大仅 8，窗口为 6 个，未涉及跨数据中心或异构资源池的联邦场景；SLO 感知分配的具体算法细节（如何预测窗口违规）描述较简略，复现难度较高。
- **安全性/隐私未讨论**：压缩后的残差与不变量包含关键实体的结构化元组，若内存被攻击者读取或侧信道探测，信息泄露风险比原文更高还是更低？论文完全未讨论这一问题。

### 8. 综合点评与启示

- **核心贡献的优先级判断**：论文最持久的贡献可能不是 CrystalMem 本身，而是“内存滞后”（memory hysteresis）这一现象的命名与量化，以及 Proposition 3 给出的残差赤字下界。它把代理记忆治理从“保存什么”的认识论推进到“保存什么以允许未来重建”的信息论层面——前者是选择问题，后者是表示与调度问题。
- **方法论上的示范意义**：将记忆分配表述为带能量定价的约束优化，并用水填充求解，这一思想可迁移至其他缓存/索引系统；不变量验证门控作为“准入控制”环节，在生成式重建的可靠性问题中具有通用价值。
- **对生产系统设计者的启示**：字节预算的弹性与能力恢复之间并非正向单调关系，而是带路径依赖的。弹性内存侧车应具备：① 多档保真度而非二元保留；② 可逆的降级-重建循环；③ 显式计算预算上限；④ 查询日志驱动的价值估计。这四条原则可独立于 CrystalMem 的特定实现被借鉴。
- **对研究社区的建议**：滞后现象暗示了代理评测协议中的一个隐藏陷阱——任何在固定预算下比较记忆策略的实验都可能被路径效应污染。未来研究应在报告“压缩→恢复”循环下的面积指标（如滞后面积）之外，同时报告稳态能力曲线，以避免对方法优劣的错误归因。
- **评分视角**：在创新性、体系完整度、实验执行质量、理论严谨性四方面均达到顶会主刊水准；主要扣分点在于收敛性分析缺失、黑盒适配未覆盖、以及理想化假设与现实的间隙未量化。

**总体评价**：CrystalMem 是一篇“发现问题比解决问题更难得”的论文。它证明了一个反直觉现象——字节预算的弹性不等于记忆能力的弹性——并给出了可操作的工程方案与理论下界。推荐在代理记忆、弹性系统、以及缓存治理三个领域交叉处追踪后续工作。
