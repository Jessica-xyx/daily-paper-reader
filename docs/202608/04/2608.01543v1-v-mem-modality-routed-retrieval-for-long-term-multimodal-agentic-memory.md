## 摘要
用户与LLM智能体之间的交互日益多模态化：对话中文本与图像交织，后续问题可能针对其中任何一种。然而，大多数智能体记忆是为文本设计的，即使少数支持多模态对话的记忆在面对与视觉相关的问题时仍然失败。我们将这一失败归因于其依赖的相似性搜索背后的一个假设：在索引空间中，查询与回答它的相关证据距离很近。在多模态场景下，两个鸿沟打破了这一假设。模态鸿沟使得查询与其自身模态的记忆内容距离更近，而与其他模态的证据更远，即使在训练好的联合嵌入空间中也是如此。相似性-相关性鸿沟则表明，与查询最相似的内容往往不是回答该查询的证据，尤其当查询同时包含文本和图像、而其证据又不单独类似于任何单独部分时，这一问题最为严重。我们提出了V-Mem，一种多模态智能体记忆系统，它根据查询的模态和目标证据的模态来路由检索，而这两种模态都仅从查询中识别出来。为了跨越模态鸿沟，V-Mem将对话组织为轮次，并从与匹配项相同的轮次中返回目标模态的内容，而不进行跨模态比较。为了弥合相似性-相关性鸿沟，它使用LLM生成的锚点进行搜索，该锚点比查询更接近相关证据：对于仅包含文本且寻求图像的查询，锚点是一个假设性标题；而当证据只能通过将查询文本和从查询图像中提取的相关关键词相结合才能获得时，锚点是一个增强的搜索锚点，即查询文本加上从查询图像中提取的相关关键词。在Mem-Gallery上，V-Mem的LLM评判得分为0.82，而第二名仅为0.56，在带有图像的问题上差距最大（0.87，没有任何基线超过0.47）；在LoCoMo上，其得分为0.69，而对比得分为0.58。

## Abstract
Interaction between users and LLM agents is increasingly multimodal: conversations interleave text with images, and a later question may target either. Yet most agent memories are designed around text, and even the few that support multimodal conversations still fail on vision-related questions. We trace this failure to an assumption behind the similarity search they rely on: in the index space, a query lies close to the relevant evidence that answers it. In multimodal settings, two gaps break it. By the modality gap, a query lies closer to memory content of its own modality than to evidence in another, even in a trained joint embedding space. By the similarity-relevance gap, the content most similar to a query is often not the evidence that answers it, most acutely when a query carries both text and image and its evidence resembles neither part alone. We present V-Mem, a multimodal agentic memory system that routes retrieval by the modality of the query and that of the target evidence, both recognized from the query alone. To cross the modality gap, V-Mem organizes the conversation into rounds and returns the target-modality content from the same round as the match, without comparing across modalities. To close the similarity-relevance gap, it searches with an LLM-generated anchor that sits closer to the relevant evidence than the query does: a hypothetical caption for a text-only query seeking an image, and an enriched search anchor, the query text plus relevant keywords extracted from the query image, when the evidence is reachable only by combining the two. On Mem-Gallery, V-Mem reaches an LLM-judge score of 0.82 versus 0.56 for the second best, with the largest margin on questions carrying an image (0.87, no baseline above 0.47); on LoCoMo it scores 0.69 versus 0.58.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体作为长期运行的助手，会积累数周或数月的多模态交互历史（文本、图片、语音消息交织）。然而 LLM 只能处理当前上下文窗口，早期信息一旦被挤出即不可用；单纯扩大窗口也会因 lost-in-the-middle、context decay 等效应导致远端证据权重不足。
- **现有方案的不足**：Memory-Augmented Generation（MAG）把历史存入外部存储、在每次新轮次检索相关片段，但大多数 MAG 系统仅支持文本（摘要、图节点、句子嵌入），即使少数支持多模态对话的系统（如 MemVerse、Omni-SimpleMem、M2A）在视觉相关问题上仍会失败。
- **根本原因**：它们依赖相似性搜索，其隐含假设是"在索引空间中，查询与回答它的相关证据距离很近"。多模态场景下该假设被两个鸿沟打破：
  - **模态鸿沟（Modality Gap）**：当查询与证据处于不同模态时，查询在嵌入空间中更接近同模态内容，即使使用 CLIP/SigLIP 等训练好的联合嵌入空间也无法消除。
  - **相似性-相关性鸿沟（Similarity-Relevance Gap）**：与查询最相似的内容往往不是能回答它的证据。尤其当查询同时携带文本和图像、而证据既不单独类似文本也不单独类似图像时，必须结合两者才能找到证据，现有方法全部失效。
- **典型例子**：用户附上 Google 总部照片并问"我们讨论过图中组织什么？"，相关证据是"Google 给学生免费一年 Gemini Pro 订阅"——照片与文本嵌入都离该证据很远。

## 2. 方法论

### 2.1 核心思想
V-Mem 提出**按模态路由检索**：根据查询模态和目标证据模态的组合决定检索策略，而非对所有查询做统一相似性搜索。两个关键机制：
1. **通过共享轮次跨越模态鸿沟**：在同一模态内匹配，返回与匹配项同一轮次的目标模态内容，全程不做跨模态比较。
2. **用 LLM 生成的锚点弥合相似性-相关性鸿沟**：生成比查询更接近相关证据的搜索锚点。

### 2.2 记忆表示：轮次（Rounds）、单元（Units）与通道（Lanes）
- 对话历史组织为轮次序列 C = (r₁,…,r_T)，每轮是一次用户-助手交换；轮内单元 u 为单个文本片段或单张图片，模态 m(u) ∈ {txt, img}。
- 同轮单元共现、彼此相关，这是"通过共享轮次匹配"的前提。
- 按模态分组为通道：**文本通道**（对文本单元和图片标题建立稠密嵌入 + BM25 稀疏索引）、**图像通道**（对原始图像建立视觉嵌入）。
- 记忆构建**零 LLM 调用**：不摘要、不重写，直接追加编码，可在对话进行中增量构建。

### 2.3 路由检索
检索公式（简化）：
- 路由 Route(q) 仅从查询本身推断（查询、目标）模态对，**无 LLM 调用**：查询模态由是否附带图像决定；目标模态由关键词规则判定（问"哪张图/照片/多少张"→图像，否则→文本）。
- 四种情形：
  - **text→text**（同模态）：仅激活文本通道，原始查询检索。
  - **image+text→image**（同模态）：仅激活图像通道，查询图像与存储图像做视觉嵌入匹配。
  - **text→image**（跨模态）：匹配限定在**含图像的轮次**的文本通道内（避免无图轮次排挤），用 LLM 生成的**假设标题（hypo-caption）**匹配存储图片的标题；计数类问题跳过该锚点、保留原始查询文本。
  - **image+text→text**（跨模态）：用视觉 LLM 从查询图像中提取最多 8 个关键词，追加到查询文本形成**增强搜索锚点**；图像通道与文本通道并行激活。

### 2.4 评分与融合
- 稠密/视觉信号取余弦相似度，稀疏信号用 BM25；单元级计分，轮次取其中单元的**最高分**。
- 不同信号尺度不同，采用**基于排名的融合（RRF，κ=60）**而非原始分数融合，避免某一信号主导。
- 上下文组装：多数查询返回 top-k 轮次并包裹 ±1 相邻轮次（时间有序、合并重叠块）；聚合类问题（"多少种博物馆"等，关键词规则识别）舍弃邻居、扩大返回轮数（12→30，仅 LoCoMo）。

## 6. 主要结论与发现

- **主结果**：Mem-Gallery 上 V-Mem 达 0.825，第二好的 Omni 仅 0.561；LoCoMo 上 0.690 对 0.583。Qwen2.5-VL-32B 骨干下不变（0.829 对 0.628）。
- **视觉类别差距最大**：携带图像的问题（TTL）0.872，无基线超过 0.472；视觉推理（VR）0.575，最强基线仅 0.273。
- **LoCoMo 上**：单跳（0.818）和时序（0.574）大幅领先，多跳与 Omni 打平（0.550 对 0.555），开放域落后于 M2A（0.375 对 0.477）。
- **消融结论**：共享轮次匹配是最大增益步骤（+0.129 整体、TTL +0.182/VR +0.181/VS +0.154）；路由在纯文本类别普遍提升但视觉类持平；生成锚点增益集中在触发场景（VR +0.038、VS +0.032）。
- **效率结论**：零 token 构建是检索设计的直接结果而非独立优化；作答 token 增加是换取视觉准确率的有意权衡。
- **错误分析**：剩余携带图像类错误主要是**答案模型未能利用已检索到的证据**，而非检索失败。

## 8. 缺点与局限性

- **路由规则依赖启发式**：目标模态与聚合问题类别的判定完全依赖关键词规则，这在英文数据集上表现良好，但难以覆盖语义隐晦、指代不明或非英语查询。例如用户问"我们当时看的那个东西"但并未提及"图片/照片"，规则会错误路由到文本通道。
- **两个"鸿沟"的解决并不完全对称**：模态鸿沟通过轮次共现机制解决，但其隐含假设是"同一轮次内的单元必然彼此相关"——在用户连续上传多张无关图片或助手在一轮中回复冗长多主题内容时，该假设会被稀释，而文中未讨论这一边界情形。
- **图像目标模态的判定粗糙**：text→image 情形下目标模态仅由关键词判定，若查询是"我们讨论过 Google 那栋楼长什么样"，"楼"不是图片词，会路由到文本通道而无图像结果。这种缺陷被实验设计（Mem-Gallery 的 9 类问题均有明确模态标记）部分掩盖。
- **LoCoMo 开放域类型显著落后于 M2A**：0.375 对 0.477，下降 0.102，接近 20% 的相对差距。论文将其归因于开放域问题有多个候选答案、需要更强的语义理解，但未分析 V-Mem 的哪些机制在此失效，也未提出修复方向，是实验结论中最明显的弱点。
- **消融统计力度有限**：路由与生成锚点两个步骤整体 p 值分别为 0.16 和 0.14，均不显著。作者用逐类别效应辩护，但这些类别样本量小（如 VS 仅 100 多个问题），bootstrap 置信区间宽，结论的统计强度弱于共享轮次步骤。
- **视觉信息仅保留原图与标题，丢失交互细节**：不做任何摘要意味着早期轮次的低质量图像（模糊、截图、多图拼贴）没有机会被清洗或重新编码，编码器能力直接成为系统上限；相反地，基线如 Omni 通过 LLM 提炼可弥补编码器不足，在部分场景反而有利。
- **图像标题依赖未充分消融**：text→image 的假设标题（hypo-caption）匹配存储图片的标题，而标题本身由外部模型生成。若标题质量差（如对图中文字、图标描述不准），跨模态检索会连锁失败，但论文只做了标题折叠（title folding）实验，未检验标题质量对检索性能的敏感性。
- **上下文窗口依赖前 k 截断**：返回轮次固定为 12（聚合类 30），当所需证据分散在远多于 k 的轮次时无法召回；对长对话的可扩展性没有压力测试（Mem-Gallery 对话规模约数周，真实智能体可能运行数月）。

## 9. 与相关工作的定位

- **对 MAG 思路的延续与修正**：V-Mem 仍属 Memory-Augmented Generation 范式（外部存储 + 检索），但其核心贡献在于指明了该范式在多模态场景下的两个系统性问题（模态鸿沟、相似性-相关性鸿沟），并用路由机制修正了"统一相似性搜索"这一 MAG 默认前提。
- **与 MemVerse、Omni-SimpleMem、M2A 的区别**：这三者均为"先统一编码、再统一检索"，V-Mem 反其道而行——先按模态分流、再在各通道内独立匹配。共享轮次机制相当于在检索空间中引入了一个**弱对齐**：不依赖嵌入相似度跨模态对齐，而依赖对话结构本身的对齐，这是方法论上的重要转向。
- **与多模态 RAG 的区别**：传统 RAG 的查询扩展（query expansion）多为生成相对查询的新表述，V-Mem 的假设标题和关键词提取则是面向"目标模态"的生成（text→image 生成图片描述、image→text 提取图片关键词），本质上是**模态变换作为检索预处理**，这一思路可推广到其他跨模态检索任务。

## 10. 启示与思考

- **"不比较即是解决"的巧妙之处**：V-Mem 对模态鸿沟的处理不是试图压缩多模态嵌入空间的距离，而是通过设计彻底避免跨模态比较。这种思路在工程上比训练更强的对齐编码器更便宜、更可控，对多模态检索系统的构建有直接启发。
- **LLM 的正确用途**：论文展示了 LLM 在记忆系统中不应是记忆的"加工者"（摘要、抽取），而应是检索的"辅助者"（生成锚点）。锚点生成只发生在检索时，且只在触发情形下使用，因此 token 开销极小——这是对 LLM 成本与收益的合理权衡。
- **启发式路由的天花板**：路由表目前是人工设计的，且冻结不学习。未来若能用轻量分类器（如小模型或查询嵌入的线性分类器）替代关键词规则，并覆盖更多模态对（如视频、音频），V-Mem 的框架可以更通用。
- **对答案模型的关注不足**：错误分析显示携带图像类的剩余错误主要来自答案模型未能利用检索到的证据——这意味着即使检索完美，生成端仍是瓶颈。这提示多模态记忆系统不应只有记忆模块的优化，还应在上下文注入时以更有利于 LLM 感知的方式（如提示明确区分文本与图像证据）进行组装。遗憾的是这与论文总体观点（聚焦检索）一致，但为后续工作留下了明确空间。

## 11. 总体评价

V-Mem 是一篇**问题诊断准确、方法简单有效、实验诚实透明**的多模态记忆检索论文。它没有引入复杂的图结构、注意力机制或训练流程，而是用两个关键机制直击多模态记忆检索的固有痛点，在召回质量上大幅超越现有强基线，并在资源开销上低至 2–3 个数量级。其主要的学术贡献在于将"模态路由"确立为一个独立且有效的检索策略维度，为后续多模态记忆系统提供了清晰的设计参考。局限在于路由规则偏启发式、跨模态锚点依赖标题质量、以及消融统计中个别步骤缺乏强显著性，但这些并不动摇核心结论：多模态记忆检索应按模态路由，而非统一相似性搜索。
