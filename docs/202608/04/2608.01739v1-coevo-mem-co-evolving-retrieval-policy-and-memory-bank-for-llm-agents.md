## 摘要
随着记忆在任务和会话间的不断积累，长期LLM智能体的性能同时依赖于针对查询的检索和持续的记忆精炼。然而，现有方法通常要么通过迭代查询重写或自适应检索策略来优化记忆访问，要么通过结构更新等机制来优化记忆进化。这种分离忽略了一个基本的反馈回路：检索决定了哪些记忆获得使用信号，而更新后的记忆库又会重塑未来的检索。我们提出\textbf{CoEvo-Mem}，一个用于协同进化检索策略和记忆库的闭环框架。对于每个查询，一个冻结的LLM生成路由特定的查询重写和路由先验，由轻量级残差路由器在线修正。检索到的上下文作为两个学习过程之间的耦合接口：任务结果将信用分配给路由决策，而轨迹条件反馈更新记忆值和图关系。这些更新会改变记忆在后续查询中的排序和选择方式，从而闭合反馈回路。为缓解耦合引起的非平稳性，CoEvo-Mem在固定记忆库更新路由器与固定检索策略进化记忆库之间交替进行。在七个多样化的基准测试中，\textbf{CoEvo-Mem}取得了最先进的性能，证明了检索-记忆协同进化的重要性。

## Abstract
As memories accumulate across tasks and sessions, the performance of long-term LLM agents depends jointly on query-specific retrieval and continual memory refinement. However, existing methods typically optimize either memory access, through iterative query refinement or adaptive retrieval policies, or memory evolution such as structural update. This separation overlooks a fundamental feedback loop: retrieval determines which memories receive usage signals, while updated memory bank reshape future retrieval. We propose \textbf{CoEvo-Mem}, a closed-loop framework for co-evolving the retrieval policy and memory bank. For each query, a frozen LLM generates route-specific query rewrites and a routing prior, which a lightweight residual router corrects online. The retrieved context serves as the coupling interface between the two learning processes: task outcomes assign credit to routing decisions, while trajectory-conditioned feedback updates memory values and graph relations. These updates alter how memories are ranked and selected for subsequent queries, thereby closing the feedback loop. To mitigate coupling induced non-stationarity, CoEvo-Mem alternates between updating the router with the memory bank fixed and evolving the memory bank with the retrieval policy fixed. Across seven diverse benchmarks, \textbf{CoEvo-Mem} achieves state-of-the-art performance, demonstrating the importance of retrieval-memory coevolution.

### 1. 核心问题与研究动机
- **背景**：LLM智能体在长期交互中会积累大量历史数据，无法全部放入单一上下文，必须依赖外部记忆机制进行存储、检索与更新。长期的智能体性能同时取决于两个互补过程：
  - *记忆访问*：如何针对当前查询检索出相关经验；
  - *记忆演化*：如何更新、优化和组织已存储的经验。
- **核心矛盾**：现有工作通常将两个方向分开处理——检索/访问方法（如RAG、查询重构、自适应检索）假定记忆库固定；记忆演化方法（如MemQ、MemRL、A-MEM等结构化记忆）假定检索策略固定或预先定义好。
- **被忽视的反馈闭环**：
  - 检索决定哪些记忆被暴露、获得反馈信号；
  - 记忆更新（价值估计与关系结构的变化）重塑后续检索的排序结果。
  - 二者相互依赖，若只优化一方而固定另一方，将导致双方与对方的新状态失配。
- **论文主张**：检索策略与记忆库应当作为一个耦合的学习问题，在一个统一的反馈回路中协同进化（co-evolve），而非孤立优化任意一方。

### 2. 方法论：CoEvo-Mem 框架

#### 2.1 总体架构与核心思想
- 采用**闭环框架**，以**检索到的上下文集合 Aₜ**作为检索策略与记忆演化之间的*耦合接口*：
  - 路由策略决定哪些记忆被暴露；
  - 暴露的记忆进入上下文供LLM生成回答；
  - 任务奖励反馈给路由器更新路由策略；
  - 完整轨迹（query、retrieved set、answer、reward）驱动记忆价值与关系更新；
  - 更新后的记忆库改变后续检索排序，从而闭合反馈回路。

#### 2.2 关键组件与技术细节

**(1) 路由特定查询重写与检索（Route-Specialized Query Rewriting）**
- 冻结LLM作为**Self-Routed Query Rewriter（SR-QR）**，对每个查询生成：
  - 稠密查询重写（保留语义意图）；
  - 稀疏查询重写（强调实体、专有名词、精确词项）；
  - 初始稠密-稀疏路由先验 p₀ₜ ∈ Δ¹；
  - 辅助置信度特征 ξ₀ₜ。
- 每个路由可有1–3个重写，输出为严格JSON格式；解析失败时退回原查询、均匀先验。

**(2) 轻量级残差路由器（Residual Router）**
- 不从头学习检索策略，而是在冻结LLM的路由先验基础上学习*残差修正*。
- 计算流程（公式3）：
  - 查询编码器 ϕψ 编码 (qₜ, oₜ) 得到特征 cₜ；
  - 策略头 fω 输出修正量 Δₜ ∈ R²（最后一层零初始化，保证初始策略恰为先验）；
  - 对先验做平滑后，取 softmax(log p̄₀ₜ + Δₜ) 得到最终路由策略 πₜ。
- 路由器训练中用 Beta 分布采样连续路由混合权重 ζₜ ~ Beta(κπᵈₜ, κπˢₜ)；
- 损失函数（公式4）：
  - **REINFORCE式得分函数项**：−sg[Âₜ] log pθ(ζₜ|qₜ,oₜ)，其中 Âₜ = Rₜ − EMA基线，将不可微检索过程中的任务奖励分配给路由决策；
  - **KL正则项**：约束策略不偏离LLM先验过远（系数 β_KL）。
- 推理和记忆阶段禁用探索，直接用策略均值 πₜ。

**(3) Q加权混合检索器（Q-Weighted Hybrid Retriever）**
- 融合三路信号：稠密相似度（余弦）、稀疏匹配（BM25）、学习到的记忆效用 Qₜ。
- 使用加权**倒数秩融合（RRF）**（公式5），路由权重 wₜ 控制稠密/稀疏通道的贡献，λ_Q 控制效用排名的权重。
- 时间图扩展：对初始top-k候选，加入其时间邻居，在扩展池上重新计算所有排序，取最终top-k。

**(4) 检索对齐的关系记忆图（Typed Relational Memory Graph）**
- 图中节点存储：内容、稠密描述、稀疏关键词、时间元数据、来源轨迹、效用值 Qₜ(m)。
- 边类型：**Dense**（语义接近）、**Sparse**（词法重叠）、**Time**（时间先后续接），与检索通道一一对应。
- Memory Construction：用固定prompt将每个训练轨迹（无论成败）蒸馏为新的程序性记忆，保留来源轨迹作为provenance；奖励仅作为记录而非过滤条件。
- 时间边由冻结LLM验证并定向。

**(5) 轨迹条件记忆价值更新（TD-style Utility Update）**
- 对暴露记忆 m ∈ Aₜ，用固定prompt评估其对生成的贡献分数 uₜ(m) ∈ [0,1]。
- 新记忆的初始价值继承自产生它的上下文（暴露集价值的均值或中性常数 Q_init）。
- TD式残差（公式7）：
  - δₜ(m) = Rₜ·uₜ(m) + γ·Q̂ₜ(m_new) − Qₜ(m)
  - 即时项=任务奖励×记忆归因；引导项=从新蒸馏经验向后传播下游效用。
- **关系型信用传播**（公式8–9）：沿类型化边路径（最多D跳，每条边按类型有衰减因子 ρ_c）将信用传播到非暴露但相关的记忆；取最强路径防路径多重性放大，再对多个暴露记忆取均值控制更新规模。
- 同步更新：所有残差基于同一更新前快照计算后同步应用（公式10），并投影到 [Q_min, Q_max] 区间。

**(6) 交替协同进化（Alternating Co-Evolution）**
- 核心设计：**同一轨迹不同时更新两个组件**，按阶段轮流：
  - **Router阶段**：记忆图只读，采样路由混合，仅更新路由器参数 θ；
  - **Memory阶段**：路由器冻结，用确定性均值策略检索，图顺序演化。
- 阶段级状态转移（公式11）：每个阶段完整遍历一次训练集D_tr后切换到另一阶段。
- 若图初始为空，先插入一个 Memory 引导阶段（Memory bootstrap）。
- 目的：缓解耦合引起的非平稳性，让每次更新都针对对方的最新状态。

### 6. 主要结论与发现
1. **协同演化带来显著提升**：6个评测设定均超过最强基线，平均提升3.72个百分点，最大单点提升达7.50（GPQA Diamond）；
2. **提升跨任务领域泛化**：最大增益出现在科学QA（+7.50）、非思考模式函数调用（+6.33）、代码生成（+3.81），证明不是单一任务特化收益；
3. **两组分均不可或缺**：
   - 去除SR-QR造成宏平均下降4.24个百分点（GPQA上损失8.33，MC协议上损失6–10个百分点）；
   - 去除记忆演化造成宏平均下降4.80个百分点（GPQA -10.00、LiveCodeBench -7.62、BFCL思考模式 -5.94）。
4. **交替调度优于同时更新与两阶段训练**：宏平均分别高出1.92和3.33个百分点，验证了交替更新对缓解非平稳性的有效性；
5. **训练能泛化**：LoCoMo训练/验证准确率随阶段交替稳步升至87%/84%，且检索接口可跨回答骨干迁移（GPT-4上MC分数升至89%/82%）。

- **泛化验证充分**：训练/验证分离、跨骨干迁移、固定图协议隔离检索组件效应，多角度验证各组分贡献；
- **工程鲁棒性**：附录给出了完整的接口规范、失败语义和实现契约，可复现性强。

- **记忆演化消融未覆盖固定图协议**：MC协议下无法评估记忆演化的贡献，只能在上文间接推断。

**方法层面的局限**
- **模型角色分配未系统优化**：论文采用固定(F_ans, F_route)配对而非跨配对搜索，未探索不同骨干组合对性能的影响（论文在Future Work中明确承认）；
- **不可微的RL训练**：路由器通过REINFORCE式评分函数训练，方差控制依赖EMA基线与KL正则，对奖励噪声较大的任务可能稳定性不足；
- **多代理与异步场景尚未覆盖**：当前框架为单智能体设计，跨代理记忆共享、异步写入和延迟反馈下的稳定性缺乏理论保证；
- **超参数众多**：RRF常数η、效用权重λ_Q、衰减因子ρ、路径深度D、折扣γ、浓度参数κ、KL系数β_KL等需要逐任务调节，虽然论文报告了共享默认值，但未做敏感性分析；
- **理论层面**：论文提到未来将探索耦合检索-记忆优化的理论保证，当前缺乏对交替优化收敛性的形式化分析。
