## 摘要
长期记忆对于在长周期交互中运行的LLM智能体至关重要。然而，现有记忆系统的若干持久局限性可追溯到长期交互场景中两种反复出现的错配模式：时间-结构错配（TSM）和延迟效用显现（DUM）。当时间邻近性与主题或事件层面的关联性不可靠对齐时，会出现TSM；而当写入时显著性与未来查询效用不可靠对应时，则出现DUM。为缓解这些错配模式，我们提出MemSIF（内存与结构化交互和事实），一个结构化交互到事实的记忆框架。结构化交互记忆将原始交互组织为主题片段（Topical Segments）和事件轨迹（Event Trajectories），前者保持局部主题连贯性，后者维持跨时间事件连续性。双轨事实记忆使用两条互补的轨道：CoreFact记忆在写入时整合稳定的、模式引导的信息，而ActiveFact记忆按需形成事实，并提升那些由多个历史来源和重复查询需求支持的事实以供重用。在五个骨干LLM上的LoCoMo和LongMemEval-S实验表明，MemSIF在所有设置中均取得最高的总准确率（Total ACC），在LoCoMo上比最强基线高出2.29%-8.79%，在LongMemEval-S上高出2.87%-6.15%。这些结果支持将结构化交互记忆与双轨事实记忆相结合以缓解TSM和DUM的有效性。代码可在https://github.com/luoyufeihaha/MemSIF获取。

## Abstract
Long-term memory is critical for LLM agents operating over long-horizon interactions. However, several persistent limitations of existing memory systems can be traced to two recurring misalignment patterns in long-term interaction settings: Temporal-Structural Misalignment (TSM) and Delayed Utility Manifestation (DUM). TSM arises when temporal proximity does not reliably align with topical or event-level relatedness, whereas DUM arises when write-time salience does not reliably predict future query utility. To mitigate these misalignment patterns, we propose MemSIF (Memory with Structured Interactions and Facts), a structured interaction-to-fact memory framework. Structured Interaction Memory organizes raw interactions into Topical Segments that preserve local topical coherence and Event Trajectories that maintain cross-time event continuity. Dual-Track Fact Memory uses two complementary tracks: CoreFact memory consolidates stable, schema-guided information at write time, whereas ActiveFact memory forms facts on demand and promotes those supported by multiple historical sources and recurring query demand for reuse. Experiments on LoCoMo and LongMemEval-S across five backbone LLMs show that MemSIF achieves the highest Total ACC in all settings, outperforming the strongest baseline by 2.29%-8.79% on LoCoMo and 2.87%-6.15% on LongMemEval-S. These results support the effectiveness of combining Structured Interaction Memory with Dual-Track Fact Memory to mitigate TSM and DUM. Code is available at https://github.com/luoyufeihaha/MemSIF.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：随着LLM智能体从单轮问答演进到长周期任务，交互历史不断累积，将全部历史放入上下文窗口既不经济也可能损害性能，因此可检索、可更新的外部记忆成为关键。
- **核心问题**：现有长期记忆系统存在两类反复出现的系统性错配：
  - **Temporal–Structural Misalignment（TSM，时间-结构错配）**：时间邻近性不一定等价于主题或事件层面的关联性；相邻对话可能主题无关，而跨时间分离的片段可能属于同一事件/任务。固定时间边界会把无关主题分到同一记忆单元，或把关联证据拆分到不同单元。
  - **Delayed Utility Manifestation（DUM，延迟效用显现）**：写入时看似不重要的信息，可能在后续查询中变得关键；写时显著性无法可靠预测未来查询效用。写时压缩面临“激进过滤丢失关键信息 vs. 保守保留冗余”的两难；查询时方法虽然能按需恢复，但恢复的证据只服务于当前查询，不持久沉淀，后续复用仍依赖检索，存在检索失败风险。
- **整体含义**：现有方法往往单独优化“交互组织”或“事实构建”，但二者需要联合设计，才能同时缓解TSM和DUM，让交互经验真正沉淀为可复用的知识。

## 2. 提出的方法论：MemSIF

- **核心思想**：将交互组织与事实构建统一在同一框架中，构建“结构化交互记忆”与“双轨事实记忆”两个模块。
- **结构化交互记忆（Structured Interaction Memory，M_int）**，用于缓解TSM：
  - 将原始交互历史组织为两类互补结构：
    - **Topical Segments（主题片段）**：时间上连续、主题连贯的交互单元，保留局部主题一致性。
    - **Event Trajectories（事件轨迹）**：将属于同一演化事件/任务但时间上不连续的Topical Segments关联起来，维持跨时间事件连续性。
  - 共享匹配函数：
    - `φ(A,B) = α·s_sem(A,B) + (1−α)·J(K_A, K_B)`
    - 其中 `s_sem` 为归一化余弦相似度，`J` 为关键实体集合的Jaccard重叠度，`α=0.8`。
  - **主题片段构建**：按时间顺序处理消息，使用“双阈值”规则（`τ_split=0.325`, `τ_merge=0.60`）：分数≥τ_merge自动合并；≤τ_split开启新片段；位于中间时由LLM裁决。这样仅让LLM处理模糊边界，兼顾效率和主题连贯性。
  - **事件轨迹聚合**：按时间顺序处理主题片段，检索Top-K（K=3）候选轨迹，由LLM判断事件身份、任务连续性和状态一致性；若兼容则加入最高分轨迹，否则新建轨迹。
- **双轨事实记忆（Dual-Track Fact Memory）**，用于缓解DUM：
  - **CoreFact记忆（M_core）**：写时、模式引导的事实整合。
    - 使用可配置的CoreFact schema（如身份、事件、偏好、关系等类型），LLM从主题片段提取符合schema的候选事实，事件轨迹提供跨时间证据进行补充/调和。
    - 事实条目格式：`⟨subject, type, stmt, meta⟩`。
    - 写前检索已有条目，由LLM从Add / Update / Merge / Supersede四类操作中选择；过时事实标记Supersede但保留以便回答历史问题。
    - schema之外或写时不确定的信息保留在结构化交互记忆中，可被ActiveFact后续恢复。
  - **ActiveFact记忆（M_act）**：查询时、需求驱动的事实形成。
    - 四个阶段：查询局部提取 → 回答后候选累积 → 候选晋升 → 持久维护。
    - 当检索到的事实记忆不足以回答查询q_t时，从结构化交互记忆检索相关片段/轨迹，提取查询局部证据用于生成当前答案；回答生成后该证据成为候选，按主体聚成候选簇 `C_k=(s_k, X_k, Q_k, R_k)`。
    - 晋升条件：必须同时满足历史来源支持与重复查询需求：
      - `Score_src(C_k) = (1−1/|R_k|)·Coh(X_k)`
      - `Score_qry(C_k) = (1−1/|Q_k|)·Coh(Q_k)`
      - `P(C_k) = 1[Score_src ≥ θ_s ∧ Score_qry ≥ θ_q]`，其中 `θ_s=θ_q=0.45`。
      - 晋升后的条目成为持久ActiveFact条目 `⟨subject, stmt, meta⟩`，可供后续查询直接复用。
- **查询时检索与回答生成**：
  - 对每个查询同时检索CoreFact和持久ActiveFact事实；LLM充分性检查器判断事实是否覆盖查询需求；若不足，再检索结构化交互记忆获取查询局部证据。
  - 回答上下文由检索到的事实条目和查询局部证据组合，而非直接放入原始交互单元；LLM生成答案后，查询局部证据进入ActiveFact流水线。
- **关键设计**：CoreFact解决“写时可识别价值”的信息；ActiveFact解决“价值仅在查询后显现”的信息；两者互补且共同检索。

## 6. 主要结论与发现

- MemSIF在LoCoMo和LongMemEval-S上、所有三个主骨干下均取得最高Total ACC：
  - LoCoMo相对最强基线提升8.79%（Qwen3-4B）、5.78%（Qwen3-32B）、2.29%（DeepSeek-v4-pro）。
  - LongMemEval-S相应提升6.15%、4.62%、2.87%。
  - Qwen3-8B和Llama-3.1-8B上分别提升7.69%和6.47%。
- 类别层面：
  - LoCoMo上最大增益集中在Temp类（Event Trajectories的作用），Qwen3-4B/32B分别提升16.37%/11.00%。
  - LongMemEval-S上MemSIF在所有类别均领先。
  - 在最强骨干DeepSeek-v4-pro下，MemSIF在个别类别（如LoCoMo M-hop低2.18%、Temp低0.82%）仍会落后于特定基线，但总体最高。
- 消融显示四个组件均有贡献且互补：
  - 移除Event Trajectories在LoCoMo Temp上降幅最大（10.36%）；
  - 移除Topical Segments损害M-hop；
  - 移除CoreFact在LongMemEval-S上总ACC降幅最大（12.77%）；
  - 移除ActiveFact在M-hop上降幅最大（13.23%/12.38%）。
  - NCE子集上移除交互结构组件降幅最大，LSHU子集上移除ActiveFact降幅最大，直接支持对TSM和DUM的缓解作用。
- ActiveFact分析表明，仅查询局部提取（不持久化）就已超过最强基线，而完整MemSIF进一步通过持久ActiveFact条目提升LSHU准确率并降低token/运行时间。
- 效率方面：MemSIF在最高准确率下仍有良好的准确率-成本平衡；例如Qwen3-32B下比GAM少40.6% token且准确率更高，比token预算相近的SimpleMem减少42.8%运行时间并提升8.38%准确率。
- 配对bootstrap的95%置信区间在所有六组设置中均不含0，说明相对最强基线的提升在统计上可靠。

## 7. 优点

- **问题刻画清晰、系统性强**：明确提出TSM和DUM两类错配模式，并通过独立于方法的经验诊断（ASV、SNTD@k、LSHUR、CDL-QAD）给出证据支撑；构造NCE和LSHU诊断子集，使针对性评估成为可能。
- **方法设计新颖且互补**：结构化交互记忆（Topical Segments + Event Trajectories）与双轨事实记忆（CoreFact + ActiveFact）形成有机组合，分别应对两类错配；既保留写时可识别的价值，又支持查询时浮现价值的持久化。
- **效率设计合理**：双阈值减少LLM调用，ActiveFact晋升后避免重复回溯原始历史，从而在更高准确率下保持较好成本。
- **实验丰富度较高**：跨五个骨干、两个基准、多个消融、敏感性、效率、人类验证和统计显著性分析，证据链完整。
- **评估规范**：报告置信区间、三次运行均值、人工验证、方法和数据均公开，可复现性强。

## 8. 不足与局限

- **基准覆盖有限**：仅使用LoCoMo和LongMemEval-S两个长期记忆QA基准；LoCoMo只有10个对话，对话多样性有限；LongMemEval-S样本量较小。未涉及更广泛的多智能体、在线交互或跨领域场景。
- **骨干×数据集覆盖不完全**：Qwen3-8B和Llama-3.1-8B仅在LoCoMo上评估，未在LongMemEval-S上验证。
- **增益随骨干能力增强而收窄**：在DeepSeek-v4-pro上的提升仅为2.29%–2.87%，且在个别类别上落后于部分基线；大模型下优势边际变小。
- **依赖手动schema与超参**：CoreFact schema需在应用前手动指定并在设置内固定，不支持在线自适应；分段阈值、匹配权重、晋升阈值等超参数虽经敏感性验证，但全局默认未必适合所有场景。
- **依赖LLM判断环节多**：分段模糊边界、事件轨迹匹配、CoreFact更新、充分性检查、证据提取等均调用LLM，存在计算开销和判断不稳定的风险；论文未深入分析LLM裁决错误对端到端性能的影响。
- **评估针对短答案QA**：实验集中在问答正确率，未验证对任务型Agent、决策执行、多轮行为一致性等更广泛长期记忆用途的收益。
- **潜在偏差风险**：GPT-4o评估虽经人工验证（93%一致性），但仍有约7%分歧；诊断子集构造依赖GPT-4o打分，可能残留模型特定偏差；三次运行平均和bootstrap降低了但未完全排除随机性影响。
